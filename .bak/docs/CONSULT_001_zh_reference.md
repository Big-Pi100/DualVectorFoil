# 咨询 001 — 操控、界面、美术风格与实现方式

> 这份文档是给外部设计/美术顾问看的。下面每一条都写成**可以直接回一句话**的形式：
> 编号下写「A / B / C」或一句判断即可，不需要写方案。

## 0. 三分钟了解现状

**产品**：横版动作游戏《二向箔》(SoulKeep)，单文件 HTML，纯 2D Canvas。
**核心卖点**：主角是一张**被拍下来的照片**，玩家可以上传自己的照片把主角换成自己那张。
**核心新机制**（本次要验证的）：主角能把自己**压成纸片**，从墙上 2px 的纸缝里挤过去。

**技术事实**（这些约束会直接影响你们的建议能不能落地）：

| 项 | 现状 |
|---|---|
| 渲染 | 单个 `<canvas>`，逻辑分辨率约 890×480，按窗口缩放 |
| 地形 | **代码绘制**（每块砖由哈希函数生成明暗），不是瓦片图 |
| 角色 | 20 帧精灵图集（1993×744），来自一条"名片管线"，可被玩家照片替换 |
| 敌人/道具/灯/缝/特效 | **全部代码绘制**（路径 + 渐变），没有贴图 |
| 物理 | 120Hz 定步长，跳跃顶点 203.8px（30/60/120/144Hz 一致） |
| 音效 | 全部现场合成，零音频文件 |
| 发布形态 | 单 HTML ≈ 934KB（图集内联 base64） |
| 存档 | localStorage，版本化 |

**视觉现状一句话**：靛紫黑的环境 + 米白/暖金的纸与光，石墙 + 拱窗 + 壁灯 + 相框（编号 No.07/08/11/12），敌人是"被拍坏的照片"（纸团有折痕和撕口，纸片蝙蝠）。

## 1. 操控与界面说明（这一版刚改完，需要你确认）

### 1.1 之前错在哪

按键本身一直是好的（有 23 项自动化测试盯着）。**错的是界面那行说明只写了三分之二**：

- 把 `W A S D` 揉成一句"移动 · 蹲 · 抬头"，玩家不知道哪个键对应哪个动作；
- **两个组合键一个字都没提**：滑铲 = 下+跳、穿板（从薄板往下掉）= 下+攻；
- 蓝魂槽是空的时候，`L` 按下去**什么都不发生**，界面却理直气壮写着"蓝魂"。

结果就是"说明和操控完全不一致，没法测"。**这不是控制坏了，是说明书坏了 —— 但在玩家那里是同一件事。**

### 1.2 现在的做法

键位与动作的对应关系收进一张**唯一的表**，界面那一行由它自动生成（字母也取自它，所以不可能印错），并新增一组 26 项测试**直接读界面上那行字**、照着逐条按键验证：

- 图例多写一个按不出来的键 → 测试红
- 能用的键没写进图例 → 测试红
- 改键位忘了改说明 → 字母对不上，测试红

当前表（界面就是这张表的渲染结果）：

| 手 | 键 | 动作 | 条件 |
|---|---|---|---|
| 左 | A / D | 移动 | |
| 左 | W | 抬头（镜头微抬，看高处） | |
| 左 | S | 蹲 | |
| 左 | S + K | **滑铲** | 地面 |
| 左 | S + J | **穿板**（从薄板掉下去） | 站在薄板上 |
| 右 | J | 攻击 | |
| 右 | U | 红魂（火球） | 需装备红魂，未装备时变灰 |
| 右 | K | 跳 | |
| 右 | I | 后跃（向后急退，带无敌帧） | 地面 |
| 右 | L | 蓝魂（按住滑翔） | 需装备蓝魂，未装备时变灰 |
| 右 | O | 魂匣（菜单） | |
| 右 | F | 纸（按住 = 压扁侧身） | 有墨、非受击/滑铲/冲刺/出招中 |

别名行：方向键=WASD · 空格=跳 · Tab=魂匣 · R 连按两次=重开 · M=静音。

### 1.3 需要你确认的判断

**Q1. 键位分组对不对？**
现在是"同一个手指管一对语义"：食指 J/U = 打出去，中指 K/I = 位移（跳/后跃），无名指 L/O = 状态（按住的能力/系统菜单）。你觉得这个逻辑玩家能感知到吗？还是应该按"使用频率"重排？

**Q2. 组合键要不要保留？**
滑铲（下+跳）和穿板（下+攻）是照《月下夜想曲》的原版来的。好处是省键位、有"老游戏"的手感；坏处是**必须靠说明才学得会**，而且手机上要两个手指同时按。
选项：**A** 保留组合键并把说明做足 ／ **B** 拆成独立键（键位变多，但可发现） ／ **C** 保留组合，但滑铲改成"跑起来按跳"这类更直觉的触发。

**Q3. 图例应该常驻吗？**
现在 3 行常驻在右下角（覆盖在砖地上）。它解决了"测不了"，但它本身是**屏幕上的第 5 个信息块**（左上三条、右上魂槽、右下小地图、左下日志）。
选项：**A** 常驻但更淡 ／ **B** 主界面只留 4 个高频键，完整表放进魂匣（暂停）界面 ／ **C** 开局显示 10 秒后淡出，按某个键唤回。

**Q4. 没有对应魂的时候，那一项变灰（现在的做法）够不够？**
还是应该干脆**从图例里隐藏**？（变灰的好处是"以后会有"，隐藏的好处是"现在能用的都是真的"。）

**Q5. 空格 = 跳 这个别名要不要留？**
它不在任何宣传里，只是通行习惯。留着方便，但它让"WASD 左手 / JKL 右手"的双手布局变得不必要（右手能全用空格+鼠标？不，没有鼠标）。删掉更纯粹。

## 2. 界面设计（HUD）

**Q6. 五个角全占了，砍哪个？**
左上 HP/MP/墨 三条 + 房间名；右上三个魂槽 + 收集计数 "1/5"；右下小地图（150×120）；左下三行日志；右下键位图例。
我的判断是**日志最该砍**（它承担叙事："这张照片是你拍的"），但砍了叙事就没了。你怎么看？

**Q7. 墨条的位置。**
墨是侧身机制的燃料（100 点，26/秒，只有灯能补）。它现在**只在有灯的房间出现**（第三条），出现/消失时左边整块会跳一下。
选项：**A** 常驻第三条（空房间也显示，满格） ／ **B** 只在房间里出现，但**预留位置**（不跳） ／ **C** 不做成条，改成角色身上的可见变化（越薄越亮之类）。

**Q8. 魂槽的浪费。**
右上三个槽占了一大块，实际大部分时间是"炎魔之魂 / 空 / 空"。
选项：**A** 保持三槽（一眼看清配置） ／ **B** 只显示当前红魂 + 蓝魂（黄魂是常驻被动，不必占位） ／ **C** 收成一个图标，展开才看。

**Q9. "1/5" 是什么的 1/5？**
现在只是个数字，没有单位也没有图标。要不要改成"魂 1/5"或者干脆放到魂匣里？

**Q10. 小地图要不要留？**
单房间 32×18 格，一屏基本能看全。它现在只画房间轮廓 + 几个点，信息量很低。删掉能空出右下角给图例。

**Q11. 字号。**
界面正文 11px 中文（2× 缩放下相当于 22 设备像素）。图例 11px、条件注释 9px。对 1080p 显示器偏小。要不要整体 +1~2px，代价是图例更宽。

## 3. 美术风格

**Q12. 侧身只有 6px 宽，怎么让它"还是个人"？**
现在是**同一张精灵横向压扁到 6px**（上下不变，所以还留着头发/外套/裤子的颜色分层）+ 呼吸光晕 + 一侧亮边 + 脚下投影。
1:1 看（`flat_zoom_inside.png`）能认出是人；但整屏看就是一条暖色细线。有没有更好的办法？比如：剪影化 + 只保留一条侧棱高光？或者干脆接受"一条线"，靠**运动拖影**来表达？

**Q13. 人和墙缝怎么在视觉上彻底分开？**
两者都是细长条，这是目前最大的可读性风险。我现在的做法是"人暖（金）+ 缝冷（墨）+ 人身上有色阶分层"。更根本的做法可能是**色彩制度**：环境全冷（靛/墨绿），角色与光全暖（米白/金），两者永不混用。你赞成这种强制度吗？它会限制后面所有场景的配色。

**Q14. 灯该长什么样？**
现在是"现代落地灯"轮廓（三角灯罩 + 细杆 + 暖光晕）。它好读、光源位置明确，但和"纸的世界"不太搭。要不要改成**纸灯笼 / 折纸灯**？代价是轮廓变复杂，"这是光源"的第一眼识别度会下降。

**Q15. 敌人要不要表情？**
纸团敌人有工笔眉（两条细眉 + 撕口当嘴），一眼能读出情绪。但"被拍坏的照片"这个设定需要**多明确**？表情越强，越像卡通怪物；越弱，越像环境装饰。你倾向哪边？

**Q16. 背景拱窗太空。**
背景是大块暗紫拱形，几乎没有信息，只起"这不是天空"的作用。要不要加一层"照片墙/档案柜"的纹理让它有叙事？还是保持空，把注意力全留给前景？

**Q17. 字体。**
现在用系统无衬线 + 大字距做"档案感"。要不要一套等宽/打字机字体来统一气质？（中文等宽的可用选择很少，这也是个现实约束。）

## 4. 实现方式（这些决定了建议能不能做）

**Q18. 地形：代码绘制 vs 瓦片图集。**
现在每块砖由哈希生成明暗，好处是任意尺寸、无接缝、改关卡只改字符；坏处是**没有手工质感**，也无法画"这一块砖是特殊的"。
改成瓦片图集能让美术介入，但关卡编辑、碰撞、隐藏墙全要重做。值不值得？

**Q19. 角色和敌人是两套画法。**
角色是精灵图集（20 帧，可被照片替换），敌人是代码绘制的路径图。两者并存，风格上能看出来不是一个人做的。
要不要给敌人也出图集？（代价：每个敌人要有 4~8 帧，且要能被"照片化"改写。）

**Q20. "换名片"是核心卖点，它对侧身成立吗？**
玩家上传照片后，角色变成他那张照片。但**侧身时人被压到 6px** —— 一张照片压成 6px 就是一条色带，皮肤的意义瞬间消失。
这是机制和卖点的直接冲突。有没有办法让"压扁"仍然保留照片的识别度？（比如压扁时保留一小片"未压扁"的脸？还是接受"侧身时看不见自己"？）

**Q21. 单文件 934KB 要不要拆？**
现在所有资源内联在一个 HTML 里（双击就能玩，好传播）。拆包能缓存、能按需加载，但部署变复杂。你们的经验里，这种小体量游戏值得拆吗？

## 5. 这次实验本身需要拍板的三件事

（背景：要验证"侧身"这个动词是否值得做下去。判据是——首次玩家能不能在无提示下发现它；过了必经的缝之后会不会**自发**复用；它是不是形成了战术选择而不是无敌帧。）

**Q22. 过墙之后没有任何"值得压扁"的东西，怎么办？**
实验房结构是：入口 → 可选壁龛（内有墨瓶）→ 必经墙（只能用侧身过）→ 出口。过了墙就是一条死路。
所以"过墙后是否自发复用"这个指标**在结构上永远是 0**，不是玩家不想用。
要在墙后加一个可选的诱因（第二个壁龛 / 一个只有侧身能拿的魂），还是承认这条判据只能留到下一版？

**Q23. 壁龛那根柱子，192px 高，而单跳顶点是 203.8px。**
余量只有 11.8px。它本意是"可以跳过去，所以壁龛是可选的"，但实际很可能会被玩家读成"过不去"，于是**第一次侧身发生在壁龛，而不是必经墙**——那样"首次使用"测的就不是我们要测的地方。
要不要把柱子降一格（变成 144px，轻松跳过去）？

**Q24. 墨只够 3.8 秒。**
100 点 / 26 每秒。这个数字是拍出来的，没有依据。
它决定了侧身是"短促的战术动作"还是"可以慢慢探索的形态"。你们希望它偏哪边？

## 6. 我不需要的

- 泛泛的"可以更精致/更有氛围"——请指到具体某个元素。
- 需要引入引擎、着色器、3D 的方案（当前是单文件 2D Canvas，这是产品约束）。
- 完整重做 UI 的提案——我需要的是"这一块删掉/合并/换个位置"级别的判断。
