## 玩

双击 `SoulKeep.html`（单文件，图集已内联，不联网也能跑）。

| 键 | 作用 | 恶魔城里的对应 |
|---|---|---|
| **W A S D** | 移动 / 蹲 / 抬头 | 十字键 |
| **J** | 普攻（装「识破」时能砍碎隐藏墙） | **B 键** |
| **K** 或 空格 | 跳（拿到银魂后可二段跳） | **A 键** |
| **U** 或 **W + J** | 红魂（火球 / 飞斧） | **上 + B**（原版没有独立魔法键） |
| **F**（旧键 **I** 仍可用） | 冲刺（朝背对方向急退，带 0.12s 无敌；手机上叫「冲刺」） | **L 键**（能力键） |
| **L** | 蓝魂（点一下，滑翔 3 秒，走冷却） | **R 键** |
| **S + K** | 滑铲 | 下 + A |
| **S + J**（站在薄板上） | 从单向平台掉下去 | 下 + B |
| **O** / Tab | 魂菜单（红蓝黄各装一个） | START |
| M / R 连按两次 | 静音 / 重开 | —— |

**右手六个键的分组逻辑**（不是"手够得着"，是同一手指管一对语义）：

```
   左手            右手
                    J  K  L     食指：攻 / 中指：跳 / 无名指：蓝魂
   W                 U  I  O     食指：红魂 / 中指：后跃 / 无名指：魂匣
 A S D
```

> **红魂在原版里不是独立键，是「上 + B」。** 我们两套都留：U 是便捷键，
> `W + J` 是原版语义 —— 因为"方向是动词的一部分"这件事，丢了就不是恶魔城了。
>
> **↑ 不是跳。** 原版 `↑` 是 `ric_anim_press_up`（抬头看），跳永远是 `A`。
> 现在 ↑ 只做抬头（镜头往上），不产生任何位移。
>
> 手机端（WO-004，照《重生细胞》手机版）：左浮动摇杆（下推蹲 / 上推抬头），
> 右下**四个装备格 + 三个方形键**。四格是「剑 / 空 / 红 / 蓝」，**点一下就用**
> ——攻击不再是独立键，它装在武器格里（这正是死细右边只留三个键的原因）。
> 三键是跳（最大最靠角）/ 翻滚 / 交互，魂匣在左上。
> 位置和四格大小**玩家可调**：匣 → 操作 → 调整位置，拖完松手就记住。
| 右上「按快门」 | 把一张真人照片印成二维主角（本地像素化，碰撞体不变）——**这个动作就是二向箔** |

**通关路线**：打史莱姆拿火球 → 爬钟塔拿识破 → 回廊砍碎那堵"墙"拿飞斧 →
钟塔顶打死守关者拿双跃 → 回廊左侧 288px 高台（单跳 203px，差 85px）→ 结局。

> **侧身（Flatten）已删除（2026-11-25）**。原来的设计是按住 `F` 把人压成 6px，
> 从 6px 的纸缝里挤过去。删它的三个理由，按分量排：
>
> 1. **它在正式流程里用不到**：纸缝只长在实验房 `paper`（显影室），而那间房
>    没有任何传送门 —— 玩家一辈子碰不到这个动词，只有测试在调它。
> 2. **它占着 F 键**：白哥对参考图的原话是「D 是交互、**F 是冲刺**」，F 却一直是侧身。
> 3. **它是第二条资源条**：魂都已经改成纯冷却了，侧身还在烧墨 —— 等于自己推翻自己。
>
> 「穿窄处」这件事没有消失，它换了做法：**留给 P3 的 rune 门**（爬 / 撞 / 传）。
> DC 的窄通道从来不是靠玩家把自己压扁开的，是靠"有没有那个符文"。
> 纸作为**世界观与美术**还在（`STORY.md`），它只是不再是一个动词。
>
> 没装备的魂那一项**变灰 + 明写「未装备」**（空槽的 `L` 本来就没用）。
> 分组**按动作**（移动/战斗/工具/系统），不按手指 —— 手指分工是内部逻辑，玩家问的是"我想抬头按哪个"。
> 主界面只放**四个高频动作**（移动/跳/冲刺/攻），完整表在魂匣里。
> 多键条目要印出**怎么组合**：`A / D` 是二选一，`S + K` 是同时按（上一版两种都印成"S K"）。

> 按键是好的，说明是残的，而玩家分不出这两件事。**改键位不更新这张表，测试会红。**


> **第三类测试：反馈层。** 前两个脚本量的是手感数值，`test.js` 量的是逻辑。但它们都抓不到
> "状态对了、屏幕上没东西"这一类 bug —— 上一轮就是这么漏的：走路时 `map.walk` 指向了一个

## 手感：两套预设，默认是恶魔城



`src/game.js` 顶部的 `FEELS`。默认 `aos`；地址后面加 `?feel=modern` 切回上一版做对比。

### aos（恶魔城，默认）

**数据来源不是 wiki、不是录像，是 `sotn-decomp` 的反编译源码。** 每个数都能指到具体一行：

| 项目 | 源码原值 | 出处 | 换算（1 格 16px → 48px，×3） |
|---|---|---|---|
| 走速 | `RicSetSpeedX(FIX(1.25))` | `pl_steps.c:128` | 1.25 × 3 × 60 = **225 px/s** |
| 跑速 | `FIX(2.25)` | `pl_steps.c:126` | **405 px/s** |
| 地面减速 | `RicDecelerateX(FIX(0.125))` | `pl_steps.c:51/119/145` | 0.125 × 3 × 3600 = **1350 px/s²** |
| 空中减速 | `FIX(0.0625)` | `pl_steps.c:187` | **675 px/s²**（地面的一半） |
| 重力 | `velocityY += 0x3800` | `pl_steps.c:1063` | 0.21875 × 3 × 3600 = **2362 px/s²** |
| 起跳 | `velocityY = FIX(-5.4375)` | `pl_setstep.c:141` | 5.4375 × 3 × 60 = **979 px/s** |
| 松手切断 | `velocityY = FIX(-1)` | `pl_steps.c:174` | **绝对值**，不是乘系数 |
| 撞顶 | `velocityY = FIX(-0.25)` | `pl_steps.c:178` | 压到 -45 px/s |
| 受击硬直 | `ric_hit_stun_timer = 0x18` | `pl_steps.c:688` | **24 帧 = 400ms** |
| 受击击退 | `func_8015CAAC(FIX(-1.25))` + `velocityY = FIX(-3)` | `pl_steps.c:544/551` | 225 / 540 px/s |
| 土狼时间 / 跳跃缓冲 / 顶点滞空 | 不存在 | —— | 全部为 0 |

**关键理解：走路"没有加速度"不等于"没有摩擦"。** `RicStepWalk` 每帧先 `RicDecelerateX(0.125)`
再 `RicSetSpeedX(1.25)` —— 恒速是"每帧重设速度"的结果，摩擦一直在跑。
所以松手后会继续滑，**10 帧、约 29px 才停**。上一版把它做成 `FRIC = 1e6`（瞬停），
"按下即满速"是对的，"松手即停"是错的。

**跳高 203px = 4.22 格 = 2.03 倍身高。** 上一版 161px 是照"1.6 倍身高"倒推的，
比原版矮 21%。改成 203 之后能力门必须跟着抬（192px 会被单跳过），
左高台从 192px 抬到 **288px**，同时门洞和密室顶一起往上挪。

### 实测（真 Chromium + 真键盘，`probe_feel.js --feel=aos`）

| 指标 | 源码算出 | 游戏实测 |
|---|---|---|
| 满跳 | 67.6×3 = 203px | **203.7px** |
| 上升 / 下落 | 24.9 帧 ≈ 414ms / 414ms | **450 / 533ms** |
| 全程滞空 | 49.7 帧 = 829ms | **983ms** |
| 顶点滞空 | 窗口 -1/8~+3/8 px/帧、重力 ×1/5 | **250ms** |
| 起步到满速 | 1 帧（无加速过程） | **17ms / 1 帧 / 首帧 100%** |
| 松手滑停 | 0.125px/帧² → 10 帧 ≈ 29px | **200ms / 20.6px** |
| 转身 | 1 帧 | **17ms / 17ms** |
| 轻点跳 | 按一次 | 76.7px（1.6 格） |

**滞空比理论值多 154ms，这不是误差，是顶点窗口。** 原版在 `-1/8 ~ +3/8 px/帧` 这一小段
（`pl_collision.c:18`）把重力降到 1/5，条件是"按住跳键且这一跳没撞过顶"。
把这段算进去，829 + 150 ≈ 979ms —— 实测 983ms 正好对上。

> 这条窗口是我之前**做出过但以为是错的**：我写过 `Math.abs(vy) < 120 → 重力 ×0.6`（对称、宽 120），
> 那是凭手感编的。真实是**非对称 -22.5 ~ +67.5、×1/5**，而且必须按着跳键。

### 唯一的主动偏离

松手切断值没照搬 `FIX(-1)`：换算过来是 -180 px/s，在我们的重力下只能再升 6px，
**轻点跳不到半格，手机上等于"按了没反应"**。按"轻点刚好上一格台阶"定成 400 px/s。
质地（松手立刻掐断上升）保留了，只有幅度是照可玩性定的。

### 踩过的坑（按症状记，不按代码位置记）

| 症状 | 真正的原因 |
|---|---|
| 按 J 有动画有声音，**打不到任何东西** | 判定框在 `y+8~y+52`，敌人在 `y+62~y+100`，垂直永不重叠 |
| 蹲下后**站不起来**，所有键都失效 | `stepCrouch` 没走 `checkInput`，输入全被吞 |
| 二段跳**永远触发不了** | `stepJump` 的 checks 里漏了 `CK.JUMP` |
| **↑ 会跳** | 原版 ↑ 是 `press_up`（抬头），跳是 × |
| 手机按**蓝魂会同时起跳** | 蓝魂发 `'k'`，而跳键别名里有 `'k'` |
| 站着不动**莫名其妙掉进 fall** | 用"位移被挡住"判落地，`dy=0` 时误判脚下是空的 |
| 连续按跳，**第二下没反应** | `prevKeys` 异或：keyup 不经过帧，残留导致 tap 被吞 |
| `JBUF_T = 0` 时**整个游戏跳不起来** | `P.jumpBuf = JBUF_T` = 0，而判定是 `> 0`，永远不成立 |
| **开局按一次 R 直接重开** | 判断“两次连按”用了 `now - reloadArm < 1600`，而 `reloadArm` 初值 0，页面加载后 `performance.now()` 本来就 < 1600 |
| 手机按**“蓝”放出了红魂** | 键盘的 `l` 从红魂改成蓝魂，手机端还发着旧键名 —— 两边没共用主键名 |
| 手机上**永远做不出抬头** | 摇杆上推这一路根本没映射 |
| 按住 Tab **菜单疯狂开关** | 没挡 `e.repeat`（系统按键重复每 30ms 一次 keydown） |
| 站在平台上**站一会儿就跳不动** | `prevVy > 0` 判落地，平站时 `prevVy` 恰好是 0，`coyote`/`jumps` 永不重置 |
| 跳不到平台顶面时**人悬在平台中间** | 单向平台按"身体碰到平台格"判定，下落那帧被判成撞进内部 |

> 判据：能力门必须按**按住不放的满跳**算。上一版测试是"点一下"，加了可变跳跃高度后
> 直接掉到 39px —— 测试测错了对象，不是功能坏了。

## 配乐（零音频文件）

`src/audio.js`，三层，没有鼓、没有和声进行：

1. **持续层**：73/110/146Hz 三个三角波，失谐 0.35%，低通 420Hz 由 0.03Hz 的 LFO 慢慢扫
2. **纸层（音效）**：带通白噪（2.4kHz, Q 0.6），增益由 0.07Hz 的 LFO 起伏 —— 这是"纸在动"
3. **点状层**：D 小调五声音阶的稀疏单音，间隔随机 3.5–9s，长衰减 + 反馈延迟

12 个音效：脚步 / 跳 / 二段跳 / 挥拳 / 命中 / 受击 / 落地 / 砸地 / 拾取 / **快门** / 传送 / 死亡。

> 为什么不用音频文件：单文件 HTML 撑不住、音乐授权是下架高危项、参数化改气氛比重新导出一个数量级快。
> `test_audio.js` 用假 AudioContext 验四件事：API 用错会静默失败、指数渐变不能从 0 起、
> 信号源不能是孤儿节点、静音后不该再产生节点。
> **我听不到声音**，所以我只能保证"结构对、不静默失败、不削顶"，音色好不好听得你自己听。

## 美术（没有素材包时的三件事）

1. **确定性噪声**：每格砖的明暗/缺角由 `hash2(x,y,seed)` 定死，同一格永远长同一个样（不会闪）
2. **邻接判定**：上面是空的就是顶面（加受光），左右是空的就是侧边（压暗）——
   这一条比画贴图更省，但"体积感"几乎全靠它
3. **离屏烘焙**：整张房间的静态瓦片只画一次，每帧一次 `drawImage`。
   之前每帧要发几千个 `fillRect`，桌面看不出来，iPhone 上会掉帧

其余：两层视差（0.20 / 0.45，公式是 `世界坐标 = camX*(1-p) + 屏幕坐标`，直接减 camX 会甩出屏幕）、
长廊背墙（挂镜线 + 护墙板 + 壁灯）、拱龛穹顶、浮尘、暗角、屏幕四边的"相框"。

> 敌人不是"怪物"是**被拍坏的照片**：纸团（折痕 + 撕口 + 工笔眉）、纸片蝙蝠（三缺口翅缘）。
> 第一版是绿史莱姆 —— 好读，但它不属于一个纸的世界。

## 关卡尺寸的硬约束（踩过）

人物 100px 高、**跳 203px（4.22 格）**、二段跳 331px、一格 48px：

- `=` 是**单向平台**：横向能穿、往上能穿，只有"脚从上方跨过顶面"才站住。
  判据必须是"脚跨顶面"，不能是"身体碰到平台格" —— 后者会让人卡在平台中间悬空
- 两级平台的**垂直**间隔 **≤ 4 格（192px）**才跳得上去（跳 203，余 11px）
- 相邻平台的**水平间隙**要 **≤ 2 格（96px）**。塔原来错开 8 格（间隙 144px），
  那一跳要"升 144px 的同时横跨 144px" —— 高度够，但水平只在下落回原高度的瞬间才够，
  余量不到一帧，真人按不出来。收到 7 格（间隙 96px）才回到能玩的范围
- 能力门高度取 **288px（6 格）**：单跳 203 差 85px 上不去，二段跳 331 余 43px 能上
- 台阶别做太矮：跳 203 对 144px 的台阶容易**跳过头**，落在上一级或越过。
  这不是 bug，原版台阶也是 3 格、跳 4.22 格，靠玩家自己控按键时长
- **门洞要开 3 格高（144px）**：人 100px 站在地上时头顶落在上一格里，只开 2 格 = 门在眼前进不去
- 平台**别贴到房间边界**：贴着墙时身体上部那格算实心，连原地跳都会被按住，人下不来
- 恶魔城手感（默认）没有土狼时间：**站在平台边缘先走再跳会直接掉下去**。
  想跳远处要"原地起跳、离地后再按方向"。这不是 bug，是那个年代的手感

> 这几条不是推出来的，是走不通才发现的 —— `probe_feel.js` / `play_probe.js` 存在的意义
> 就是让"路看着在、其实走不通"在发版前暴露，而不是等玩家卡在那里。

## 触屏（手游方向）

`src/mobile.js` 是独立一层，只做缩放和输入，玩法代码一行不改：

- **浮动摇杆**：左半屏任意位置按下就地生成，取水平轴，死区 11px；纵向推 = 抬头 / 蹲
- **四格 + 三键**：四格（剑/纸/红/蓝）44px 方形、点一下就用，三键（跳/翻滚/交互）也是方形，全部直接写进
  `game.js` 的动作层（`__sk.press('atk')`），所以"按住不连跳"的行为和键盘完全一致。
  未装备的魂格写「未装备」+ 虚线边，冷却画成从下往上退去的黑幕（不写数字）
- **布局可调**：`匣 → 操作 → 调整位置`，格子与三个键都能拖，松手落盘
  （`localStorage['soulkeep.layout.v1']`），「恢复默认」一键退回。
  细节见 [`DOC_CONTROLS.md`](DOC_CONTROLS.md) §9
- **自适应视野**：高度锁 540，宽度按设备拉宽（clamp 960–1280）；iPhone 19.5:9 → 1169，不留黑边
- **安全区**：HUD 内推 `env(safe-area-inset) / --s`（`--s` 由 JS 写入），刘海不压血条
- **渲染倍率**：`RS = 缩放 × DPR`，`ctx.setTransform(RS,…)`，Retina 上不糊
- **竖屏**：遮罩"请横屏游玩"

### 触屏判定（这里错过一次，代价是"游戏完全没法操作"）

```js
// ❌ 旧：有触摸硬件就算手机
var touch = ('ontouchstart' in window) || (navigator.maxTouchPoints || 0) > 0;
// ✅ 新：主指针是手指才算手机
var touch = forceTouch || (!forceDesk && mq('(pointer: coarse)') && mq('(hover: none)'));
```

Windows 触屏笔记本普遍报 `maxTouchPoints = 10`，旧判据把它们一律当成手机 ——
`#stage.touch #keys{display:none}` 把键鼠图例整个隐藏，画面被虚拟摇杆盖住，
提示还写着"左滑移动"。玩家看到的是"这游戏没法操作"，而按键其实一直是通的。

判据要用**主指针**（`pointer: coarse` + `hover: none`），不是"有没有触摸硬件"。
触屏笔记本属于"有触摸能力但用鼠标"，必须走键鼠那条路。

- `SoulKeep.html?touch=1` 强制触屏（手机验收）
- `SoulKeep.html?touch=0` 强制键鼠（在平板上外接键盘时）

### 焦点（iframe 里"按键没反应"的第二个原因）

游戏跑在 iframe 里（预览面板 / 嵌入页）时，父窗口拿着键盘焦点，按键到不了这一层。
代码全对、现象是"按什么都没反应"。处理：

- 画布是 `tabindex=0`，`boot()` 先抢一次焦点
- 页面任意 `pointerdown` 把焦点抓回来（零成本）
- 只在 iframe 里、且 4 秒内没收到任何按键时，显示"点一下画面，再按键"；顶层窗口不显示
