# 场景两态图：为什么被移到这里（2026-11-27）

**这 8 张不是"废弃"，是"被一个更好的方案取代"。** 留着不删，是因为它们下面是两条判据的实测依据。

## 移走的是什么

| 文件 | 原本的用途 |
| --- | --- |
| `terrain_grass_top_dark/ally.png` | 草皮母版的堵塞态 / 恢复态 |
| `ground_left_dark/ally.png` | 左段底板的两态 |
| `ground_mid_dark/ally.png` | 中段底板的两态 |
| `ground_right_dark/ally.png` | 右段底板的两态 |

一共 4 个地面件 × 2 态 = 8 张，由 `art/tools/scene_state.py --approve` 产出。

## 为什么移走

2026-11-27 白哥提出改用**环境光**：天上一个紫色月亮，所有东西被同一束光染色，
就不用给每个材质各画一套。

> 「摆件和地面的跟色可能和敌人不太一样，我更希望是一种环境光的反馈，
> 就是天上有个紫色月亮造成的环境差异，这样如果行的话就不用做两套美术了。」

方案落地为 `godot/world/shaders/env_light.gdshader` + `art/tools/env_light.py`，
契约见 `art/ASSET_RULES.md §3.2.6`。

同日白哥在实机看过紫月效果，结论是**「紫月够紫，不用改了」** —— 验收通过。
验收一过，这 8 张就没有消费点了：Godot 里没有任何 `.tscn` / `.gd` 引用它们
（只被 `manifest.json` 登记着），留着等于一份会被误认成"现行规范"的死资产。

## 留下来的价值

**这 8 张是下面两条结论的原始证据，别当垃圾清掉：**

1. **明度只能加法，不能乘法。** `§3.2.2` 那张表（乘法 0.74 → 对比度只剩 72%，
   八个文件全 FAIL；加法 −0.19 → 对比度分毫不动）测的就是这批图。
2. **绿砖的坑。** `§3.2.1` 断言 3「材质不糊」的抓点：石砖 H24 → H84 变成绿砖，
   实测两块只差 2°。这条后来在 shader 端复现为「土与草输出色相差 ≥22°」。

也就是说：**换方案没有推翻旧结论，只是把实现层换了。** 旧结论在新方案里照样成立，
是调参依据 —— 这也是 `§3.2.1–3.2.5` 被标为"推演记录"而不是"作废"的原因。

## 想回退怎么办

```bash
# 看这批图长什么样
ls art/_legacy/scene_two_state_2026-11-27/

# 真要回退到两态方案：图回到 approved、重新 --approve 一遍
git checkout d664862 -- art/approved/Terrain/   # d664862 = 移走前的最后一个提交
python art/tools/scene_state.py --check
```

> **回退之后记得把 `scene_state.py` 的 `DEPRECATED` 改回 `False`。**
> 那个开关是给"方案已废止"这个事实编码的，不是装饰。

## 工具的下场

`art/tools/scene_state.py` **留在原地**，没有跟着移走 ——
`§3.2.1–3.2.5` 大量引用它的命令与输出，移走会让文档断链。

但它已经停用：`BASE_STEMS` 清空（没有要产的两态图了），顶部 `DEPRECATED = True`，
`--check` 在空清单状态下**主动 exit 2 并说明原因**，而不是静默 PASS。

那条 `exit 2` 是特意加的。本项目在"空集合上做全称判断永远为真"这件事上踩过三次
（5 种敌人磁盘只有 3 种、空矩阵假通过、`BASE_STEMS` 漏掉野文件）——
一个遍历空清单的 `--check` 会一直报 PASS，然后有人以为它在守着什么。
