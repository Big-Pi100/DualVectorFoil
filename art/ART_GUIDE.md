## 1. 视觉基准（G0 · 已锁定）

### 1.1 唯一基准图

- 文件：`art/reference/character_style_sheet.jpg`
- 内容：主角三视图、待机/跑/跳/攻击/受击/攀爬动作、五种表情、史莱姆/小刺怪/小蝙蝠、草台/路牌/石拱门。
- 所有实验与正式资产均以此图为唯一风格母版。任何新风格参考图必须经用户明确确认并更新本节。

### 1.1.1 派生裁剪规则

允许从母版裁剪角色、头发、服装、敌人、地形等局部，帮助生成器聚焦对应特征。派生图**不是新基准**，必须可追溯到母版；不得用滤镜、重绘或风格迁移改变画风；未经用户确认的新生成图不得升级为正式参考。

```text
art/reference/
├── character_style_sheet.jpg
└── derived/
    ├── character_front.jpg
    ├── character_hair.jpg
    ├── character_clothing.jpg
    ├── enemy_samples.jpg
    └── environment_samples.jpg
```

每次只引用与当前资产相关的裁剪图，避免完整设定表中的文字、排版和无关元素干扰生成。

**多格参考禁令（E02 实测 F9）**：**生成单帧动作/视图时，禁用含多个动作或多个视图的派生图做 img2img 参考**（如 `character_actions.jpg` 的 6 格动作表）。多格参考会让生成器把相邻格的手臂、腿或配件混入同一人物，产生多余肢体。单帧动作必须：① 用**单帧**派生图做参考（`character_side.jpg` 等）或纯文字描述；② 在 Prompt 加 STRICT 肢体否定句（"exactly TWO arms / TWO hands / TWO legs, no extra stub, no duplicate elbow"）；③ 生成后**放大复核关节**，整体缩略图看不出多余手肘。失败样本标记 `FAIL_` 保留，不得混入正式资产。

### 1.2 六个不可丢失的视觉特征

1. **密集蜡笔笔触**：颜色由大量方向不完全一致的蜡笔短线反复叠加，有颜料堆积感，不是色块填充。
2. **粗糙变化的轮廓线**：深棕色为主，粗细变化、重叠、断续，不是光滑矢量描边。
3. **颜料不均匀覆盖**：可见底纸颜色、白色间隙和反复涂抹纹理，不是均匀数字填色。
4. **纸张底纹**：米白纸面有细密纤维与凹凸感，像真实画在纸上，不是简单叠加纸纹滤镜。
5. **稚拙但结构清楚**：头大、四肢短、手脚简化，头发由自由短线组成；五官简单、表情夸张，但人体结构可读。
6. **明亮温暖的手绘世界**：橙棕、红、蓝、黄、绿鲜明而协调；场景也有蜡笔摩擦感，不是角色有纹理而背景光滑数字绘画。

> 这不是普通儿童涂鸦，也不是普通蜡笔滤镜，而是以儿童稚拙造型为基础、以密集蜡笔反复涂画为主要表现手段的手绘游戏美术。**蜡笔纹理必须构成形体和颜色本身，不是后期撒上的噪点。**

### 1.3 主角设计锁定

| 部位 | 锁定特征 |
| --- | --- |
| 头发 | 棕色、蓬松、凌乱，由自由短线组成 |
| 围巾 | 红色 |
| 上衣 | 米白色，带黄色星星 |
| 短裤 | 蓝色 |
| 靴子 | 棕色 |
| 包 | 蓝色斜挎包，黄色星星装饰 |

正面、侧面、背面和各动作状态下上述特征必须一致；不得改变发型、衣服颜色、头身比例或配件位置。**主角保持普通角色，不增加纸片变身形态。**

### 2.2 Master Prompt

完整固定前缀：`art/prompts/Master_v1.3.md`。所有资产生成必须使用，不得逐图改写风格段落。

固定身份句：

> Create original 2D game artwork for **Dual Vector Foil (《二向箔》)** in the established visual style: **Childlike Wax Crayon Doodle Illustration**. The artwork must feel handmade, tactile, warm, playful, and imperfect — not like a polished digital cartoon with a crayon filter applied afterward.

固定约束：遵循唯一母版或对应派生裁剪；保留密集蜡笔短线、颜料叠加、局部纸白间隙和粗糙手绘轮廓；造型稚拙但结构清楚；不得转向彩铅绘本、矢量插画、光滑商业卡通、照片拼贴、暗黑奇幻或后期蜡笔滤镜。独立资产使用第 9 节洋红底与分隔线规则；**洋红底色与青色技术分隔线仅为制作辅助，最终必须移除，不属于美术配色**。

### 2.3 分资产画法差异与视觉层级

| 资产 | 笔触与细节重点 | 游戏要求 |
| --- | --- | --- |
| 主角 | 头发密集短线，衣服叠色，深色轮廓 | 动作辨识优先 |
| 敌人 | 强烈剪影，身体内部有蜡笔颗粒 | 攻击部位清楚 |
| 地形 | 石块、泥土、草地使用不同方向短线 | 碰撞边缘清楚 |
| 背景 | 线条可松散，细节适当减弱 | 不抢前景注意力 |
| 道具 | 轮廓清晰，局部密集填色 | 小尺寸也能识别 |
| 特效 | 短促、夸张、方向明确的蜡笔线条 | 不遮挡战斗信息 |
| UI | 手绘外框与局部蜡笔装饰 | 文字必须清晰 |

**视觉优先级**：主角轮廓最清楚 → 敌人轮廓清楚且危险部位突出 → 交互物醒目 → 可碰撞地形边缘清楚 → 背景与远景装饰逐级降低细节与对比。笔触方向服从形体：草地顺草叶、石头顺轮廓、头发顺发束。

## 3. 实验总原则

1. 唯一母版是最高优先级视觉基准。
2. 每次实验只改变一个主要变量。
3. 不同资产原则上分别独立生成；需一张图排布多个同类资产/动作格时，必须使用第 9.2 节分隔线规则。
4. 先判断绘画风格，再判断造型，最后判断游戏适配性。
5. 必须检查原图、统一尺寸和 Godot 实际显示尺寸。
6. 保留 Prompt、参考图、模型参数、原始结果、失败样本和评审结论。
7. 没有实际测试的数据不得标记为通过。
8. **洋红底色和分隔线不得进入正式资产。**
9. AI 生成图仅为候选素材；入库前必须检查结构、边缘、透明度和游戏内表现。允许人工修订，但不得改变锁定风格。

## 5. 实验方法与评分

### 5.1 控制变量

| 项目 | 控制方式 |
| --- | --- |
| 视觉参考 | 同一母版，按类别选可追溯的派生裁剪 |
| Master Prompt | `Master_v1.3.md` 固定版本 |
| 角色设定 | 使用本规范主角锁定 |
| 背景 | 独立资产实验统一纯洋红底；场景背景另行规定 |
| 分隔线 | 仅用于多格资产图，按第 9.2 节 |
| 尺寸 | 记录原始尺寸、统一比较尺寸、Godot 实际尺寸 |
| 生成方式 | 记录模型、参数和日期 |
| 单图内容 | 原则上一张一个资产；多格时每格一个对象/动作 |

### 5.2 样本数量与评审轮次

每个测试对象**至少 3 次独立生成**。三张样本必须来自三次独立生成，**不得把一张图裁成三张冒充独立样本**。保留全部结果，不只挑最好的一张。

| 轮次 | 检查 |
| --- | --- |
| 1 | 原始大图：材质与绘画细节 |
| 2 | 统一尺寸：轮廓、比例、结构 |
| 3 | Godot 实际游戏尺寸：可读性与功能 |

第三轮不可跳过；未放入 Godot 的样本不能据此通过 G4。

### 5.3 通用评分

| 项目 | 观察重点 |
| --- | --- |
| 蜡笔材质真实感 | 颜料摩擦、叠色、留白，而非滤镜 |
| 轮廓与线条 | 自然、不规则的手绘轮廓 |
| 造型与结构 | 比例、形体、重要特征清楚 |
| 色彩与纸面 | 温暖鲜明，纸面处理协调 |
| 跨资产一致性 | 与其他类别像同一套作品 |
| 游戏尺寸可读性 | 缩小后清楚、易识别 |

评分：1 明显不符合 · 2 偏差较大 · 3 基本可用但有明显问题 · 4 符合基准 · 5 高度符合。尚未进入的阶段项目标记 `N/A`，**不得猜测评分，也不得把 N/A 当作通过**。

### 5.4 阶段专项评分

| 阶段 | 专项项目 |
| --- | --- |
| E01 | 颜料叠加、笔触方向、纸白间隙、轮廓、纸面质感、材质层次 |
| E02 | 风格符合度、造型结构、颜色、关键识别特征、单体辨识度 |
| E03 | 线条一致性、材质一致性、色彩一致性、细节密度协调 |
| E04 | 剪影辨识、尺寸可读性、动作可读性、画面层级、边缘/透明度、Godot 显示效果 |

### 5.5 门禁判定

- **PASS**：当前阶段所有关键项 ≥ 4 分，无严重结构/功能问题，至少 3 个独立样本均达标。
- **REWORK**：有项目 < 4 分且偏差可通过调整明确变量修正；每轮只调整一个主要变量，失败项至少重生成 3 个样本。
- **STOP**：连续两轮仍不达标；类别间无法复现同一风格；或方法持续破坏结构/可读性。返回方法设计阶段，不得无限堆 Prompt 试错。

🔴 **不能用平均分掩盖关键缺陷**：材质只有 2 分时，其他项全 5 分也不通过。

## 6. 分阶段实验设计

### 6.1 E01 · 蜡笔材质一致性（下一轮）

**目的**：验证蜡笔表现能否跨不同形状和颜色稳定复现。

五类测试对象，每类至少 3 次独立生成（共至少 15 张）：

1. 棕色头发：一束清楚的发束 / 头发区域。
2. 红色围巾：有褶皱和方向变化的一段布料。← **洋红污染高危对象，见 9.6**
3. 蓝色挎包：完整包体，保留黄色星星识别装饰。
4. 绿色草地：一段草叶和草地边缘。
5. 灰褐色石块：一个独立石块。

**控制条件**：每个对象单独生成；统一画布比例、主体占比、观察尺度和纯洋红底；固定 Master Prompt；资产补充描述只说明形状、颜色和笔触走向。不得同时改变主体造型来弥补材质问题。E01 单对象图**不需要分隔线**。

**专项检查**：颜料密度、笔触方向、纸白间隙、深色手绘轮廓、纸张质感、蜡笔叠色层次。

**G1 通过条件**：六项均 ≥ 4/5；每类三个样本均表现稳定；不依赖额外噪点、模糊或滤镜才能产生蜡笔感。

### 6.2 E02 · 单资产类别验证

| 子实验 | 对象 | 重点 |
| --- | --- | --- |
| E02-A 主角 | 正面、侧面、一个动作；随后扩展动作 | 角色锁定、人体结构、服装一致 |
| E02-B 敌人 | 史莱姆、小刺怪、小蝙蝠 | 不同体型使用相同材质语言 |
| E02-C 地形 | 草地、泥土、石块 | 材质变化、平台边缘、拼接 |
| E02-D 道具 | 灯、钥匙、收集物 | 小尺寸辨识度 |

主角动作扩展检查：站立、跑步、跳跃、攻击、受击、攀爬。检查头部尺寸、围巾方向、挎包位置、四肢长度、重心和帧间连续性。先验证单帧，再验证连续动作。

**G2 通过条件**：每类至少 3 个独立样本；专项评分达标；不得出现彩铅、矢量或精致商业插画式异风格；不得出现只有背景有纸纹、主体却缺少蜡笔笔触的情况。

### 6.3 E03 · 跨资产一致性

将 E02 通过的样本并置比较：主角与敌人轮廓、不同材料的笔触、颜色覆盖、纸面/颜料颗粒、细节密度是否协调。

**G3 通过条件**：材质与线条一致性 ≥ 4/5；无明显异风格资产；不依赖统一滤镜伪造一致性。

> 一致性 ≠ 细节密度完全相同。不同密度仍须呈现相同绘画媒介和视觉语言。

### 6.4 E04 · Godot 游戏尺寸与功能验证

将资产导入《二向箔》真实 Godot 场景，按实际渲染尺寸、缩放和运行条件验证。

| 条件 | 目的 |
| --- | --- |
| 原始资产尺寸 | 材质与线条细节 |

**F13（G5 返工发现）**：**角色精灵严禁烘焙场景元素**（墙/石柱/草/地面/梯子等）。`climb` 首版因参考图取自带墙母版格 + prompt 写了 "climbing a stone wall"，生成出整面石墙（占右侧 40%）+ 脚底草；此类资产在游戏里爬任何墙都带同一面墙、与场景 tilemap 重叠、草出现在半空。

返工两次才收敛，两条教训都要记：
- **不能为去场景而丢人物参考图**：第二次重生成只用文字描述（无 `image1`），人物长相漂移（头变小、脸型发型全变）。**动作类资产即使要禁场景，也必须保留人物参考图锁长相**——正确做法是先用空间分离（墙在右/人物在左，手区用肤色判据）把参考图的墙草 P 成洋红底、做出"纯人物姿态参考图"，再 `image1` 用它 + NO-SCENERY prompt 生成。这样人物一致性与去场景两头兼顾。
- 单独把 prompt 从 "climbing a stone wall" 改成 `ABSOLUTE NO-SCENERY RULE`（显式列出 wall/stone/pillar/grass/ground…并声明轮廓外只有洋红底色）能彻底去掉场景；但**参考图里若残留场景碎色会被生成器放大**（手上抓握处的墙顶碎色变成手周围一圈灰绿轮廓），参考图必须先清干净。

- 主角正/侧/背结构一致，至少 4 种核心动作通过尺寸测试。

## 9. 洋红底色、资产分隔线与抠图规范

> 🔴 **最高优先级执行提醒**：洋红底色（`#FF00FF`）与青色分隔线（`#00FFFF`）是**生成和抠图的技术辅助色，不是最终美术配色**。主角有红色围巾和粉色脸颊，抠图时必须特别检查边缘颜色污染，**避免把主体细节误删**。

### 9.1 标准洋红底色

- 标准色：`#FF00FF`（RGB 255, 0, 255）。
- 背景必须均匀纯色，无纸纹、渐变、阴影、光晕、颗粒或装饰。
- 主体完整，四周留出空白安全边距，不接触画布边缘。
- 蜡笔纹理保留在主体内部，不得扩散成背景污染。
- 尽量避免主体大面积使用与洋红相同或极接近的颜色。

主角红色围巾、粉色脸颊等暖色区域需特别检查。抠图必须检查抗锯齿边缘、半透明像素和颜色污染；**不得只做简单颜色替换**。若资产本身必须使用接近洋红的颜色，应单独设计并记录抠图方案，不得牺牲主体颜色。

### 9.2 资产之间的分隔线（方案 A）

当一张图包含多个独立资产或动作格时，使用**资产之间的分隔线**划分单元格。分隔线不是主体轮廓线，不沿主体外缘描画。

1. 每个资产/动作占一个独立单元格。
2. 单元格之间使用清楚、连续、规则的直线；优先规则网格，不用斜线或不规则边界。
3. 分隔线只放在单元格之间的空白沟槽，不得穿过主体、阴影、蜡笔飞线或轮廓。
4. 主体与分隔线之间留安全间距；分隔线不得贴住主体。
5. 分隔线必须与洋红背景及主体轮廓明显区分。
6. 分隔线是临时技术标记，裁切后必须完全移除。
7. 自动裁切时，单元格尺寸和排列必须规则；不得让生成器自由决定格数和布局。
8. 默认不生成编号、文字标签、标题或装饰框；需要时另行制作。

建议技术分隔线颜色为纯青色 `#00FFFF`，并声明该颜色仅用于分隔线、不得用于资产主体。若资产包含大量青色，改用经记录的其他高对比技术标记色。抠图流程必须识别并移除分隔线颜色。

**优先单资产单图生成。** 分隔线主要用于同类动作帧、同规格道具或确需批量裁切的资产组，不得为了节省生成次数而混排不相关资产。

### 9.3 Prompt 技术附加段

独立资产：

```text
BACKGROUND AND EXTRACTION:
Use a perfectly uniform solid magenta background (#FF00FF, RGB 255, 0, 255).
No paper texture, gradient, shadow, vignette, particles, or decoration in the background.
Keep all crayon pigment, rough outlines, and texture contained within the asset.
Leave clear empty margin around the complete subject.
Do not let the subject touch the canvas edges.
The magenta background is a temporary extraction color, not part of the artwork.
```

多单元格资产：

```text
CELL SEPARATORS:
Arrange each requested asset/action in its own clearly separated rectangular cell.
Draw straight, continuous technical separator lines only in the empty gutters between cells.
Use cyan (#00FFFF) as a temporary separator marker, not as part of the artwork.
Never draw separator lines through, around, or touching any subject.
Keep consistent cell dimensions, alignment, and generous margins.
Do not add labels, numbers, titles, decorative frames, or extra assets.
All separator lines are temporary production marks and must be removed during extraction.
```

### 9.4 抠图与导出流程

1. 保存未经处理的原始生成图。
2. 根据网格和分隔线识别单元格，先裁切单元格区域。
3. 移除分隔线技术标记色。
4. 对单元格内洋红背景抠除，生成真正 Alpha 透明区域。
5. 检查主体边缘的洋红污染、白边、断裂和蜡笔纹理损失。
6. 在透明棋盘格及深浅两种背景上检查边缘。
7. 导出透明 PNG；不得以洋红背景替代 Alpha。
8. 导入 Godot，检查缩放、过滤、透明混合和边缘表现。
9. 保留原图、裁切图、抠图中间结果和最终文件。

### 9.5 各类资产背景规则

| 类别 | 生成/交付规则 |
| --- | --- |
| 主角、敌人、道具 | 洋红底生成；抠图后透明 PNG |
| 特效 | 洋红底生成；透明 PNG；重点检查半透明效果 |
| 地形 | 独立地形块可抠图；需无缝拼接时额外检查边缘 |
| 背景 | 完整场景背景，不强制抠成透明主体 |
| UI | 独立元素可抠图；文字与信息层单独检查清晰度 |

纸张纹理可存在于绘画主体内部，也可作为独立背景层；不得未经设计烘焙成所有资产的矩形背景。

### 9.6 本次新增：洋红污染防护补强（针对红围巾 / 粉脸颊）

> 以下是基于「洋红辅助色 ≠ 美术配色」提醒做出的可执行补强，纳入 G2 / G4 的透明度专项检查。

**根因（事实）**：`#FF00FF` 的红色通道与蓝色通道均为满值。红色围巾、粉色脸颊同处暖红/粉色相区，色相与洋红相邻；使用「按颜色全局替换」或高容差色键抠图时，这两处最容易被误判为背景而删除，或留下品红边。这是用户点名的具体风险。

**硬性做法**：

| # | 规则 | 理由 |
| --- | --- | --- |
| P1 | **禁用全图颜色替换**，改为「从画布四角做种子 flood-fill，只删除与边缘连通的洋红区域」 | 主体内部的暖红/粉色像素不与边缘连通，不会被删 |
| P2 | 纸白间隙必须是**米白色颜料实体**，Prompt 明令「gap 为 paint, not exposed background」 | 否则抠图后主体出现破洞，蜡笔质感塌掉 |
| P3 | 主角一律**单资产单图生成**，禁止用多格分隔线批量出主角 | 主角同时带红围巾、粉脸颊、蓝挎包，与洋红底、青线双撞色 |
| P4 | 边缘半透明像素做 **despill（去色溢）**：将残留洋红分量替换为邻近主体色，不直接删除 | 保住抗锯齿柔边，避免轮廓被啃出缺口 |
| P5 | 抠图参数（flood-fill 容差、羽化半径、despill 强度）写入实验记录 | 保证可复现，符合门禁第 6 条 |
| P6 | 多格图若主体含蓝/青色，分隔线改用经记录的高对比技术色（不可与主体同色系） | 青线与蓝挎包/蓝短裤撞色，同样会误删 |
| P7 | 抠图后在深/浅/棋盘格三背景 + Godot 实际缩放过滤下各看一次红围巾与脸颊 | 静态大图看不出小尺寸品红边 |
| **P8** | **生成工具若强制加水印（浅色文字、不与背景连通），抠图前必须先剔除水印区域** | flood-fill 只删与边缘连通的背景色，水印是独立前景会残留 |
| **P9** | **不按死阈值 `#FF00FF` 抠图；先从画布实测背景色，再按实测色做 flood-fill** | E01 实测生成器输出为 `RGB(239,29,168)`，与 `#FF00FF` 差距大，死阈值会失效 |
| **P10** | **背景色采样必须排除右下水印区**：从画布边缘条带取样本、剔除水印矩形后取中位数，不得只取四角 | E04 F10：四角采样点落在水印上（G 通道偏高如 `[255,102,201]`），污染 median 导致背景删不干净 |
| **P11** | **被删除像素的 RGB 必须做最近邻颜色扩散**（把主体边缘色填入透明区），不得让 alpha=0 像素保留洋红 RGB | E04 F11：Godot `Image.resize` 的 BILINEAR 插值会把透明像素的洋红 RGB 混进半透明边缘，产生品红边；静态大图看不到，只有游戏缩放链暴露 |

**P1 的判定口径**：若某资产内部必须出现接近洋红的颜色，单独记录抠图方案；不允许以「牺牲主体颜色」换取抠图方便。

**抠图工具**：`art/tools/extract_magenta.py` 已实现 P1/P4/P8/P9/P10/P11，本项目所有正式资产一律用它处理，禁止手写临时脚本替代。

### 12.1 引擎条款等价表

| 规范条款（Godot） | 本项目（Canvas 2D） | 等价做法 | 是否仍必须执行 |
| --- | --- | --- | --- |
| `preload("res://art/approved/…")` | `new Image(); img.src='art/approved/…'` | 目录结构逐字一致，路径只需去掉 `res://` | ✅ |
| SpriteFrames 单帧动画（每态 1 帧、speed 10） | 状态 → 贴图查表 | 本项目同样按「一态一图」渲染，不做多帧插值 | ✅ |
| E04 Godot 实际游戏尺寸验收 | 实机 Canvas 截图（`shots/`） | 必须在 960×540 真实画布下看，静态大图不算 | ✅ 不可跳过 |
| `Image.resize` BILINEAR 混洋红（P11） | `ctx.drawImage` 缩放同为双线性 | **P11 在本项目同样成立**：alpha=0 处残留洋红会被混进边缘 | ✅ |
| Godot 导入过滤设置 | `ctx.imageSmoothingEnabled` | 角色帧缩小 0.51×，必须开 smoothing；瓦片整数倍放大才关 | ✅ |
| Godot `_process` 帧循环 | `requestAnimationFrame` | 无差异 | — |

### 12.2 尺寸换算（本项目唯一口径）

素材实测（`player_idle_00_sprite.png`，340×340 帧框）：

| 量 | 值 | 来源 |
| --- | --- | --- |
| 帧框 | 340×340 | 素材原尺寸 |
| 主体 bbox | 153×251（x 93–245，y 45–295） | alpha>8 实测 |
| 脚底基线 | y = 295 | 同上 |
| 本项目角色显示高 | **128**（`P_SPRITE_H`） | `src/game.js:144` |

换算：`scale = 128 / 251 = 0.5100` → **帧显示 173×173**，脚底距帧顶 `295×0.51 = 150.5`，距帧底 `173−150.5 = 22.5`。

渲染时以「脚底对齐碰撞盒底边」为锚点，不要用帧框中心对齐（帧框上下留白不对称）。

**各态主体高不同，统一用 0.51 这一个缩放比**（不要逐态归一化，否则跳/受击姿态会被拉高，动画抖动）：

| 状态 | 主体 bbox | 主体高 | 显示高（×0.51） |
| --- | --- | --- | --- |
| idle | 153×251 | 251 | 128 |
| back | 149×256 | 256 | 131 |
| side | 125×240 | 240 | 122 |
| climb | 176×237 | 237 | 121 |
| run | 142×234 | 234 | 119 |
| jump | 199×226 | 226 | 115 |
| hurt | 248×218 | 218 | 111 |
| attack | 236×200 | 200 | 102 |

### 12.2.1 敌人与道具：不要跟着角色缩放

敌人 sprite 是 **128×128 帧框，主体恰好 48 高 = 1 个 TILE**（三个敌人都是 48，这是标准化时刻意对齐的）。**直接用原尺寸渲染，不要再乘 0.51**。

| 资产 | 帧框 | 主体 | 直接渲染 | 相当于 |
| --- | --- | --- | --- | --- |
| `enemy_slime_idle_00_sprite` | 128² | 68×48 | 128² | 1 TILE 高 |
| `enemy_spike_idle_00_sprite` | 128² | 53×48 | 128² | 1 TILE 高 |
| `enemy_bat_idle_00_sprite` | 128² | 68×48 | 128² | 1 TILE 高（可上浮） |
| `item_star_sprite` | 48² | 36×36 | 48² | 1 TILE |

角色 128 高 / 敌人 48 高 = **2.67 : 1**，这是这套资产的原始比例，改它就等于改世界观。

### 12.2.2 地形摆件：只能摆，不能铺

| 资产 | 尺寸 | 相对角色(128) | 用法 |
