# p5.brush 能力评估（2026-11-25 实测）

> 上游：[acamposuribe/p5.brush](https://github.com/acamposuribe/p5.brush)（MIT，1.4k★）
> 本地：`.deps/p5.brush`（29MB，已 gitignore，只用于查源码与出图）
> 结论先说：**它是笔刷引擎，能画瓦片、也能画贴片。**
> 边界只有两条：元素最小可画尺寸 ≈120px、只做"有方向"的东西。
> 判据与背景需求清单见 `BG_SCOPE.md`；分工见 §5。

## 0. 它是什么

一个给绘画用的**笔刷引擎**：不是"生成图片"，是把「笔刷 + 路径」渲染成像素。
一支笔 = 一张带颗粒的笔尖纹理，沿路径按 `spacing` 盖章，`scatter` 让它横向散开，
`pressure` 让起收笔变细。粉笔/炭笔/蜡笔的区别只是那张纹理和这几个数的组合。

两个构建，**不能混用**：

| | p5 build | standalone build |
|---|---|---|
| 文件 | `dist/p5.brush.js`（111KB） | `dist/brush.js`（123KB） |
| 依赖 | p5.js 2.x + WEBGL 画布 | **无依赖**，只要浏览器 WebGL2 |
| 画布 | `createCanvas(w, h, WEBGL)` | `brush.createCanvas(w, h)` |
| 坐标 | p5 的 `translate()` | `brush.translate()` |
| 种子 | `randomSeed()` / `noiseSeed()` | `brush.seed()` / `brush.noiseSeed()` |
| 落帧 | 自动 | **必须 `brush.render()`**，否则画布全空 |

我们用 **standalone**：headless chromium 实测 WebGL2 可跑，`seed()+noiseSeed()` 两重置后
两次渲染字节完全一致（**只调 `seed()` 不行，噪声不清** —— 这条只看文档想不到）。

## 2. 命令集

### 2.1 画布与生命周期（standalone）

```js
brush.createCanvas(W, H, { parent?, pixelDensity? })
brush.clear(color?)        // 清成某个底色（不是 background()）
brush.render()             // ‼ 落帧，忘了就全白
brush.load(canvas)         // 切到离屏画布；再调一次切回来
```

### 2.2 笔刷状态

```js
brush.set(name, color, weight)   // 一次设三个，最常用
brush.pick(name)                 // 只换笔，颜色/笔宽不动
brush.stroke(color)              // 只换颜色（同时启用描边）
brush.strokeWeight(w)            // 只换笔宽
brush.noStroke()                 // 关描边（涂面之前必须调）
brush.box()                      // 列出所有可用笔刷名
brush.scaleBrushes(s)            // 全局缩放所有笔刷
```

`weight` 是**倍数**，实际像素 = 笔刷基础 width × weight × scaleBrushes。
这是它最反直觉的一处：`set('HB', c, 1.2)` 在 192px 画布和 768px 画布上粗细差 4 倍。

### 2.3 线

```js
brush.line(x1, y1, x2, y2)
brush.flowLine(x, y, length, dir)      // 沿矢量场走，dir 跟 angleMode
brush.spline([[x,y,p], ...], curv?)    // 逐点压力，返回 Plot 可复用
brush.beginStroke('curve'|'segments', x, y)   // 手动分笔
brush.move(angle, length, pressure)
brush.endStroke(angle, pressure)
```

### 2.4 形状

```js
brush.rect(x, y, w, h, 'corner'|'center')
brush.circle(x, y, r, irregularity)    // irregularity 0~1 = 手绘歪斜
brush.arc(x, y, r, start, end)         // ‼ 只能描边，不能填
brush.polygon([[x,y], ...])            // 返回 Polygon，可后补 hatch/mass
brush.beginShape(curvature?) / brush.vertex(x,y,p?) / brush.endShape(close?)
```

### 2.5 涂面：三种，必须分清

| 方法 | 是什么 | 适合 |
|---|---|---|
| `fill(color, 0-255)` | **水彩**：Hobbs 生长形状，有边界沉积、颗粒沉淀、湿接湿 | 背景层次、天空、远处雾 |
| `mass(name, color, opt)` | **干性手绘填充**：用指定笔刷来回涂满 | 蜡笔/粉笔色块（我们的主力） |
| `hatch(dist, angle, opt)` | **排线**：一组平行线，可叠两组做交叉 | 阴影、明暗、纹理叠加 |

```js
// 水彩
brush.fill(color, opacity)
brush.fillBleed(strength, 'out'|'in', angle?, softness?)   // 边缘渗开
brush.fillTexture(textureStrength, borderIntensity, scatter?, split?)
brush.noFill()

// 干性填充（蜡笔的正确用法）
brush.mass('crayon', color, { precision, strength, gradient, outline })
brush.noMass()

// 排线
brush.hatch(dist, angle, { rand, continuous, gradient })
brush.hatchStyle(name, color, weight)
brush.noHatch()

// 批量（把已存的几何体当一次手势）
brush.hatchArray(polygons, { rule: 'evenodd'|'nonzero' })
brush.massArray(polygons, { rule })
```

> `mass` 的 4 个参数**实测语义**（文档没写清，这是从渲染结果反推的）：
> - `strength` = 排线密度。0.5 是**稀疏几道**（不是"淡"），1.0 才涂满
> - `precision` = 笔触贴合形状边界的程度。高 → 边缘齐；低 → 溢出
> - `gradient` = 沿某个方向的浓淡渐变
> - `outline` = 是否在形状外圈补一道轮廓

### 2.6 矢量场

```js
brush.field(name)          // 内置：hand / curved / zigzag / waves / seabed / spiral / columns
brush.wiggle(intensity)    // = field('hand', intensity)，手抖
brush.noField()
brush.refreshField(t)      // 动画时每帧推进
brush.listFields()
brush.addField(name, (t, grid) => { ... })   // 自定义，返回角度网格
```

### 2.7 变换与裁剪

```js
brush.push() / brush.pop()
brush.translate(x, y) / brush.rotate(a) / brush.scale(x, y?)
brush.angleMode(brush.DEGREES | brush.RADIANS)
brush.clip([x1, y1, x2, y2]) / brush.noClip()
```

> **WebGL 原点在画布中心**，第一句永远要 `brush.translate(-W/2, -H/2)`。

### 2.8 自定义笔刷

```js
brush.add('name', {
  type: 'default'|'spray'|'marker'|'custom'|'image',
  weight, scatter, sharpness, grain, opacity, spacing,
  pressure: [s, e] | [s, m, e] | (t) => v,
  tip: (_m) => { ... },        // type:'custom'，在 100×100 空间里画，原点居中
  image: { src: './tip.png' }, // type:'image'，要 await
  rotate: 'none'|'natural'|'random',
  markerTip: true|false,
  noise: 0..1,
})
```

### 2.9 十一个内置笔刷的实测手感

| 笔 | 特征 | 我们能用来做 |
|---|---|---|
| `pen` / `rotring` | 极细、硬、几乎无颗粒 | 极细结构线、刻字、标注 |
| `2H` / `HB` / `2B` | 铅笔三档（浅→深） | **结构线**（砖缝、门框），连续不断 |
| `cpencil` | 彩色铅笔，柔 | 远景线条、草稿感 |
| `charcoal` | 炭笔，颗粒粗、对比强 | 深色区、阴影、砸实的暗部 |
| `crayon` | **蜡笔**，颗粒中等、边缘碎、有纸白 | 我们的主笔 |
| `pastel` | 粉笔，最软最散、覆盖力强 | 大面积厚色、背景、光晕 |
| `marker` | 马克笔，平头、边缘硬 | 平涂色块、UI 色带 |
| `spray` | 喷枪，纯散点 | 尘、雾、火星（不能画实体） |

## 3. 实测：能做到什么（`shots/p5brush_cap.png`）

这张样张只用我们 12 色板，画了：11 种笔的同一条线（直线+折线+重笔+小圆）、
6 种涂面（水彩 / mass × 两档 strength / pastel / outline / 交叉排线）、
6 个矢量场、`circle` 三档不规则度、`spline` 逐点压力、`clip` 遮罩、三遍叠涂。

**能做好的**：

1. **单笔质量高**：芯实、边碎、外面飞屑 —— 和生图的蜡笔样本表对得上。
   我 Python 版调了七八轮才勉强接近，它开箱就是这样。
2. **`mass` 的涂面有"一笔一笔"的方向感**，边缘毛糙、留纸白。这是它最强的一项。
3. **`spline` 逐点压力**：一笔之内线宽自己变化，Python 版没有这个能力。
4. **矢量场**：草、发丝、烟、雨这类"要顺着某个方向乱"的东西，靠 `field` 一行搞定。
5. **`clip` 遮罩**：排线可以只在框里出现，做 UI 和阴影很有用。
6. **速度**：1240×860 全画完 1.2 秒；192×192 瓦片 90–450ms。

**做不好的**：

1. **`spray` / `pastel` 在细线上完全读不出**（谱系图最后几行糊成一片）。
2. **叠涂三遍会糊成实心黑块**（底部右侧那块），越叠越丢笔触 —— 和真蜡笔"越叠越深但仍有颗粒"不同。
3. **`clip` 只对 stroke 生效**，hatch 会跑出来（图里方框内只有我画的横线，斜排线没进来）。

## 4. 做不到什么 —— 三条，但都被误读过

> **本节 2026-11-25 修订。** 初版写的是"没有 wrap / 笔触尺度绑画布 / strength 不是浓度"，
> 其中第二条是错的，第一条有解。真正的判据见 `BG_SCOPE.md` §2。

### 4.1 没有 wrap —— 有解：9 重放

它的每一笔都裁在当前画布内。无缝平铺要**同一份内容平移 9 次**：

```js
for (const [ox, oy] of [[0,0],[-W,0],[W,0],[0,-H],[0,H],[-W,-H],[-W,H],[W,-H],[W,H]]) {
  brush.seed(S); brush.noiseSeed(S);      // 两个都要重置，只重置 seed 不够
  brush.push(); brush.translate(ox, oy); paint(); brush.pop();
}
```

两个前提：
1. **几何随机必须走自研 PRNG**，不能用 `Math.random()` —— 否则 9 份错开，接缝裂开。
2. **内容本身必须有周期**：砖宽组合必须凑满瓦片宽，起点对齐瓦片宽。
   初版用随机 offset(0~192)，结果同一区域被 `ox=0` 和 `ox=±192` 两套砖同时覆盖，缝交错成乱线。

成本：单张 192 瓦片 8–12 秒。离线生成，可接受。

### 4.2 笔触尺度 —— 绑的是**形状**，不是画布

`mass` 的弧线半径 = `dist(中心, 形状端点)`（`hatch/mass.js:360`）。
`scaleBrushes()` 只改 `weight / scatter / spacing`（`stroke/stroke.js:240`），**管不到半径**。

所以：
- 96×48 的砖里，弧线半径 ≈ 54，一道弧就跨过整块 → 只能落两三道，读成"毛刷扫过"
- 96×96 的石头里，半径 ≈ 68，能落四五道 → 读成"一块被涂过的石头"

**推论：元素最小可画尺寸 ≈ 120px。** 这条直接约束了场景设计（石头 ≥96×48、柱子 ≥128 宽）。

### 4.3 `strength` 是排线密度，不是浓度

0.5 是**稀疏几道弧**（不是"淡"），1.0 才涂满。
想"变深"只有一条路：**同一支笔多涂一遍**，不是降低 strength。
用低 strength 叠"暗部"会得到一把黑毛刷（`shots/wall_new.png` 那版的黑笔触就是它）。

## 5. 分工（按"能不能画得开"，不按喜好）

| 图层 | 谁做 | 理由 |
|---|---|---|
| 墙 / 地 / 平台 **瓦片** | **p5.brush**（`tilegen.html`） | 9 重放能无缝；石头 ≥96×48 时 mass 正好 |
| **房间装饰贴片** | **p5.brush** 出透明底 PNG | 有机形状、无接缝问题 |
| 标题画面 / CG / 过场 | **p5.brush** | 一次性整图，尺度最合适 |
| 角色立绘 / 角色卡 | **p5.brush** | 大尺度、要笔触 |
| 特效（火、烟、尘、光） | **p5.brush** `field` + `mass` | 矢量场是它独有的 |
| 门框 / 窗格 / 齿轮 / UI 边框 | **程序画** | 要精确几何，笔刷画不出直线 |
| 雾 / 光晕 / 暗角 / 均匀渐变 | **引擎层** | 各向同性，mass 做不了 |
| 尘埃粒子 | **引擎层** | 运行时每帧，它是离线渲染器 |

**统一画法 ≠ 统一工具。** 玩家的眼睛认的是"笔触一不一致"，
不是"是不是同一个程序生成的"。程序画的精确直线 + p5.brush 画的材质，
在蜡笔画里本来就是两种笔（尺子 / 蜡笔），并存不冲突。

## 6. 瓦片生成实测记录（2026-11-25）

走了 12 版，每版都是踩出来的：

| 版 | 做法 | 结果 |
|---|---|---|
| A | 整幅 hatch | 粒度对了，但横排线跨过砖缝不断 → 读成草席 |
| C | 整幅 mass | 弧线横跨半张图，彻底失控 |
| D/E | 逐砖短笔 | 砖形出来了，但砖之间是**没涂到的纸色** → 贴纸拼贴 |
| F/G | 逐砖独立涂法 | 涂法有个性了，但白缝 + 蓝灰太跳 |
| H/I | 满铺底 + 逐砖 mass | 缝变成"露出来的白底"，石头边缘一圈亮边 |
| K | 小砖 + 碎笔触 | 被纸白框成贴纸 |
| L | 96×96 大石 + mass | 单看最好，**进游戏读成"预制板"**，10 块铺满一屏 |
| 定版 | 96×48 小砖 + 一密一稀两遍 mass + 黑缝 + 不铺满底 | 砖形、笔触、露纸三者都在 |

定版的三条关键：
1. **不铺满底** —— 蜡笔质感一半来自"纸色从笔缝透出来"，铺密排线会变成刷涂料
2. **一密一稀两遍** —— 密的一遍保证"这块是实心的"，稀的一遍保证"看得见笔"
3. **缝是画上去的暗线，不是露出来的底** —— 露底会让 mass 在 rect 边缘堆出一圈亮边

## 8. 瓦片填色：四个参数语义 + 一条硬边界（2026-11-25，20+ 变体实测）

> 起因：`decal_on_wall.png` 里墙最不搭。用户看后说「太满了，笔触填色其实不是填满的」。
> 结论是**四个参数一直被误读**，纠正之后才知道"满"不是层数问题。

### 8.1 四个纠正

| 参数 | 以为 | 实际 | 源码 |
|---|---|---|---|
| `mass` 的 `strength` | 浓度 0~1 连续 | **三档层数开关**：≤0.33 打 1 层、≤0.66 打 2 层、>0.66 打 3 层。没有中间值 | `hatch/mass.js:605,621` |
| `set(name, color, w)` 的 `w` | 像素宽度 | **乘**在笔刷自身 `weight` 上。`crayon` 的 weight 是 0.33，所以 `set(…, 6)` 只有 2px | `stroke.js:562` |
| `mass` 内的笔宽 | 跟随 `set` | `createMass` 里固定 `set(brush, color, **1**)`，所以排线笔宽恒为 **1×笔刷weight** | `hatch/mass.js:572` |
| `scatter` | 颗粒强度 | **每个 dot 的横向随机偏移**（单位=笔宽）。`crayon` 1.9 会把 1px 的笔散成 2px 的雾 —— 这就是"水波/木纹"的来源 | `stroke.js` queueSegment |

**`strength` 是三档**这一条最要命：旧版配方「0.52 + 34%×0.58 + 0.30 + 26%×0.72」看起来是"一密一稀"，
实际是 **4.5 层 mass pass**（2+0.68+1+0.78），纸色被彻底吃光 —— 实测 std 13、纸色 0%，
而参考图 `p6_crayon.png` 同口径是 std 74、纸色 17%。**"涂满"的量化含义就是这两个数。**

### 8.2 硬边界：96×48 的小砖上做不出"可辨笔触"（⚠ 此结论已被 §10.3 推翻）

> **2026-11-25 后记：这条是错的。** 把生图砖块压到 96×48 后蜡笔排线依然清楚（std 42），
> 96px 完全装得下。真正的原因是我画的**频率**太低（周期 8~10px = 木纹频率），
> 不是面积不够。详见 §10.3。下面这段保留作为过程记录。

一块砖 96×48 ≈ 4600 px。一条能看出来的笔触（4~6px 宽 × 30px）占它 **1/10 面积**：
- 拉对比（亮一档/暗一档）→ 读成"贴上去的一道胶带 / 迷彩块"
- 不拉对比 → 融进底里，看不见

这不是参数问题，是**面积问题**。试过的 20 多个变体全部落在这两头：

| 变体 | 做法 | 结果 |
|---|---|---|
| A | 一密一稀 + 两成补涂（4.5 层） | **平灰**，std 13，用户否掉的那版 |
| B | 单层 mass | 笔触清楚，但露白条 → "没画完" |
| C/D | scribble 短笔 | 颗粒斑驳，但每块一样深浅、方向各自随机 |
| E/F/G | 长短短笔叠 | 砖缝断（charcoal opacity 只有 120） |
| H/K | 14/10 行手涂 | 纸色 18%/27%，与参考图 17% 吻合，但露白成**长条** |
| J | 薄 mass 垫底 + 22 行手涂 | 纸色 0.1% —— 印证 mass 就是"满"的元凶 |
| L/M | 抖动网格手涂 | 网格 `Math.max(2,…)` 把 n=1 放大成 4 笔，一直"满" |
| P | 修好网格 + 长短混合 | 连贯短条，但纸色仍成长条 |
| X/Z3 | 三档明暗笔压在底上 | 96×48 上成"胶带"，96×96 试过成"迷彩" |
| Z4 | 两层 crayon + 28% 补涂 | **定版**：std 20，进游戏能看见波浪形涂抹 + 石头深浅差 |
| DD/EE | 整面长笔触 + 勾缝 | 结构对了，但 1px 笔配 8-bit 累积出"白刮痕" |

### 8.3 定版

```
mass('crayon', base, {strength: 0.42, precision: 0.74})   // 2 层
若 rnd()<0.28 → 再来一遍 0.50                            // 3 层，石头变深
砖基色三档：#929188 / #83827B / #8C8B84（差 ±7%，再大就成补丁）
```

比旧版少的只有层数（4.5 → 2.3），但这就是"不满"与"满"的分界。

### 8.4 要继续往下走，只有两条路

1. **换元素尺度**：石头 ≥192×96 让笔触有地方施展 —— 但 96×96 试过，进游戏整面墙读成"预制板"
2. **换工具**：`crayon.py` 的笔尖纹理模型（转写自 p5.brush 的 stamp + scatter）在任意尺度下都成立，
   代价是它没有 `mass` 的绕形状弧线

**现阶段的取舍**：瓦片用 p5.brush（无缝、9 重放已验证），接受"像石材纹理"而不是"像蜡笔涂鸦"；
笔触质感交给贴片/立绘/标题（它们尺度够）。这条已经在 `BG_SCOPE.md` §2 的分工里。

## 9. 生图当"标尺"：先造一块目标砖，再照着复现（2026-11-25）

> 起因：用户说「太满了…笔触填色其实不是填满的」。对着整张风格图猜"什么叫不满"，
> 猜了 20 多个变体都没对上。改用**先生成一块目标砖**（`art/tiles/ref_gen/`），
> 把"不满"变成一张可以逐条对照的图，问题一下就具体了。

### 9.1 方法

用生图模型以 `p6_crayon.png` 为参考图，只画**一块砖**（隔离目标，不给场景干扰）。
生成后逐条列特征，再用 p5.brush 复现 —— **"复现不了哪一条"本身就是结论**。

生图砖块的四个特点（当前瓦片一条都没有时）：

| # | 特征 | 说明 |
|---|---|---|
| 1 | **粗笔触条带** | 一条条 20~35px 的斜笔，大致平行但有 ±3° 摆动 |
| 2 | **窄缝透底色** | 带间留 8~12px 亮缝，缝里是纸/浅灰，**不是白** |
| 3 | **明暗来自条带本身** | 每条带自己深浅不同，不是"平底 + 另叠亮笔" |
| 4 | **毛边轮廓** | 砖边是粗炭笔抖线，宽窄不一、会断 |

第 3 条是之前理解反的地方：`Z3` 变体试过"平底 + 三档明暗笔"，在 96×48 上成了"贴胶带"。
正确做法是让**每一根条带按自己在砖里的位置取色**，亮暗是条带的属性，不是额外一层。

### 9.2 条带画法的五个关键值

```js
// 角度：横长条石材走**接近水平**，不是 30°
a = -0.07 + (rnd()-0.5)*0.14        // 2:1 横砖。照方形砖取 -30° 会读成"斜纹布"

// 带宽/缝宽（96×48 上）
bw = 4.8 + pow(rnd(),1.3)*3.4       // 4.8~8.2px  参考图一层约占石高的 1/5
gp = 1.7 + rnd()*1.1                // 缝 1.7~2.8px，再宽就成"白条"

// 明暗：必须按**合成后的目标亮度**反推笔色
grad = 48 - 104*rel                 // rel = 条带在砖内的相对高度（0 顶 / 1 底）
col  = shade(base, grad + (rnd()-0.5)*20)

// 条带要断成 2~4 段（每段 60%~110% 均分长，段间留 1~3.4px 缺口）
```

**`opacity` 反推这一条是本次的关键。** `stripe` 的 `opacity` 是 165/255（65%），
笔色会被纸色抬亮：`合成后 = 0.647×笔色 + 0.353×纸(≈220)`。
所以想让砖面读到 90，笔色得压到 20 左右。
前几版按"看起来的亮度"给 ±25 的偏移，合成后差距只剩十几 —— 量化出来 std 17~19，
而参考图同口径是 **59**。改成按合成公式反推后，std 直接到 29。

### 9.3 走错的两条路（留注释，别再走）

| 做法 | 症状 | 原因 |
|---|---|---|
| 照方形砖取 -30° 斜条带 | "斜纹布 / 木地板" | 2:1 横砖 + 30° = 一条带正好横贯整砖，读成机织纹 |
| 缝里透**纯纸色**（无底） | "划痕 / 白条 / 到处破洞" | 缝要的是**浅灰**，纸色是 220，对比过强 |
| 条带一笔拉通整砖 | "印上去的条纹" | 蜡笔做不到 96px 不断；放大参考图看，每条带由 2~4 段接起来 |

### 9.4 复现结果：抓到 3/4

| 特征 | 是否复现 | 备注 |
|---|---|---|
| 粗笔触条带 | ✅ 部分 | 能看到一条条横向笔触，但宽度只有 3~8px，缺"厚度" |
| 窄缝透底色 | ✅ | 缝 1.7~2.8px，读作浅灰不是纸白 |
| 明暗来自条带 | ✅ | 上亮下暗，std 28.6（旧定版 18.7） |
| 毛边轮廓 | ✅ | 缝宽 2.2px + `wiggle(0.30)` |
| **笔触的"蜡的厚度感"** | ❌ | 生图的每条带有 20~35px 宽、能堆出蜡的隆起；缩到 96px 砖只剩 3px，8-bit + 65% opacity 混合后糊成灰 |

**第 5 条是 §8.2 那条硬边界的另一种表述**：不是 p5.brush 画不出，是这块砖装不下。

> **2026-11-25 后记：这条判断也错了。** 生图砖块压到 96×48 后蜡笔排线依然清楚，
> 装得下。原因在频率（周期 2.7px vs 我画的 8~10px），详见 §10。

### 9.5 当前定版（S2）

```
stripe 笔：weight 1.0, scatter 0.28, sharpness 0.76, grain 1.5, opacity 165
角度 -0.07±0.07（每块砖独立抖）
带 4.8~8.2px / 缝 1.7~2.8px / 断 2~4 段
明暗 grad = 48 - 104*rel
砖基色三档：#A4A398 / #9C9B90 / #96958A（差 ±5%，实测差 20 会成"补丁"）
缝：seam 2.2px + wiggle(0.30)
```

实测 mean 112 / std 28.6；进游戏（`shots/scene_hall_S2.png`）比旧版读得出"一块块砌上去"，
但仍达不到"蜡笔涂鸦"级别 —— 与 §8.4 的两条路结论一致。

> ‼ **改了瓦片 PNG 必须重跑 `python build.py`**。
> 瓦片是构建时 base64 内嵌进 `SoulKeep.html` 的（`build.py` 的 `__TILES__`），
> 只换 `art/tiles/*.png` 不重新构建，游戏里跑的还是旧图 —— 本轮在这上面白拍了一轮对照。

## 10. 机制：它到底怎么画一笔（2026-11-25，查源码后纠正）

> 起因：用户问「P5 是怎么画出来的？是选好笔触然后规定路径，像人类画画那样吗？」
> 答案是一半是 —— 而**不是的那一半**恰好是我前面所有版本失败的原因。

### 10.1 它真的是"笔尖沿路径走过去"

一条 `brush.line(x1,y1,x2,y2)` 的完整过程（`src/stroke/stroke.js`）：

| 步骤 | 做什么 | 源码 |
|---|---|---|
| 1 | 沿直线每前进 `spacing` px 打**一个笔尖图章** | `draw()` L365-366 |
| 2 | 图章大小由**压力**决定，沿笔触是一条**高斯鼓包**（峰值位置每条随机） | `gauss()` L537 |
| 3 | 每个图章横向随机偏移 `±scatter×笔宽` | `getImageTipOverscan` L561 |
| 4 | 图章按 `opacity` 叠加，**重叠几次就深几层** | `calculateAlpha()` L553 |

也就是说：**它和"人拿笔在纸上划一道"在结构上是同构的** —— 笔尖轨迹 + 压力 + 手抖。
笔刷参数（weight / scatter / grain / opacity / spacing / pressure）就是"笔的物理属性"，
路径就是"手的动作"。

### 10.2 我错在哪：把路径算得比人精确太多

前几版（S/T/U/V）的代码是：

```js
while (t < mx + 3) {          // 沿法线精确排布
  brush.set('stripe', col, bw);
  brush.line(...);            // 方向固定 ang0 + 微抖
  t += bw + gp;               // 间距精确 = 带宽 + 缝隙
}
```

**位置、方向、粗细、间距全是算出来的** —— 这是机器铺排，不是手。
人涂一块石头只有几个动作：方向随手偏、会压到上一笔上、从纸外起笔。

更隐蔽的一条：`spacing` 我原来设 **0.05**，即每 0.05px 盖一个 9px 图章，
重叠近 200 倍 → 变成**连续实心色块**，蜡笔的颗粒感被彻底抹平。
蜡笔的"蜡感"正来自**图章之间露的缝**。改成 0.3~0.45 才有质地。

### 10.3 更重要的纠正：「96px 硬边界」是错的

§8.2 曾断言"96×48 的小砖装不下可辨笔触"。**这个结论错了。**

判定实验：把生图砖块直接压到 96×48，再放大回来（`_exp/cmp_gen_downscale.png`）。
结果 —— **蜡笔排线依然清清楚楚，std 42.1**。

所以画不出来的原因不是面积，是**频率**：

| | 周期 | 96px 砖上有几条 | 观感 |
|---|---|---|---|
| 生图砖（压到 96px 后） | **2.7px** | 约 35 条 | 蜡笔排线 |
| 我一直画的（Z/S/W） | 8~10px | 3~4 条 | **木纹 / 横纹壁纸** |

**质感来自条纹密度，不是笔触粗细。** 这一条比前面所有参数调整都关键。

### 10.4 按正确频率重画（N 变体）

```
底：mass('crayon', warmize(shade(base,56),0.9), {strength:0.34})  // 亮底
线：hair 笔，周期 2.9~3.8px，线宽 = 周期×0.68~0.90
    颜色 = warmize(shade(base, -4 - 74*rel), 0.75)                // 亮底 + 暗线
    每块砖角度 **±26° 独立随机**                                   // 否则整面墙成斜纹布
```

两条新踩出来的：

| 错法 | 症状 | 正解 |
|---|---|---|
| 暗底 + 亮线 | 斜纹在灰底上**发白**，读成"划痕/斜纹布" | 蜡笔只会把纸**压暗**：先铺亮底，再压暗线 |
| 每块砖角度只抖 ±4° | 8 块砖同一个斜向，铺开是**一匹布** | ±26°：天然石材是不同方向劈开的 |

**当前状态（N 变体，未定版）**：单砖已经能读出蜡笔排线，实拍（`shots/scene_hall_N.png`）
整面墙也不再是斜纹布；但**偏黄偏暗、白点偏多**，还没到能替换 S2 的程度。
瓦片 PNG 也从 275KB 涨到 610KB（高频噪点压缩率低）。

> 结论：P5 **能**复现这个质感，前提是按"生图的真实频率"画，
> 且用"亮底压暗线 + 每块砖独立纹向"。之前判它是硬边界，是我自己的频率错了。

## 11. 定版：整面细笔多遍（GG 变体，2026-11-25）

> 起因：用户否掉三个版本，只给一句判据 ——
> 「**这三个都不对，笔触太宽了，手绘蜡笔是细笔触多次涂抹**」。
> 这一句把前面 §8~§10 的方向整个改掉了。下面是照着做出来的过程与结论。

### 11.1 先量化，别猜

对目标砖（生图砖块压到 96×48）沿纹理法线取一条剖面，实测：

| 量 | 目标砖实测 | 我此前所有版本 |
|---|---|---|
| 暗段（线）宽度 | **1.42px** | 2.0~3.0px（粗一倍） |
| 线间距 | **4.33px** | 3.4~10px 不等 |
| 剖面区间 | 43 ~ 210（差 167） | 差 60~120（对比不足） |
| 整块 mean / std | 144 / 42 | 100~157 / 22~40 |
| RGB 均值 | 156, 142, 120 | 偏冷或偏黄 |

**「笔触太宽」不是主观感受，是可测的 2 倍误差。**

### 11.2 三个连续踩空的错法（都记下来，别再走）

| 变体 | 做法 | 错在哪 |
|---|---|---|
| **P / Q** | 细笔（1.5px）但**通长**（0.5~1.1 倍对角线），6/10 遍 | 线是细了，但每条都拉到底 → 还是**斜纹布** |
| **FA** | 细笔 + **短**（6~18px）+ 随机撒 90 笔 | 太稀（间距 8~12px）→ **砂纸 / 雀斑** |
| **FC** | 细笔 + 短段（10~22px）+ 密排（1.5px 间距）+ 3 遍 | 密度对了，但**逐块画** → 整面墙成**斜纹板补丁** |
| **FG** | 单砖做到量化吻合（线宽 1.4 / 间距 4.3 / RGB 150,141,119） | **单砖完美，整墙灾难** —— 8 块砖各斜涂一遍，铺开就是斜纹布 |

**FG 是最有价值的一次失败**：它证明"单砖对齐目标"不足以保证"整面墙对"。

### 11.3 真正的结构分界：`stone()` 里画 vs 整面画

`tilegen.html` 里每个变体都写在 `stone(x,y,w,h,base)` 内部 —— 也就是**每块砖各涂一遍**。
这是所有"补丁感 / 斜纹布"的共同根因：

```
逐块：石头A 涂一遍 → 石头B 涂一遍 → ...  → 8 块独立的纹理贴在一起
整面：整张瓦片涂一遍（笔触跨缝）→ 最后勾砖缝 → 一面墙
```

真实的手绘墙只涂**一次**。砖缝是涂完之后用暗线勾出来的**结构**，不是涂色的边界。

`EE` 变体（上一轮就有）用的正是整面结构，只是笔触是粗的（3.5~10px × 36~114px）。
**GG = EE 的整面结构 + 细笔短段 + 三遍不同角度。**

### 11.4 定版配方

```js
// 底：wax 铺实。strength 必须 >0.66（三层），否则排线缝里透纸色 → 白点/霉斑
brush.mass('wax', '#9A998F', { strength: 0.74, precision: 0.66 });
brush.rect(0, 0, N, N);

// 三遍细笔短段，跨砖
for (let p = 0; p < 3; p++) {
  const ap = -0.52 + (p - 1) * 0.16;         // 每遍差 9°，叠出交叉
  for (let i = 0; i < 200~260; i++) {
    const a = ap + (rnd() - 0.5) * 0.22;     // 单遍只抖 ±6°
    const len = 10 + rnd() * 18;             // 短段，不是通长
    const col = rnd() < 0.38 ? '#78776F' : P.cold;   // 只有主色 + 暗笔
    brush.set('hair', col, 1.15 + rnd() * 0.55);     // 1.15~1.7px
    brush.line(x0, y0, x0 + cos(a)*len, y0 + sin(a)*len);
  }
}

// 块间明暗：22% 的石头压暗一档（再多就成"棋盘格"）
// 砖缝：seam 2.2px + wiggle(0.30)，双道
// 跨石头的脏：2 条 1.3~2.4px × 6~15px —— 细、短、少
```

### 11.5 三条新的硬教训

| 错法 | 症状 | 正解 |
|---|---|---|
| 底层 `mass` 用 `strength ≤0.66`（两层排线） | 缝里透出纸色 `#E8DCBE` → 满墙**白点/霉斑**（GG1~GG3 都毁在这） | `strength 0.74` 走三层 |
| 细笔再加**比底色亮**的「亮笔」 | 暗底上 1.5px 的亮线 = **雪点** | 蜡笔只会压暗，不要亮笔（§10.4 已记过，又犯一次） |
| 跨石头的脏用 2.5~6.5px × 14~40px | 整面墙上一眼是**棕色补丁** | 1.3~2.4px × 6~15px，且只 2 条 |

### 11.6 结果

| | 现行 S2 | GG |
|---|---|---|
| 单砖 mean / std | 112 / 29 | 108 / 23 |
| 整面观感 | 平灰 + 水渍波浪纹 | 细笔触斜向密布、砖有层次 |
| 实机 | 读成「潮湿水泥墙」 | 读成「手绘石砌墙」 |
| 瓦片 PNG | 90KB | **56KB**（噪点少，压缩率高） |

回归全绿（冒烟 + 控制 + 界面 + 键位 + 定步长 + 存档）。

> **一句话总结**：蜡笔的「细」是 1.4px 的笔尖，「多次」是**整面涂三遍**而不是**每块砖涂一遍**。
> 前者是参数，后者是结构 —— 而结构错了，参数怎么调都救不回来。
