> （各向同性效果、精确几何、运行时粒子）——换任何工具都适用，可以读。
> **不要照它分配任务**。

> 结论先说：**统一用 p5.brush 是对的，但不是"全部都归它画"。**
> 它是**笔触引擎**，负责"材质与做旧"；结构、光、透明叠加归引擎。
> 这不是两套画法，是"画"和"打光"的分工 —— 两者必须分开，否则会互相打架。

## 0. 为什么上一版的分工表是错的

`P5BRUSH.md` §5 曾写"瓦片归 Python，p5.brush 只做贴片"。那张表是**按工具喜好**分的，
判据只有一条"它没有 wrap"。这轮实测推翻了三条：

| 上一版的判断 | 实测结论 |
|---|---|
| "没有 wrap，平铺必然有缝" | **9 重放可以严格无缝**。每次重放前把 `seed()` 和自研 PRNG 都归零，9 份就是同像素平移。单张 192 瓦片 8–12 秒，离线生成完全可接受 |
| "笔触尺度跟画布绑死" | **错。绑的是形状，不是画布。** `mass` 的弧线半径 = `dist(中心, 形状端点)`（`hatch/mass.js:360`），`scaleBrushes()` 只改 weight/scatter/spacing，**管不到半径** |
| "`strength` 不够淡" | 它本来就不是浓度，是**排线密度**。0.2 得到的是"稀疏的全浓度黑线"，永远做不出"薄薄一层" |

第三条的后果最严重：用它做"淡暗部"会得到一把黑毛刷（`shots/wall_new.png` 那版）。

## 1. 真正的问题：`decal_on_wall.png` 里墙为什么最丑

不是配色，是**画法**：

| | 墙（Python 生成） | 贴片（p5.brush） |
|---|---|---|
| 砖缝 | 几何直线，宽度恒定 | — |
| 砖面 | 平涂 + 纸纹针孔（噪点滤镜） | `mass` 弧线，一笔一笔 |
| 边缘 | 精确 90° | 毛糙、有飞屑 |

两套东西贴在一起，读起来是"矢量图 + 蜡笔贴纸"。**换成 p5.brush 之后这一层没了**：
墙、地、平台、贴片现在是同一支笔画出来的（`shots/scene_hall.png`）。

## 2. 背景需求全集 —— 逐项判能不能干

判据只有两条，都是从实测推出来的：

- **判据 A｜最小可画尺寸 ≈ 120px。** `mass` 的弧线半径 = 半对角线，
  元素小于 120px 时一道弧就跨过整个元素，只能落下两三道，读成"毛刷扫过"。
- **判据 B｜只能是"有方向的"。** `mass` 的笔触永远沿形状走，做不出各向同性的东西
  （水渍、雾、均匀渐变）。这类要用 `fill`（水彩），而水彩**必须叠在纸上**，不能透明。

### 2.1 结构层

| 元素 | 尺寸 | 判 | 结论 |
|---|---|---|---|
| 背景墙砖 | 96×48 | ✅ | 192 瓦片，6 变体 + 四向翻转，已接入 |
| 地面石 | 96×48 | ✅ | 192×48 单行瓦片，整条平铺 + clip 到实心格，已接入 |
| 平台石板 | 48×20 | 🟠 | **太小，笔触放不下**。只能做"两遍 hatch + 赭金顶线"，本质是材质色块。已接入，但别指望它有个性 |
| 天花板 / 拱顶 | ≥96 | ✅ | 同墙，换 `par` 层 |
| 柱子 | 建议 ≥128 宽 | 🟠 | **必须把柱子设计宽**。48px 的细柱子用 mass 就是一根糊条 |
| 拱门 | 跨度 ≥192 | ✅ | 形状够大，mass 正好；但拱形轮廓要用 `spline` 描，`arc` 不能填 |
| 门洞 / 窗 | — | ❌ | 需要精确矩形。**框留给程序画**，p5.brush 只画"门板的木纹、窗框的锈" |

### 2.2 远景 / 氛围

| 元素 | 判 | 结论 |
|---|---|---|
| 远塔、远山剪影 | ✅ | `mass` 大块 + 单笔轮廓，是它最强的一项 |
| 雾、尘、均匀渐变 | ❌ | 各向同性，`mass` 做不了（水渍同因失败）。**归引擎**：径向/线性渐变 |
| 天空 | 🟠 | `fill`（水彩）很好看，但必须纸底、不能透明。要做就做成**不透明大瓦片**，不要做叠加层 |
| 暗角 / 光晕 | ❌ | 引擎层。p5.brush 画光晕会得到"一团脏排线" |
| 尘埃粒子 | ❌ | 运行时每帧，p5.brush 是离线渲染器 |

### 2.3 装饰

| 元素 | 判 | 结论 |
|---|---|---|
| 苔藓 | ✅ | 已验证。多而小（16 个 r10~30）才像，少而大会变"橄榄球" |
| 剥落墙皮 | ✅ | 已验证。不规则多边形 + `mass(outline)` |
| 裂缝 | 🟠 | 抠图会滤掉细线，必须画得比"看起来合适"重 1.6 倍。**更好的做法：直接画进瓦片，不做贴片** |
| 水渍 / 渗水 | ❌ | `mass` 各向同性失败。要么 `fill` 画进瓦片（不透明），要么不做 |
| 蛛网 / 藤蔓 | ✅ | `spline` 递归 + `field`，一次成型 |
| 挂画 / 海报 | 🟠 | 框必须精确 → 程序画；画面内容（人像）用 p5.brush |
| 壁灯 / 烛台 | 🟠 | 灯罩形体程序画，光晕引擎画 |
| 钟摆 / 齿轮 | ❌ | 机械件要精确几何。程序画，只让"锈迹、磨损"用 p5.brush |
| 折痕 / 撕裂（钟塔） | 🟠 | `spline` 能做，但它跨整个房间 → 做成**一整张 overlay**，不用瓦片 |

### 2.4 UI

| 元素 | 判 | 结论 |
|---|---|---|
| 面板底纹 | ✅ | 小尺寸贴片，`hatch` 平铺 |
| 血条框 / 按钮边 | ❌ | 要精确像素，程序画 |

## 3. 于是场景设计要改的地方

用户的原话是"我们的故事场景可能都要跟着这个工具的能力去设计"。具体落成四条约束：

1. **石头不小于 96×48，柱子不小于 128 宽。** 小于这个数就只能靠 hatch 涂色，没有笔触。
2. **要精确几何的东西（门框、窗格、齿轮、UI 边框）一律程序画。** 不是妥协 ——
   蜡笔画里的"直的东西"本来也是尺子画的，不是笔刷画的。
3. **各向同性的效果（雾、光晕、水渍、均匀渐变）归引擎图层。** 硬用 p5.brush 会得到脏排线。
4. **需要透明的细节不做贴片，直接画进瓦片。** 贴片必须走"纸底渲染 + 色差抠图"，
   浅色内容会在抠图时被当纸纹滤掉（裂缝因此被迫加粗 1.6 倍）。

## 5. 一句话给以后的自己

**p5.brush 不是画图工具，是笔刷引擎。** 问"它能不能画 X"之前，
先问 X 有多大、是不是各向同性。这两条不过，换工具不如换设计。
