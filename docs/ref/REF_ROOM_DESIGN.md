# 参考拆解：别人的一间房是怎么设计的

> 这份文档不是规范，是**取证**。每条都写清出自哪款游戏、谁说的、具体数字。
> 我们的规范在 `docs/gdd/09_单间房间排布.md`，它从我们自己的六间房反推；
> 那份是「从结果猜标准」，这份才是「看别人做过的决定」。两份冲突时，先改 09。

拆三个问题，各找一个参照：

| 问题 | 参照 | 因为 |
| --- | --- | --- |
| 一间房**怎么被造出来**（流程与硬约束） | Hollow Knight | Team Cherry 公开讲过流程与数值 |
| 一间房**靠什么被记住** | SOTN / 晓月圆舞曲 | 同一套单屏房间语法，做了二十年 |
| 一间房**靠什么不空** | Blasphemous | 背景巨构 + 前景剪影，最极端的做法 |

## 1. Hollow Knight：先做空间，再谈美术

Team Cherry 在 GDC 访谈里讲过一间房的诞生顺序（机核译文《百万销量的〈空洞骑士〉，地图是怎么设计出来的？》）：

```
64×64 黑方块铺满 → 块化出房间轮廓 → 直接按 Play 跑跳，验证能不能跳上去
→ 再去「装扮」（放景物） → 最后放敌人 / 交互物
```

原话（Gibson）：

> 整个世界一开始全部都由 64×64 的黑色小方块构成的。……有了这个，我们就可以按下 Play，
> 开始做大量的测试，从而对游戏空间大小找感觉。

以及两条硬约束：

> 一个房间再小，也不能低于 **20 个瓦片的高度**。（98% 的情况如此）

20 × 64 = **1280px**，而他们的屏幕高 720 —— 房间普遍比一屏高，镜头要移动。

**对我们的意思（这一条是反的）**：我们是先出地面美术图（96/384/96 × 144），再往场景里塞。
顺序倒过来了。结果是美术决定了空间，而不是空间决定美术 —— 所以「该多满」永远算不出来。

## 2. Hollow Knight：三层的对比度预算是分配好的

环境固定拆三层，**每层有自己的活**（Medium《The Art of Hollow Knight》）：

| 层 | 职责 | 处理 | 占比 |
| --- | --- | --- | --- |
| 背景 | 承载「这是哪儿」，并**预告危险** | 低饱和、低对比、多层视差 | 最大面积 |
| 中景 | 玩法层（角色/敌人/平台） | **对比最强、描边更厚**；角色与敌人比环境亮 | 中等 |
| 前景 | 框景、纵深 | **近黑剪影**（飞虫、钟乳石），比相机快 | 少量 |

背景预告危险的具体做法：

> 遗忘十字路有一种叫 Goam 的敌人会从地里钻出来。**这些生物也画在背景里**，
> 帮玩家预先知道危险要来。尖刺也先出现在前景和背景，玩家才在中景真正面对它。

层数与视差（多个 2D 环境设计资料的共识值，HK 取上限）：

| 层 | 视差系数 |
| --- | --- |
| 天空 | 0.05 |
| 远山 | 0.15 |
| 中景丘陵 | 0.40 |
| 近处道具 | 0.75 |
| **玩法层** | **1.00** |
| 前景装饰 | **1.25**（比相机快，"我正在经过它"） |

饱和度梯度：天空/远景 20–30%，远山 40–60%，中景丘陵 60–80%，前景与玩法层 80–100%。

**留白的正确含义**（同一个来源）：

> 画面里应有 **30–50% 是视觉安静的**（天空、简单地形、纯渐变）。

注意括号里那三个东西 —— **安静的是「画好的天空」，不是「没画」**。
我们六间房 76% 是空白纸色，看着比 HK 的 30–50% 空得多，原因不是数字，
是 HK 那 30–50% 里有渐变、有远山剪影、有雾；我们的那 76% 里什么都没有。

## 3. SOTN / 晓月：房间靠一个「背景事件」被记住

SOTN 里几乎每个房间都有自己的一处小机关，而且**多数不在玩法层**：

- 逆城某处，一只**巨大的眼睛**在背景里看着你跑过
- 外壁：满屏的雾，墙边挂着一个稻草人
- 地下墓穴：背景是一整面**流动的冰**

> all of Castlevania's different rooms are each unique with their own little twists and quirks

而且每个房间有自己的曲子 —— 记忆点是**视听事件**，不是堆物件。

晓月（Aria of Sorrow）是 GBA，屏幕 240×160，一间房就是一个屏。它的房间语法是
**封闭盒子**：砖墙铺满整个背板，地板、天花、侧墙都画出来。第三方描述：

> Stone brick walls form the backdrop … A teal-colored floor platform runs horizontally
> across the lower portion of the screen.

宏观上晓月用「中央枢纽 + 分区」把房间串起来（`danielprimed` 的拆解），
枢纽房间因为反复经过，天然成为空间记忆的锚点。

**对我们的意思**：我们的房间是**开放平台** —— 没有天花、没有侧墙、没有背墙。
不是「墙画得少」，是**根本没有墙这个层**。所以「空」不是密度问题。

## 4. Blasphemous：不靠物件密度，靠背景巨构

玩家评论里被反复提到的一处：

> 背景是一整座夕阳照射的大教堂，前景则是只有剪影的自己，看起来格外诗意。

它的房间可以几乎没有可交互物件，也不空 —— 因为**背景是一个「巨构」**，
前景是纯剪影，中间留给角色。物件密度接近零，信息量却满。

这也解释了它为什么能做得那么「宗教」：巨构承载叙事（塞维利亚哥特、彩窗、雕像），
小物件只是点缀。

## 5. 三方对照

| | 层数 | 背景承担什么 | 记忆点靠什么 | 留白怎么处理 |
| --- | --- | --- | --- | --- |
| Hollow Knight | 5–7 | 预告危险 + 区域身份 | 手工摆的遭遇 + 背景事件 | 画好的远山/雾，30–50% |
| SOTN / 晓月 | 2（背板 + 玩法层），靠背板图案做「层」 | 房间身份（砖墙/彩窗/冰面） | 每房一个背景小演出 | 几乎不留白：封闭盒子铺满 |
| Blasphemous | 2–3 | 巨构 + 叙事 | 巨构本身 | 靠剪影对比，而不是留白 |
| **我们（现在）** | **1（玩法层）** | **无** | **通用石构件拼的占位** | **76% 空白纸色** |

## 6. 对照我们六间房：结论不是「物件太少」

实测（`tools/ref/room_layout.py --gaps`）：六间房平均非空 **24.0%**，空 **76.0%**；
3 间在 y<420 零元素。房间没有 `Camera2D`，视口 1280×720，房间正好一屏 —— **镜头固定**。

四条判断，都能验：

1. **背景层数 = 0。** 六个房间的节点只有：`TileMapLayer`（地面）、`Sprite2D`（草皮/摆件）、
   `ColorRect`（后处理遮罩）。没有任何一张图在扮演「背板」。所谓背景就是纸色 + 纸纹 shader。
   → 76% 空，空的是**没画的地方**，不是「留白」。
2. **镜头固定 ⇒ 背景必须自己撑住。** HK 靠镜头移动不断揭示新景物；我们一屏到底，
   玩家从头到尾盯着同一块背景。这块背景要么有内容，要么就是白墙。
3. **开放平台 vs 封闭盒子。** 晓月一间房是盒子，背板铺满，天然不空；
   我们是悬浮在纸上的平台，缺的不是摆件，是「这间房在哪儿」。
4. **地标是占位，不是地标。** 风车 = 石柱 + 星星 ×3；灯塔/书堆 = 石块 ×3。
   这一条 09 已经写了，但当时的结论是「要专用图」—— 顺序错了：
   在背景层是 0 的情况下，专用地标图放上去也只是「白墙前摆一个精致物件」。

**所以第一件该做的事不是加摆件，是加背板。**

## 7. 能直接用 / 不能照搬

**能直接用（有出处，且不依赖体量）**

| 做法 | 出处 | 我们的落点 |
| --- | --- | --- |
| 三层分工 + 对比度预算（中景最强，前景纯剪影） | HK | 背板定稿后立刻适用 |
| 背景预告危险（敌人先出现在背景里） | HK | 侵占房间可用 |
| 前景剪影框景，比相机快 | HK / Blasphemous | 单屏固定镜头下，前景只能做静态框 |
| 每房一个背景小演出 | SOTN | 替代「堆一个大地标」 |
| 留白 = 画好的安静区，不是空白 | HK | 直接否掉「空着就空着」 |

**不能照搬（体量/结构不同）**

| 做法 | 为什么不行 |
| --- | --- |
| 5–7 层视差 | 镜头固定，视差没有意义；我们只能做「静态分层」 |
| 房间不低于 20 瓦片高（1280px） | 我们单屏 720，房间不是可滚动空间 |
| 64×64 黑方块先块化 | 地面资产已成，重走一遍成本大于收益；但「先验空间再装扮」的顺序要学 |
