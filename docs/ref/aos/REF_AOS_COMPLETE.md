## 1. 一句话

《晓月》的完整结构是：**一条 99 级的平滑数值底座 + 13 个按角色分工的区域 + 6 个全部由「非 BOSS」
提供的能力门 + 120 个按成本分层的魂**。四层各自独立，串起来才是那个「越玩越自由」的手感。

对我们最有用的一句：**它的难度靠「HP 台阶」和「等级要求」堆，不靠敌人机制复杂度。**
109 个敌人里绝大多数只有 1–2 种攻击。这一点和「动作手感第一、敌人少而精」是两条路，
必须自觉选一条，不能混着抄。

## 3. 七条要紧的结构性判断

### 3.1 等级是底座，不是战力来源

`HP = 320 + 12×(L−1)`，L1 到 L99 只涨 **4.7 倍**。而武器 ATT +1→+120、防具 DEF +5→+49、
魂威力 16→285。

**结论：升级让你「活得久一点」，装备和魂才让你「打得动」。** 这不是缺陷，是刻意的 ——
它保证玩家无论等级多少，都能靠换装备/换魂应对新区域，不会被等级墙硬卡（除了计时塔那一次）。

还有一条更值得记：**它的等级成长曲线没有指数段。** HP 和 LCK 是纯直线，STR/CON 是五段折线，
但整条线归一化后几乎看不出弯。也就是说《晓月》从来没有「升级越来越快」这种爽感设计，
它的爽感全部来自「换了一件装备，战力突然跳一档」。这是**两种完全不同的成长叙事**，
我们只能选一种。

对我们的意义：想让「技术」比「刷」重要，就压低等级涨幅，把成长感放到可替换的装备/技能上；
想要明确的成长反馈，就得让等级涨幅可见地大。**这是一个必须先选边的决定，不能两头都要。**

### 3.2 敌人的强度是 HP 台阶，不是机制台阶

109 个敌人里，绝大多数只有「走近撞你」和「吐一个弹」两种行为。真正的差异在 HP：
1 → 25 → 100 → 300 → 1000 → 5000 → 9999。

经验效率（EXP/HP）从 **0.05 到 30，差 200 倍**：

| 敌人 | HP | EXP | 效率 |
|---|---|---|---|
| 天空鱼 | 100 | 3000 | **30.00** |
| 针（Needles） | **1** | 10 | 10.00 |
| 石像鬼 | 70 | 240 | 3.43 |
| 铁巨人 | **9999** | 500 | **0.05** |

**HP 1 的针一招秒给 10 点；HP 9999 的铁巨人打半天给 500 点。** 它的经验分配不是
「越难给越多」，而是「按区域定位给」：早期怪给得少但好打，后期怪给得多但你得先能活下来。

对我们的意义：我们只有两档五敌。照这个思路，就该让「同档敌人在不同区域有不同的 HP 倍率」，
而不是「每区换一套新敌人」。前者复用资产，后者烧美术。

### 3.3 能力门只占 5%，而且 BOSS 一个都不掉门

6 个银魂 = 120 个魂的 5%。更关键的是：**11 个强制 BOSS 里，没有一个掉能力门。**

掉门的是三种来源：
- 固定拾取（守墓者、骷髅烈焰、玛尔法斯、骏鹰）—— 4 个
- 普通敌人掉落（踢腿骷髅）—— 1 个
- 进房即得（加拉莫斯）—— 1 个

**为什么这条重要**：如果 BOSS 掉门，玩家会卡在「打不过 → 过不去 → 更打不过」的死循环里没有出路。
把门放在「走过去就能拿」的地方，等于保证「卡住的人至少能靠探索变强」。

对我们的意义：我们的两个门（折叠锁高度、生长锁距离）也必须遵守 —— **门不能放在需要打赢
某个强敌才能拿的位置**。这是设计红线，不是偏好。

### 3.4 13 个区域是四种角色，不是十三个关卡

| 角色 | 区域 | 共同点 |
|---|---|---|
| **枢纽** | 荒城回廊、地下水域 | 有传送点，连通 3–4 个方向，玩家反复回来 |
| **门区** | 藏书库、舞踏馆、居所、地下墓地 | 每个区产出 1 个能力门，进门和出门的门不同 |
| **战斗区** | 计时塔、斗技场 | 没有门，只有强度台阶；斗技场给全游戏最强一档装备 |
| **可选区** | 禁忌区域、混沌领域 | 不去也能通关，去了战力翻倍或看到真结局 |

**只有 2 个枢纽**，都在地图中段偏下。这个比例值得记：13 个区里 2 个枢纽（15%），
剩下 11 个都是一次性推进区。枢纽太少会让玩家迷路，太多会让地图失去方向感。

对我们的意义：我们的 6 区 48 房，该有 **1 个枢纽**（根系入口）+ 5 个推进区。
现在 `04 关卡与地图` 的根系算不算枢纽，要单独确认 —— 它连通几路、有没有传送点，是判据。

### 3.5 用装备栏做叙事选择，成本几乎为零

击败格拉罕时，身上带的三个魂决定结局：
- 火焰恶魔（红）+ 巨蝙蝠（蓝）+ 魅魔（黄）→ 开混沌领域 → Best Ending
- 否则 → Bad Ending

三个魂都是本来就会拿到的，判定只是一个「if 三件都在身上」。**没有新美术、没有新关卡、
没有新对话**，却让玩家在最后一战前必须做一次真正的取舍（带这三个，就得放弃另外三个的输出/生存）。

对我们的意义：这是最便宜的深度来源。要多结局，优先考虑「用已有技能的组合做判定」，
而不是「做三条不同的剧情线」。

### 3.6 BOSS 的复杂度来自「你打哪里」，不来自「它有几招」

11 个 BOSS，招式数：**2 / 2 / 2 / 2 / 3 / 3 / 2 / 3 / 5 / 2 / 6**，中位数 2。
前七个里有六个只有 2–3 招。**没有一个中期 BOSS 靠「招式多」撑难度。**

那它们的差别在哪？在受击面。11 个里有 8 个的受击面不是「全身一个判定」：

| BOSS | 受击面 | 玩家要学会的事 |
|---|---|---|
| 大装甲 | 盾挡正面 | 正面无效，要等它先挥、抓硬直 |
| 大巨人 | 手臂打不掉血 | 你最先想打的地方是错的 |
| 猎头者 | 三种形态 = 三种距离 | 换形态是逼你换站位，不是加招式 |
| 死人军团 | 壳 + 核 | 血条不止一条，先破壳 |
| **巴洛尔** | **身体不伤人，只有拳头伤人；拳头又打不掉血** | **最安全的位置在最危险的拳头正下方** |
| 格拉罕 | 头 4000 / 双手各 2000 / 躯干 2000，**只有躯干必死** | 目标选择：全都打 = 拖长战斗 |
| 混沌 | 形态一头颅打不到只能打球；形态二核心必死、四角眼纯干扰 | 把前面所有课合起来考 |
| 尤里乌斯 | 血降到阈值就结束 | 血条清零不是唯一结束条件 |

**巴洛尔那一行是全作最漂亮的一处**：威胁源（拳头）和受击点（身体）是两个东西，
而且互不重叠。玩家的直觉是「离危险远一点」，这个 BOSS 反过来 —— 最安全的位置
在被砸下来的拳头正下方。**一个几何关系就把玩家练了一路的直觉推翻了，没加一招一式。**

对我们的意义（也是回你的问题）：你说「BOSS 不可能单一技能单一行为」，对，但
「多行为」不一定等于「多招式」。**给 BOSS 加第二招，玩家多躲一次；给 BOSS 换受击面，
玩家要重新想「打哪里、站哪里」。** 后者更省美术、更省帧、更难被跳过。

我们有两个位移技能（折叠、生长），天然适合做「站位类」BOSS —— 这是《晓月》没有的牌。
反过来要注意它的坑：受击面必须给**确定性提示**（前摇、颜色、位置），否则从「学」变成「猜」。
AoS 每个部位都有明确的视觉区分（红眼的手、发亮的核、盖着壳的球），这是它能成立的前提。

### 3.7 伤害公式：物理伤害不吃 STR

完整公式已拿到（上一轮这里是空的），关键三条：

```
武器/徒手：  Power = ATK
红魂：       Power = (STR + 60) / 160 × AP
蓝魂：       Power = (Soul AP rate × INT) + Soul AP
对敌伤害：   Damage = (Power − Enemy DEF/2) × (256 − Enemy DEF) / 256   （最低 1）
受敌伤害：   Damage = 2 × Power − DEF                                   （普通模式）
```

**`Power = ATK` 这一条是整个数值体系的枢纽。** 面板 ATT = STR + 武器加成
（实测：LV50 STR 132 + 克莱姆·索拉斯 99 = 231，与攻略记的 ATT 231 对上），
所以物理伤害确实随等级涨 —— 但那是因为等级涨 STR，而 STR 是通过「面板 ATT」间接进去的，
不是直接参与。真正直接的杠杆是**武器 ATK**：1 → 130。

再看对敌伤害那条：先减掉一半 DEF，再乘 `(256−DEF)/256`。**对付高防敌人，ATK 每一点的
边际收益反而更大** —— 这是双惩罚，不是简单相减。而受击公式 `2×Power − DEF` 是纯减法，
所以 DEF 一旦接近 2×Power，伤害归零：**堆防在 AoS 里异常有效**。

对我们的意义：我们没有等级，也没有 DEF 面板。要抄的是「两种公式形状」：
- 对敌用**乘法折扣**（高防敌人吃装备，逼玩家换武器）
- 受击用**减法阈值**（防御类能力一旦堆起来是质变，不是量变）
这两条正好对应我们缺的两个战斗角色（防御、放置）。

### 3.8 城堡实际有多大：1210.8 屏，约 650 间

这一节是本轮唯一「自己动手量」的部分。上一轮把它列成「拿不到」，因为网上没人统计过
《晓月》的房间数。查清之后发现**它根本没有房间口径** —— 游戏只认地图格：

> 「一个地图格只有索玛走进它那 256×256 px 的屏幕时才会点亮，所以要走到房间里每一个
> 没点亮的格才算走完。」—— pixelguides「100% 地图」通篇记录（map-completion 页）

房间是玩家语感，格数才是游戏的单位（RATE = 点亮格 / 总格）。而房间大小在 1–4 屏之间浮动，
跨游戏硬比房间数，会把「大小不同」误读成「数量不同」。所以我量的是**面积当量（屏）**。

**两条独立测量互相印证：**

| 测法 | 做法 | 结果 |
|---|---|---|
| A · 逐区 | 13 张区域渲染图，各自量可走像素 ÷ 38400 | **1210.8 屏** |
| B · 整图 | 全城堡整图（另一份拼接）同样口径 | **1134.1 屏** |

两条差 2.6%。A、B 用的是同一作者的同一套素材，但拼接方式、缩放比例都不同，
所以这个吻合能证明「比例换算没错、背景判定没错」两件事。

**再往下换一个口径也对得上：** 1210.8 屏 × 38400 ÷ 65536 = **709.5 格**（13 区）；
去掉不进 RATE 的混沌领域是 **647 格**。而 pixelguides 记了一处关键实测 ——
RATE 从 70.6% 走到 71.2% 正好是「四个未探索房间点亮」：

```
0.6% ÷ 4 间 = 0.15%/间  →  总格数 = 100 ÷ 0.15 ≈ 667
```

667 与实算的 647 差 3%。**两个数从两条完全不同的路走到一起，所以「1 间房 ≈ 1 格」成立**，
房间量级 ≈ 650 间（误差 ±5%，是推断，不是官方口径）。

**对我们的意义（这条最要紧）：**

| | 《晓月》 | 我们 | 差 |
|---|---|---|---|
| 房间数 | ≈650 | 48 | **1/13** |
| 面积（屏） | 1210.8 | 48（每房恰好一屏 20×11.25 格） | **1/25** |
| 面积（16px 瓦片） | ≈181,600 | 10,800 | **1/17** |

换个说法更直观：**《晓月》单区面积的中位数是 83.3 屏，最大的地下水域 204 屏。
我们整座城堡（48 房）还不到它的一个中等区域。** 这不是错，因为两者结构不同 ——
它是「13 个区串起来的一次探索」，我们是「据点 + 关卡推进」。但它否掉了一个危险的假设：
**48 房撑不起 10 小时的探索时长。** 要么把关卡做成「复用同一批房间的不同组合」，
要么接受主线时长短、把时间放到经营循环里。

还有一条：13 区的填充率从 25%（荒城回廊）到 74%（地下墓地）差 3 倍。
**《晓月》的区不是方块，是「长廊套着房间」** —— 荒城回廊外接 45×14 屏，实际只填了 25%。
我们的根系用的是 L 形折返廊，思路是同一个：**用走廊把房间串长，而不是把房间堆大**。

## 4. 可抄 / 不可抄 / 抄了会炸

| 项 | 判断 | 理由 |
|---|---|---|
| 四层成本模型（按次/按秒/免费/永久） | ✅ **抄** | 判据是「怎么收费」，玩家不用记属性，只记「扣不扣蓝」 |
| 能力门零消耗 | ✅ **抄** | 位移收费会把玩家卡死在坑里，这不是难度是坏档 |
| 掉落优先级 Soul > Item > Gold | ✅ **抄** | 一行规则解决「刷魂顺带攒装备」的数值膨胀 |
| 三魂定结局 | ✅ **抄** | 见 §3.5，成本几近于零 |
| Boss Rush 重编排 | ○ **可抄，但要有余量** | 零新增内容换重复游玩量，前提是 BOSS 本身够耐打 |
| HP 台阶式难度 | ○ **看路线** | 我们要「动作手感第一」，纯 HP 台阶会变成搓血条 |
| 109 个敌人各 1–2 招 | ❌ **不抄** | 核心卖点是手感，敌人必须有可读的前摇与破绽 |
| 99 级 + 300 万经验 | ❌ **不抄** | 那是给「刷」留的空间；我们的循环是种植/经营，不该有第二套刷子 |
| 13 区 × 各自敌人池 | ❌ **不抄** | 美术成本是它的 20 倍（GBA 像素 vs 手绘帧动画） |

先问清那是哪套编号 —— 按 StrategyWiki 它是 83 号。

### 6.2 1–99 级逐级表不可信

pixelguides 的经验表有三处硬伤：
- L14 INT 27 → L15 INT 25（属性不该回落）
- L44 CON 84 → L45 CON 93（单级 +9，不在任何分段里）
- L67 MaxHP 写成 112（应为 1112，掉了首位）

**处理**：不做逐级验证。改用「分段规则（GameFAQs 文字）+ 从 L1 累加到 L99 命中端点 + 五个自洽点」
三重交叉。所以本库给的是**公式和检查点**，不是逐级表。需要逐级数字的地方，宁可空着。

> 顺带记一个自己踩的坑：第一次把段定义写成「累加到 level 为止」，
> 结果每一级都差 1 —— 因为 L1 是起点本身，不该再 +1。段必须从 2 开始。
> 这类差 1 的错误，靠肉眼看表是查不出来的，只有回代才能抓到。

### 6.3 格拉罕的 HP 有四个数，尤里乌斯的差一位

格拉罕：
- pixelguides 敌人表：**500**
- pixelguides 实战：形态一 1500、形态二躯干 2000
- rpgdl 论坛实测：1250 / 1250 / 2500
- rpgdl 汇总说法：5000

四个数说的不是一件事（单形态显示值 / 两形态 / 三形态 / 总血）。**不裁决**，
数据层填 500 并在 `hp_note` 写明其余三个。

尤里乌斯则是纯粹的错：敌人表 **600**，实战 **6000**。判 6000（曲线上的位置不支持 600），
理由见 §7.1。**这类「差整整一位」在敌人表里不是孤例**（源站 L67 的 HP 被写成 112），
所以看到可疑数值先怀疑位数，别怀疑来源。

### 6.4 地下墓地的敌人池是空的（口径问题，不是漏抓）

源敌人表把地下墓地的敌人并进了「地下水域」（Legion / Flame Demon / Biphron 在 Fandom 都记在 Cemetery）。
所以 `area_pool.underground_cemetery` 为空。已在 `aos_areas.json` 用 `enemy_data_gap` 写明，
构建器也认这个字段 —— **不为了让测试变绿去补一个假敌人**。

### 6.5 加拉莫斯不在敌人表里

它是 6 个能力门的提供者，但 pixelguides 的敌人表没有这一条（只在魂表里有）。
本库把它记在 `aos_bosses.json` 的 `elites`，构建器允许「BOSS 名在魂表里也算找到」。

### 6.6 哪些是推断

| 内容 | 性质 |
|---|---|
| 区域 `role`（枢纽/门区/战斗区/可选区） | **我的归纳**，不是官方分类 |
| BOSS 的 `role`（「它在这条流程里干什么」） | **我的归纳** |
| BOSS 的受击面分类（九种类型） | **我的归纳**，但每个分类都指向可核实的实战描述 |
| 「普通敌人只有 1–2 种攻击」 | 仍是概括，**没有逐个敌人统计**（BOSS 已逐个统计，见附 E） |
| 区域连通关系 | 来自 StrategyWiki 区域页与 pixelguides 流程，可信 |
| 每区面积（屏 / 格） | **实测**，不是推断。两条独立测量互证，见 §3.8 |
| 房间量级 ≈650 间 | **推断**。依据「1 间 ≈ 1 格」，两边总数差 3%，不是官方口径 |

### 6.7 经验表：网页能读到，但数字被压成一串

pixelguides 的经验页有完整的 99 行表，但转成文本后列边界丢失：
L99 那行被抽成 `993019500894961496135019885198170165107`。它能读，
是因为**我们已知 L99 应该是「总经验 3019500 / 本级 89496 / HP 1496 / MP 1350 / ATT 198 / DEF 85 /
STR 198 / CON 170 / INT 165 / LCK 107」**，对着已知值往回切才对得上。
其余 98 行没有这个便利，切分必然出错。

**处理**：只取 L99 一行做端点验证，不写逐级表。这比「大概猜着切开」诚实。

### 7.1 顺带确认的两件事

**① 那条 EXP 公式不属于《晓月》。** Fandom 写的
`EXP = floor(0.3L⁴ + 1.8L³ + 3.3L² + 0.6(L−1)² + 184.8L − 0.6)`
回代 L=99 得 30,620,818，而实测总经验是 3,019,500 —— 差 10.1 倍。
用 L=2 验：公式给 402，实测 84。**差的不是一位数，是整条曲线都不对。** 该公式属于系列里别的作品
（页面把多作公式混排在一处）。不采用。

**② 尤里乌斯的 600 → 6000 是掉位，不是两个数。** 敌人表写 600，攻略实战说 6000。
判 6000：它是全场倒数第二个 BOSS，前一个有 4000，后面还有 5000。600 比第 5 个（700）还低，
在曲线上是凹的。这类「差整整一位」的错误在敌人表里还有一处（源站 L67 的 HP 被写成 112），
所以不当作孤例。
