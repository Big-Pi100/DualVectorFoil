## 2 必须先说清：277 个里只有 27 个有代码

这是本轮最重要的一条，先说它，因为后面所有「介绍」都受它影响。

```

templates/games/*/index.html  →  27 个
差额                          → 250 个只有「标题 + 封面 + 中英文案」
```

我验证过三种可能，全部排除：

| 猜测 | 验证方式 | 结果 |
|---|---|---|
| Git LFS 没拉下来 | 读 `cover.webp` 文件头，是 `RIFF…WEBP` 真实图片 | ✗ 排除，clone 是完整的 |

## 4 官方 genre 为什么不能直接用

6 个值装 277 个玩法，必然错。举证 6 个：

| 模板 | 官方 genre | 实际机制 | 错在哪 |
|---|---|---|---|
| `plants-vs-zombies` | shooter | 塔防：种植物挡波次 | 没有「射击」这个动作，是布置防线 |
| `haunted-dorm-clash` | **horror** | 塔防：造炮塔挡鬼 | 恐怖只是美术皮 |

| `judge-idiom-court` | **story** | 成语拼图 | 叙事被当成文字解谜 |

## 7 那 27 个有代码的：结构是什么样

抽三个读了一遍，结论一致——**单文件、无构建、关卡硬编码**。

| 模板 | 体积 | 结构 |
|---|---|---|
| `skyline-courier` | 18.1 KB / 48 行 | 全部逻辑手写：`fit / tone / wake / burst / setState / begin / end / pause / resume / frame`。关卡是 `parcels=[{x:967,y:385,got:false},{x:1825,y:275},{x:3115,y:360}]` —— **三个写死的坐标** |
| `last-light` | 18.0 KB / 50 行 | 同上量级的单文件，三把钥匙 + 火把衰减 |
| `pin-rescue` | 14.3 KB | 5 关拔针，关卡数据内联在代码里，无外部数据文件 |

**这个形态决定了三件事**：

1. **换一关要改代码**，不能改数据。所以它们只做 3~5 关（`four stages` / `five puzzles` / `three timed stages` / `ten waves`）。
2. **没有「房间」这个单位**。全库没有一个模板有房间图、房间连接、房间模板。
3. **没有种子**。277 个里 `seed` 出现 0 次，关卡是死数据。

对照我们的做法：`level_01.graph`（图）+ `blueprints/*.txt`（零件）+ `gen_level.py`（拼装）+ `level_01.layout.json`（输出）+ `seed`。**我们的关卡层比这个仓库高一个代际**——它的模板连「关卡是数据」这一步都还没到。

## 8 与我们项目的关系

### 8.1 直接可用的：0 个

我们的痛点是「一间房的可玩性」。全库 277 个模板里，**有「房间」概念的：0 个**。有「固定关卡」的只有 8 个（6.9 关卡平台），其中：

| 模板 | 为什么不算 |
|---|---|
| `duke-duck-quest` / `tiny-hero-quest` / `squirrel-brawl-2d` | 单线横版闯关，从左跑到右，无分叉、无房间 |
| `gunner-rooster-run` | 横版射击，同上 |
| `fire-water-duo` | 双人协作解谜，是「一屏一谜题」不是「一间房」 |
| `magic-tower-rpg` | **唯一有钥匙-门-楼层结构的**，但它是网格 RPG 不是平台跳跃 |
| `skyline-courier` | 3D 屋顶，90 秒送 3 个包裹，是「限时目标」不是「房间探索」 |
| `kazehane` | 3D 自由滑翔，无失败条件，是氛围体验 |

### 8.2 值得借的一条：`magic-tower-rpg` 的锁钥结构

它是全库唯一实现了「彩色钥匙 → 对应颜色的门 → 多层楼递进」的。这跟我们上一轮讨论的**锁钥图可达性**是同一个数学问题（拿到钥匙前，某些区域不可达）。
差别在于：它把可达性做成了**数值门槛**（攻击力够不够打这只怪），我们做成了**空间门槛**（跳得够不够高）。前者可以用公式验，后者必须跑机器人验。所以它对我们只有**概念参考**，没有算法可抄。

### 8.3 值得借的第二条：三层平衡模拟的缺失

这个仓库的 `openmotion_game_simulate` 跑三层基线（reference win / weak / idle loss）。它的 277 个模板本身**没有体现这一点**（都是固定难度），但它的验证思路可以用在我们的 L9：强 bot 稳过、弱 bot 险过、挂机 bot 必须失败。

### 8.4 反向价值：它证明了什么

这个仓库一周产出 277 条游戏目录、27 个可运行单文件，靠的是**绕开关卡设计**——每个游戏只做 3~5 关，靠换皮和题材差异堆量。
这条路我们走不了。DC 类产品的最小可玩单位是「一局 12 间房」，绕不开房间设计。所以：**它的量产能力不能迁移，它的验证闭环（五步质检）可以迁移。**
