# 参考拆解：Dead Cells 的一间房内部是怎么设计的

> 这份文档回答一个问题：**Dead Cells 的房间为什么"有东西可做"，而我做的没有。**
> 前两份参考（`REF_DEADCELLS.md` 讲操作 HUD、`REF_ROOM_DESIGN.md` 讲"空"）都没碰这一层。
>
> 写法：先给证据（谁说的、原话），再给可执行规则，最后给"我们该怎么改"。
> 凡是推断，标「推断」。

---

## 0. 一句话结论

**Dead Cells 的房间是战斗场，不是跑酷题。**

它的空间复杂度全部服务于"怎么打"，不服务于"怎么过"。
玩家在房间里 90% 的时间在打，10% 在走位；而我的房间 100% 在跳，0% 在打。

这一条错了，后面所有优化都是在错的方向上加速。

---

## 0.5 ⚠️ 2026-11-27 第二次修正：房间必须**拒绝**玩家

§0 是对的（战斗为主），但我把它读成了"空间要简单"。按 §0 做出的那间房
（3 层 + 3 块长台 + 平地面 + 出口 1 跳）被白哥一句话否掉：

> 「地形全用几何就行了。问题是你现在设计的房间还是没有可玩性……
> 你这房间太简单了，没有任何迷宫解密的乐趣，完全是个垃圾」

**"战斗为主"不等于"空间要简单"。** 我漏掉的是 Dead Cells 每个房间都有的一件事：
**一个不让你过的地方。**

### 证据：机关门（Switch Door）

被囚者的牢房**必定**包含一个机关门，三个独立攻略源的描述完全一致：

> 牢房中必定会包含一个位于通往有罪者大道必经之路的机关门。此门**无法被打破**，
> 会在门上方生成一个拥有 **3~4 层平台**的独立长方形房间（图中的平台就是入口），
> 房间有怪物并且与**其他房间互不相连**，最顶层处有**一个开关**，
> 按下后即可开启机关门。

来源：
- <https://www.7xz.com/dzjj/460302.html>
- <https://www.18183.com/zqnews/202201/3783671.html>
- <https://playgame.wiki/deadcells/gonglue/20bea9ec9b>

配图（已下载核对）：`/tmp/dc1.jpg` 是那扇门的实机截图 —— 一扇竖到顶的
蓝光铁栅，玩家站在门前，门后就是通路。

沉睡的庇护所是同一个模式放大到整张图：内区尽头是「庇护所激活开关」，
按下才开黄色门，两个外区才通。**"先解，再走"** 是这张图的骨架。

### 由此得到的规则

> **房间 = 一个必须解决的问题 + 解决它的空间 + 解决过程中的战斗。**

"难度"不来自跳跃数量，来自**"我看得到出口，但我过不去"**。
上一版我把这条删掉了（`max_jump_to_exit≤1`、删 `min_alternate_stands`），
于是房间变成"从左边走到右边，顺便打几只怪" —— 那不是房间，那是走廊加了怪。

### 机关门房间的解剖（照着摆）

| 元素 | 规格 | 为什么 |
|---|---|---|
| 门 | **满高**，从地面顶到天花板 | 矮一格就会被跳过，谜题立刻失效 |
| 门的位置 | 卡在必经之路上 | 不挡路 = 布景 |
| 竖井 | 门的上方 / 旁边，**3~4 层平台** | 爬的过程就是解题过程 |
| 上升路线 | 斜向阶梯（左右交错），不是直梯 | 直梯是"按三下跳"，斜梯要走位 |
| 开关 | **最顶层**，一次交互 | 位置越高，"要爬上去"越成立 |
| 下来 | 门开后从门洞**掉下去** | 上去和下来不是同一条路，房间才有立体感 |
| 支线 | 至少一条**死路**（只放奖励/观景） | 证明"这里可以不去"，才有选择 |
| 敌人 | 铺在竖井各层 | 爬的过程要打，不是空手做操 |

### 判据必须跟着改（第三次反转）

前两版判据分别是"要求多"和"要求少"，都错。正确的判据不是数几何，而是**证明因果**：

| 判据 | 抓什么 |
|---|---|
| 门关着时，开关**够得着** | 否则房间无解，玩家被卡死 |
| 门关着时，出口**到不了** | 否则门是布景 |
| 门开着时，出口**到得了** | 否则扳了也白搭 |
| 至少 1 块平台**可以不去** | 否则只有一条路，还是一根梯子 |

前三条是 `_check_mechanisms`，"可以不去"是 `min_optional_platforms`。
四条都能被反向验证打红 —— 见 `docs/gdd/12 §9.6`。

## 1. 三条硬证据

### 1.1 GDC 2019《Dead Cells: What the F\*n!?》—— Sebastien Bénard

> "But Dead Cells is really combat oriented. **Platforming is just a [means] to move,
> to avoid enemies, to position yourself**, and it's not a hardcore platformer game.
> So, when we asked this question, it was really useful... **'Is the player meant to die
> doing this?' If the answer is no, we just make sure the player succeeds.**"

同一篇里还提到 "just in time" 跳跃：玩家脚已经离台了，游戏仍留几帧允许起跳 ——
因为**平台失误不该毁掉一次战斗**。

出处：gamasutra.cn/design/the-secrets-of-dead-cells-smart-constraints-unlocking-the-vault-3

### 1.2 Ars Technica《War Stories》—— 团队原话

> 有一段时间，游戏"**被巨大而没有实际意义的关卡创伤**"（traumatized by huge levels
> with no actual meaning）。算法很擅长生成迷宫房间，但它**判断不了什么算"好结果"**。
>
> 于是转向混合做法：**手工设计每一个房间**，有明确的出入口和**强烈的 flow 感**，
> 再让算法把它们连起来。

出处：arstechnica.com/gaming/2019/07/war-stories-designing-dead-cells-was-a-marriage-of-man-and-machine

**这条直接否掉了「结构越复杂越好」**：团队自己走过"大而空"的弯路，结论是复杂度本身没价值，**flow 才有**。

### 1.3 Motion Twin 官方分享（语雀译文）—— 房间块的属性

> "每个房间块的地形结构都是**为其用处而专门设计**的。藏有宝箱的房间和商人房间构造不同，
> 而这两种房间又和**战斗房间结构差别巨大**。"
>
> "每个房间的属性主要包括**入口数量、是否有出口以及房间的用处**。"
>
> "有些（敌人）**需要在有较大空间方便移动的地方出现**……有些**不能和其他某种怪物
> 出现在同一平台**。"

出处：yuque.com/kanfeiji-idtso/qc76el/urgyxo（Motion Twin 在 GDC/开发者分享的译文）

关键：**敌人的空间需求是设计输入，不是事后撒点。** 房间先定"这里能打什么样的仗"，
再决定放什么敌人。

### 1.4 「随机生成」的真实含义（回应"人家的房间都可以随机生成"）

Dead Cells 不是"随机长出一个房间"。它是：

```
手工设计 N 个房间块（每个块有入口/出口/用途标签）
  → 生成一张抽象概览图（哪几个节点、什么顺序、几个特殊房）
  → 按标签匹配，把块填进节点
```

**随机发生在"块与块的拼接"，不发生在"块内部"。** 块内部是美术和策划一格格画的。

所以「先把一个房间做到游戏水平」不是绕路，是**随机生成的前置条件**。
没有好的块，拼接只会拼出一堆坏房间。

## 2. Dead Cells 一间战斗房的解剖

（结构来自游戏内观察 + 上述文档的交叉印证，标「推断」的为归纳）

```
┌──────────────────────────────────────────────┐  ← 天花板：不规则，有洞窟轮廓
│                                              │
│        ▬▬▬▬▬▬            ▬▬▬▬▬▬▬             │  ← 高台：少、长、错开
│                                              │
│   ▬▬▬▬▬▬▬▬▬▬                       ▬▬▬▬▬▬▬    │  ← 中台：少、长
│                                              │
│ ═══════════╪═══════════════════╪═══════════ │  ← 地面：主体，柱子打断
│   门                                     门  │
└──────────────────────────────────────────────┘
```

| 要素 | Dead Cells 的做法 | 为什么 |
| --- | --- | --- |
| **宽度** | 1.5–2 屏，横向滚动 | 走进去才展开，不是一个一眼看穿的盒子 |
| **高度** | 约 1 屏，2–3 层 | 层多了会把战场切碎 |
| **地面** | 主战场，占 60%+ 活动时间 | 近战要空间展开；翻滚、后撤都需要地 |
| **平台** | **少而长**（每层 1–2 条，每条 6–10 格） | 平台是"机动选项"，不是"必经路径" |
| **平台厚度** | 薄，可从下方跳穿（单向） | 上得快、下得快，不打断战斗节奏 |
| **柱子/墙垛** | 从地面长上去，支撑平台 | 打断直线、给走位提供参照，视觉上不"浮空" |
| **垂直落差** | 一次跳能上，掉下来不死 | 高度是"战术位置"，不是"惩罚" |
| **出口** | 顺路，通常走地面就到 | 门锁着，跑不掉；到了自然要打 |
| **敌人** | 分 2–3 个高度，形成交叉 | 待在一个平面不安全，逼玩家动 |
| **奖励** | 放在"不顺路"的高处 | 给额外动机，但不强制 |

### 关键机制：**锁门替代了"空间强迫"**

这是我最需要改的一点。

我原来的逻辑是：**用空间强迫玩家做事**（想去门那儿？必须爬 3 层）。
Dead Cells 的逻辑是：**用锁门强迫玩家做事**（门锁了，你只能清场）。

一旦门锁了，空间就**不需要**承担"逼玩家走某条路"的责任，
它可以纯粹为"打得好看"服务 —— 开阔、有高差、有掩体。

**空间从"约束"变成了"舞台"。** 这是两个完全不同的设计目标。

## 3. 我连续两次做错，错在哪

第一次（三级台阶）和第二次（错位网格 11 块板），我都在同一个错误方向上迭代：

| 维度 | 我做的 | Dead Cells | 后果 |
| --- | --- | --- | --- |
| 房间定位 | 垂直攀爬塔 | 横向战斗场 | 玩家在赶路，不在打仗 |
| 平台作用 | **必经路径** | 战斗机动（高地/躲闪/俯冲） | 平台越多 = 越像迷宫 |
| 失败代价 | 掉下去重爬 3 层 | 掉回地面，继续打 | 平台失误被放大成惩罚，违背 1.1 |
| 出口条件 | **必须跳 3 次** | 顺路，门锁着 | 难度来源错了：来自跑酷而非战斗 |
| 房间宽度 | 26 格 = 1 屏，一眼看穿 | 1.5–2 屏，走进去才展开 | 必然"盒子感"，加多少平台都救不了 |
| 平台数量 | 11 块，每块 3–5 格 | 3–4 块，每块 6–10 格 | 空间被切成碎片，读不出路径 |
| 敌人 | 数量写死、类型按索引轮换、全地面 | 按战斗配额、类型受空间约束 | 空间和战斗完全脱钩 |
| 我的判据 | 层数多、跳数多、岔路多 | —— | **判据量的是跑酷难度，方向反了** |

**最狠的一条**：我加的 `min_jump_to_exit=3`（必须跳 3 次才能出门）和
`min_alternate_stands=6`（必须有多条岔路），**正好是 Dead Cells 明确要避免的东西**。
判据越"严格"，房间越像跑酷游戏。

第二次重做后判据全绿，但房间更难看了 —— 因为**判据和目标是反的**。

## 4. 新范式：可执行规则

用在 `Room01` 上，逐条可验：

### 4.1 尺寸与镜头

- 网格 **40 × 15**（1920 × 720）= 1.5 屏，**横向滚动**
- 摄像机已有 `limit_left/right`（`BaseRoom._apply_camera_bounds`），房间变宽后自动滚动
- 上限：宽度不超过 2 屏（2400px），否则玩家会迷路

### 4.2 高度：3 层

| 层 | y | 说明 |
| --- | --- | --- |
| 地面 | 624 | 主战场 |
| 中台 | 480 | 战斗机动层 |
| 高台 | 336 | 奖励 + 俯冲起点 |

层距 144px < 单跳 204px，留 60px 余量 —— **一次跳能上，不考验操作**。

### 4.3 平台：少而长

- 总数 **≤ 5 块**
- 每块 **≥ 5 格**（240px），不允许"2 格小岛"
- 用 `=` 单向平台（能从下方跳穿）
- **柱子支撑**：落地柱 1 格宽，从地面长到中台底面，让平台不"浮空"

### 4.4 地面：主体

- 连续可走段 **≥ 10 格**（480px），保证近战能展开
- 柱子把地面分成 2–3 段，但每段都够宽
- **不做地面高差**（项目没有自动上台阶，会变成"必须跳"）

### 4.5 敌人：混编分层

- 4 只：地面 ×2、中台 ×1、飞行 ×1
- 高度分布 ≥ 3 层
- 飞行敌人占住中段上方，逼玩家抬头
- 类型**按蓝图指定**，不按索引轮换

### 4.6 出口：顺路

- 右门在地面层，走过去就到
- 门锁着（已有机制），清场才开

### 4.7 判据（全部反转）

| 旧判据（作废） | 新判据 | 意思 |
| --- | --- | --- |
| `min_jump_to_exit=3` | `max_jump_to_exit=1` | 出口必须顺路，难度不来自跑酷 |
| `min_layers=4` | `max_layers=3` | 层多了战场被切碎 |
| `min_detour_stands=6` | —— 删掉 | 支线站面是跑酷指标 |
| `min_alternate_stands=6` | —— 删掉 | 岔路是跑酷指标 |
| —— | `max_platforms=5` | 平台少 |
| —— | `min_platform_span=5` | 平台长 |
| —— | `min_ground_span=10` | 地面开阔 |
| `min_enemy_layers=3` | 保留 | 这条是对的 |
| —— | `min_flying_enemies=1` | 逼玩家离开单一平面 |

**判据从"要求更多"变成"要求更少、更开阔"** —— 这个符号反转本身就是这次修正的核心。

## 5. 明确不照搬

| 做法 | 为什么不 |
| --- | --- |
| 房间块随机拼接 | 前置条件是有一批好块；现在一个都没有 |
| 尖刺/陷阱 | 项目没有实现，本轮不做，先靠敌人+高差制造压力 |
| 多套敌人行为（远程/瞬移/盾） | 只有地面近战 + 飞行两种，先把这两种用对 |
| 5–7 层视差 | 本轮不做美术（用户明确说先不做背景） |
| 可破坏地板 / 隐藏房 | 需要新的地形破坏系统，超范围 |

## 6. 验证方式

1. **几何判据**：生成器自动算（§4.7 全部）
2. **通行实测**：真实物理跳一遍，确认"到出口 1 次跳、到奖励 2 次跳"
3. **战斗实测**：模拟玩家从进门到清场，确认 ① 站着不动会被打 ② 有 3 个高度需要处理
4. **反向验证**：故意改回"跑酷塔"，新判据必须 FAIL

## §0.6 「单房间」指的是**一关**，不是一屏

2026-11-27，白哥给了一张《死亡细胞》的**关卡地图**截图（"选择目的地"界面），原话：

> 「这是细胞重生的单房间地图，能玩2-5分钟。你设计那个地图10秒都玩不了」

在此之前我一直把"一个房间"理解成"一屏"。截图能读到的事实：

| 看到的东西 | 数量 / 形态 |
|---|---|
| 主通路 | **一条横贯全图的走廊**，高度基本不变，偶尔上下折一两格 |
| 挂在走廊上的房间 | 上下各 5~7 个，多为 2~4 格高的小间，有的一格宽 |
| 竖井 | 2~3 处，都是"一列多格、逐级平台"的垂直通道 |
| 出口 | 3 个，分别通向**不同的下一关**（猛毒下水道 / 荒废植物园 / 有罪者的大道），蓝色门 = 已探索，橙色 = 未探索 |
| 全图尺寸 | 目测 ≈ 4~5 屏宽 × 3 屏高；玩家在里面要走、要打、要回头 |
| 标记 | 传送点、宝箱、诅咒箱、"!" 事件点散布在各房间 |

### 这一条改变了什么

- **"房间"的单位是一关**。DC 的一关 = 我们的一次场景加载。
- 判据不能只量结构（层数 / 跳数 / 岔路），必须量**体量**：
  最短步行距离、纯跑图时间、敌人密度（跟着面积走，不是跟着"房间数"走）。
- 走廊是主脊，房间是咬在上面的**凹室**，不是一个一个大盒子串起来。
  Room01 的第五版仍然是"大厅 + 竖井 + 长走廊"，右半段缺少咬合，这是下一步。
