# SoulKeep — 代码包说明

一个 2D 横版动作原型（恶魔城 / 银河战士风格）。当前路线是 **A：老实复刻《重生细胞》的动作层**
（`DESIGN_A.md`）—— 攻击后摇可取消、挨打后能夺回一段血、致命伤有一次性保护。

> 2026-11-25 变更：原来的「侧身（把自己压成一张纸）」**已删除**。
> 它在正式流程里进不去（纸缝只长在一间没有入口的实验房），还占着 F 键、
> 并且是第二条资源条。理由与影响面见 `DESIGN_A.md` §9。
> 「穿窄处」留给 P3 的 rune 门（爬 / 撞 / 传），那是 DC 的做法。

打包日期：2026-11-25。构建：`SoulKeep.html`（单文件，无外部依赖）。

## 1. 立刻能玩

双击 **`SoulKeep.html`**（或拖进浏览器）。不需要服务器、不需要联网。

- 键盘：`A/D` 移动 · `K` 跳 · `J` 攻 · `F` 冲刺（旧键 `I` 也可用）· `E` 交互 · `O` 魂匣
- 右下有**四个装备格**：剑 / 未装备 / 红 / 蓝，鼠标点一下就用。位置可调：`O → 操作 → 调整位置`
- 如果按了没反应，**先用鼠标点一下画面**再按（浏览器把键盘焦点给了别的窗口）
- 想强开手机版界面：`SoulKeep.html?touch=1`

## 3. `src/game.js` 怎么读

单文件，但严格分区，按注释横幅找：

| 行 | 分区 | 内容 |
|---|---|---|
| 12 | 常量 | 物理常数、定步长、能力位 |
| 158 | 魂表 | `KEY_OF`（键位唯一真相）、`SOULS` |
| 175 | 房间 | 房间数据（用字符串画地形） |
| 341 | 皮肤包 | 贴图包 / 照片包 |
| 441 | 状态 | 玩家状态 `P`、存档 `SAVE` |
| 517 | 存档 | localStorage 读写、脏数据白名单 |
| 649 | **输入** | 键位表 `K`、`KEYMAP`/`CODE_ACT`、动作层令牌、事件入口 |
| 1033 | 碰撞 | 瓦片碰撞、能力位判定 |
| 1114 | 房间装载 | |
| 1182 | 敌人 | 敌人状态机 |
| 1262 | 玩家 | 移动、跳跃、攻击（侧身已删，见 DESIGN_A §9） |
| 2065 | 程序化怪物 | 无贴图时的矢量绘制 |
| 2538 | 循环 | 定步长物理 + 渲染插值 + 绘制 |
| 3087 | HUD / 菜单 | 图例由 `LEGEND` 表生成 |
| 3183 | 启动 | `boot()` |

三个值得先看的设计：

1. **定步长 120Hz + 累加器 + 渲染插值**（§循环）。跳跃顶点是绝对值 203.8px，
   在 30/60/120/144Hz 下完全相同——不是靠手感调出来的，是物理步自己保证的。
2. **能力位（capability bits）而不是状态枚举**（§碰撞 / §玩家）。每个状态声明自己
   申请哪些输入位，没申请的动作在那一步根本通过不了。侧身当年就靠这条实现"不能攻击"
   （只给 `CK.FACING|CK.GRAV_FALL`）—— 动词删了，这套机制还在，蹲/滑铲仍在用它。
   是结构性保证，不是 if 判断。
3. **图例 = 规格**（§HUD）。界面上的按键说明由 `LEGEND` 表生成，
   `ctrl_check.js` 反过来读界面上的字逐条按键验证。说明和实现不可能各走各的。

**纯 Node，不需要浏览器**（用 vm + 假 DOM）：

```bash
node test.js             # 60 项：物理/手感/碰撞/掉落/能力门/关卡可达性
node test_audio.js       # 15 项：音频结构（假 AudioContext，抓"静默失败"）
```

```bash
node ctrl_check.js       # 39 项：读界面上的字，逐条按键验证效果
node keymap_check.js     # 24 项：物理键 → 动作、组合键、R 防误重开、手机四格三键
node ime_check.js        # 50 项：中文输入法组词形态下逐个动作（见 §6）
node input_env_check.js  # 20 项：桌面 / 触屏笔记本 / 手机 / iframe 四种环境
node ui_check.js         # 51 项：图例可读性、魂匣页签、触屏说明、菜单溢出、组合回执语义（见 §8）
node layout_check.js     # 32 项：布局入口、拖动跟手、夹边界、重开还在、恢复默认、触屏不重叠
node interact_check.js   # 32 项：交互键拾取半径、缝里墨囊、重复拿、手机路径
node stress_input.js     # 长按 / 连按 / 组合键，找"出不来的状态"
node verify_fix.js       # 每个键改了多少像素（画面反馈）
node probe_feel.js       # 量手感：加速度曲线、跳跃剖面、帧率
node play_probe.js 90    # 脚本机器人试玩 90 秒，看会不会卡住
```

跑之前要装 `playwright-core` 并有一个 Chromium。脚本里路径是
`process.env.NPM_GLOBAL || 'D:/node-dev/npm-global'` 和
`chromium-1248`——**换成你机器上的路径**，或设环境变量：

```bash
NPM_GLOBAL=/path/to/npm-global node ctrl_check.js
```

当前累计 **455 项测试**，全绿（`stress_input` 的 12 与 `verify_fix` 的 10 是分组统计，不是逐条断言）。

## 6. 这次修的 bug（如果只想看一处，看这里）

**症状**：中文输入法开着时，方向键能动，`A D W S J K U L I F O` 全部无效。

**原因**：字母键先被输入法拿去组词，Chrome 派发的 `keydown` 变成
`{ key:'Process', code:'KeyD', keyCode:229, isComposing:true }`。
旧代码只读 `e.key`，`KEYMAP['process']` 查不到 → 什么都不发生。
方向键不参与组词，所以只有它还能用。

**修法**：以 `e.code`（物理键位）为准；并且对所有游戏键 `preventDefault`，
不让输入法进入组词。

完整代码和推理见 **`DOC_CONTROLS.md`** §0 和 §3，验收见 `ime_check.js`。

## 7. 已知限制（诚实清单）

1. **没有真人试玩数据**。所有手感数字来自脚本机器人和参数计算，
   "第一次玩的人能不能自己发现侧身"这件事**没验过** —— 随着侧身删除，这个问题关闭了。
2. **`walk` 没有动画帧**。现有贴图只导出 idle/wave/attack/kick/hit，
   走路是 idle 帧 + 程序化步态（上下颠 ±4px、左右摆 5°）。这是美术资产唯一的硬缺口。
4. **单文件 3200 行**。要不要拆模块还没定（会破坏"双击就能玩"这个约束）。
5. **安卓真机没测过**。iOS Safari 测过。
6. **触屏拇指舒适度没验过**。四格 + 三键的误触率、长按疲劳、安全区，
   目前只有代码层与 Chromium 触摸模拟，没有真机数据。
   已知一个具体数：844×390 上格子是 **49px**，刚过 44px 的可点下限。
7. **首玩者仍然 0 人**。图例看得清了，不代表玩家会读、会自己去按 O。

## 8. WO-003 之后，界面长什么样

- 主界面右下角图例：13px、暖白字、轻量暗底，第二行是 `完整操作：O / Tab`
- 右上角空槽：`未装备` + 虚线边
- 按 `O` / `Tab`：魂匣顶部有两个页签 **「魂槽」「操作」**
  - 魂槽：装备红/蓝魂
  - 操作：完整的键盘键位表（按 移动/战斗/工具/系统 分组，带成立条件）
- 触屏：魂匣「操作」页里，布局入口在最前，触屏说明排在键盘表**前面**，
  每条标 点按 / 按住 / 组合；摇杆下推时边框转暖色；**动作真的发生**时，
  按钮组左侧浮出「滑铲」「穿板」——空中下推按跳、实地下推按攻都不会闪
  （那是普通跳 / 普攻，判定在动作层）

## 9. WO-004 之后：四格 + 三键 + 可调布局

- 右下四格：`剑`（攻击）`未装备`（原纸格）`红`（红魂）`蓝`（蓝魂）。
  44px 方形，点一下就用 —— 攻击不再占一个独立键，这就是右边只剩三个键的原因
- 三个方形键：`跳`（最大，右缘 80 / 下缘 18）`翻滚` `交互`，形状和格子同一套底板
- 魂不再吃蓝条（MP 已删），红/蓝走**冷却**：格子上的黑幕从下往上退
- 空槽写「未装备」+ 虚线边；冷却不写数字（战斗中没人读小数）
- **布局可调**：`匣 → 操作 → 调整位置`。四格与三个键都能拖，松手即存
  （`localStorage['soulkeep.layout.v1']`），能一键「恢复默认」。
  「匣」固定不可拖 —— 它是退出这段编辑的唯一出口。
  设计依据（两套坐标系、为什么大小只有一个滑杆）见 `DOC_CONTROLS.md` §9
