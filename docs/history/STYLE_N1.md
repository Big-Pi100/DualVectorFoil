# STYLE_N1 · 明快自然（冒险岛那条路）

> 定于 2026-11-25。白哥的原话：
> 「恶魔城大多偏向暗黑，有个自然系的反而会突出」
> 判定：**走 N1**。本文把它从"感觉"变成可执行的规格，供美术生产与验收使用。
> 参照实现：`style_proto.html`（canvas 程序化原型）、`shots/proto_n1_attack.png`。

---

## 1. 为什么是这个方向（三条，按分量）

| # | 理由 | 说明 |
|---|---|---|
| 1 | **赛道空着** | 类恶魔城/动作横版的主流配色是"暗色 + 哥特"：Dead Cells、Hollow Knight、Blasphemous、Salt & Sanctuary、Momodora 的夜晚段。**明亮自然的硬核动作反而是少数** |
| 2 | **可读性天然更好** | 亮背景 + 深色主角，剪影自动成立。暗场里要靠发光特效"点亮"角色，亮场里靠明度差就够 |
| 3 | **和"魂/纸"的世界观不冲突** | 白天也有鬼。真正决定恐怖感的是敌人的**造型**，不是背景的明度 |

### 1.1 但有一个必须承认的先例冲突

**冒险岛的视觉承诺是"轻松"，Dead Cells 的手感承诺是"紧张"。** 把两者硬拼，玩家会按"轻松"的预期去玩，然后被惩罚，这叫预期违背。

公开的解法只有一个，而且被验证过：**Cuphead**。

- 造型卡通、颜色明亮、音乐欢快 —— **视觉层卖的是"可爱"**
- 敌人设计怪诞（会变形的花、咧嘴的骰子）、表情凶狠、死亡反馈重 —— **内容层卖的是"不好惹"**
- 结果是：玩家一眼觉得"这游戏好看"，第一关就被打服，反而记住

所以 N1 不是"把游戏做成子供向"，而是：**用可爱的壳，装不好惹的内容。** 这条如果不执行，N1 就会掉进"看起来像休闲手游"的坑，而那正是"不够精致"的另一种死法。

## 2. 配方四条（可执行）

### 2.1 背景低饱和 + 空气透视

- 远景整体向天空色混 **45%**，对比度压到 **30%**
- 远景加 **2–3px 高斯模糊**（我们是 1280×720 逻辑分辨率）
- 每深入一层，饱和度 −15%，明度 +8%

### 2.2 前景高饱和 + 高对比

- 可站立面（草地/木台）饱和度拉满，明度压到 **40–55%**
- 近景装饰（草、蘑菇、花）用**最亮的两档绿**，形成"前景比中景亮"的错觉

> 注意：这一条和"主角要最暗"是同一条规则的两面 ——
> **可玩区（脚踩的）必须比主角亮，主角必须比背景暗，天空必须最亮。**

### 2.3 两套渲染语言（2026-11-25 修正，原规格是错的）

原文写"背景也加 2.6px 淡描边"。**生图实测证明这条必须废掉。**

背景一旦描边，树冠会变成一片贴纸，空气透视立刻死掉；而背景不描边、只靠三档明度分层，
反而能出雾感和体积。真正成立的做法是**两个图层用两种渲染语言**：

| 图层 | 描边 | 渐变 | 为什么 |
|---|---|---|---|
| **角色 / 敌人 / 拾取物**（sprite 层，前景） | **2px 硬描边**（按 100px 身高，即 200px 出图时的 4px） | 三档平涂（亮面/中调/深影） | 硬描边让 sprite 从柔和的背景里"切"出来，这是可读性的来源 |
| **背景 / 地面 / 中景树**（paint 层） | **完全无描边** | 连续微渐变 + 空气透视 | 描边会把远景拉平，失去深度 |

**判据**：同一张图里，只有角色、敌人、拾取物带轮廓线；背景里若出现任何闭合轮廓线，即为不合格。

**技术注意**（v1 踩过）：若将来仍需在代码里画描边，**不能直接 stroke**。
`ctx.stroke(Path2D)` 会把复合路径里每个子圆的内圈也描出来，树冠会变成一堆圆环。

> **这条路线的根本变化**：背景不再由代码绘制，改为**生图产出分层贴图**；
> 代码只负责分层平移、视差、光照叠加与特效。这是"精致度"能否成立的前提。

### 2.4 亮底特例：特效必须"反向"

暗场里刀光是"变亮"；**亮场里只做白光等于没做**。实测：

| 层 | 做什么 | 数值（相对） |
|---|---|---|
| 外发光 | 暖白，大半径 | `shadowBlur 32`，alpha 0.45 |
| **深墨核** | 深紫黑弧，**这一层才是被看见的** | `lineWidth 14`，alpha 0.92 |
| 白热线 | 细，压在墨核正中 | `lineWidth 3.6`，alpha 0.95 |

## 3. 色板

```css
/* 天空 */
--sky-top:#a6dbee  --sky-mid:#d7eef0  --sky-bot:#ffefd2
/* 远景（混过天空色，低饱和） */
--far:#a3c3c1  --far-lit:#bcd7d1
/* 中景树 */
--mid:#5c9a6c  --mid-lit:#8cc183  --mid-dark:#3a7452
/* 近景树/前景压边 */
--near:#2b6a43  --near-lit:#58a35c  --near-dark:#1a4a30
/* 地面 */
--grass:#4aa74b  --grass-lit:#8ed164  --grass-sun:#bde27c  --grass-dark:#2a6b3c
/* 木 */
--wood:#b17d4d  --wood-top:#d9a46c  --wood-dark:#7a5230
/* 主角（深蓝，故意最暗） */
--coat:#31435e  --coat-lit:#5a76a2  --coat-dark:#1d2b3d
--skin:#ecc79f  --hat:#1a2431
/* 敌人（紫：和绿互补，天然跳出来） */
--foe:#6c4a7d  --foe-lit:#ac7fc1  --foe-dark:#3f2b4d
/* 拾取/强调 */
--gem:#ffcf5e  --hp:#c8452f  --hp-hi:#f0764f
/* 墨（唯一允许的"黑"） */
--ink:#12222a
```

**规则：敌人一律用暖紫/朱红，不用绿。** 绿底上的绿敌人等于隐形。

## 4. 明度分工（这是整套风格的骨架）

| 层 | 相对明度 | 谁 |
|---|---|---|
| 天空 | **100** | 全画面最亮 |
| 远景 | 82 | 山、远树 |
| 中景树 | 55–65 | 树冠 |
| 可站立面 | 40–55 | 草地、木台 |
| 敌人 | 35–45 | 紫 |
| **主角** | **18–28** | 深蓝大衣 |
| 墨 | 8 | 描边、刀光核 |

**判据（可自动化）**：把画面转灰度，主角所在区域的**平均亮度必须是全画面最低的 15%**。
做不到就说明"主角被背景吃了"，无论描边加多粗都救不回来。

## 5. 装饰密度（"精致"在这里，不在材质）

冒险岛的精致不是笔触，是**同屏物件的数量**。每屏（1280×720 可玩区内）下限：

| 类别 | 数量 | 说明 |
|---|---|---|
| 草簇 | 20–26 | 成簇 3–5 根，高低错落，**不描边** |
| 灌木 | 12–16 | 贴地面，遮住树干根部（否则一排细杆像电线杆） |
| 小花/光点 | 6–10 | 两色，不要超过 3px |
| 石块 | 2–4 | 明度比草地低一档 |
| 蘑菇/蕨类 | 2–4 | 放在平台两端**不对称**，对称会像装饰边框 |
| 飘浮粒子 | 40–50 | 暖白，缓慢上飘 |

**反例**：v1/v2 里草是"一排锯齿"、蘑菇左右各一个 —— 这两处是"看起来廉价"最直接的来源。

## 6. 代价（必须提前认下）

| 项 | 代价 |
|---|---|
| **主角造型** | 主角 = 玩家自己的角色卡（手绘化），不是固定人设。圆润化只作用于**渲染语言**（厚描边 + 三档平涂），不改变脸的来历 |
| **敌人设计** | 不能再用"骷髅/腐尸"那套暗黑语汇，要重做一套"讨喜但不好惹"的怪 |
| **碰撞体** | 树冠、藤蔓是有机形状，平台边缘不规整 → 碰撞盒要么粗糙要么手调 |
| **美术量** | 装饰密度是硬成本，一屏的物件数比暗色哥特多 2–3 倍 |
| **和 DC 手感的张力** | 见 §1.1：必须靠"Cuphead 解法"补回来，不是靠换配色 |

**不受影响**：帧数据、取消窗口、rally、一击保护、定步长、全部 17 套回归。
**手感层与题材无关** —— 这是这次换风格最便宜的地方。

## 7. 验收

| # | 检查 | 判据 |
|---|---|---|
| 1 | 灰度最低点 | 主角区域平均亮度是全画面最低 15% |
| 2 | 缩小可读 | 整屏缩到 320×180，仍能指出主角在哪 |
| 3 | 描边一致 | 同一屏内描边宽度只有 0 / 2.6 / 3 / 3.4 四档，没有第三档 |
| 4 | 色相纪律 | 前景只有绿系 + 木色 + 拾取金；紫只给敌人；红只给血条与蘑菇 |
| 5 | 特效反向 | 亮底截图上，刀光**墨核**的对比度高于白热线 |
| 6 | 装饰密度 | 可玩区内草簇 ≥20、灌木 ≥12 |

前两条可以写进 `shotdiff`（视觉基线）自动跑；后四条目前靠人眼 + 代码断言。
