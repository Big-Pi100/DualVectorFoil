### 为什么整图背景作废

第一版出了一张 1536×1024 的整图，看着好，但有三个死结：

1. **房间长度被图锁死**。回廊 32 格正好一张；钟塔要重出一张；10 个房间 = 10 次
   "重新对齐一致性"。一致性变成一件每次都靠运气的事。
2. **不能分视差层**。远近全糊在一张里，走起来背景整体平移 —— 横版最忌这个。
3. **不能复用**。A 房间调好的笔触，B 房间用不上。

瓦片把这三件一次解决。代价是重复感，用「变体 + 哈希选块 + 四向翻转」压，
剩下的交给屏幕空间的低频 overlay（未做）。

### 尺寸

**192×192 = 4×4 个游戏格（TILE=48）**。不能更小：蜡笔笔尖 12–34px，
96px 的瓦片里只画得下五六道笔，细节全糊成噪点。也不能更大：越大越难藏重复。

### 无缝的三个前提（缺一条就有一条硬缝）

| 前提 | 具体 | 违反时的现象 |
|---|---|---|
| **相位一致** | 跨边界的元素（砖缝、石层）在 0 和 192 处必须对齐 | 每 192px 一条密度断层 |
| **笔迹环绕** | 跨边界的笔要画到对面去（`Crayon(wrap=True)`） | 边界上笔迹凭空断掉 |
| **不透明纸底** | 瓦片存 PNG 时要贴纸色，不能存 RGBA | 针孔露出引擎深色底，整面墙像结霜 |

> 第三条最阴：在纸色背景上预览完全看不出来，进游戏才发现。
> 第一版就是 `c.save()` 存的 RGBA，游戏里墙变成"深灰 + 亮噪点"。

### 笔刷原语（`art/tools/crayon.py`）

LLM **不许直接写 `ctx.fillRect` + hex**。只能调原语，原语只接受 12 色板的名字、
只接受 1–34px 的笔宽，写错抛异常。一致性由代码保证，不靠"我记得住规范"。

笔尖模型转写自 [p5.brush](https://github.com/acamposuribe/p5.brush)（MIT）：
它的 `crayon` 参数是 `scatter 1.9 / grain 2 / spacing 0.07`，关键结论是
**笔尖不是实心圆，是一张带颗粒的纹理图**。转写后线条才有"芯实、边碎、外面飞屑"。

四条必须分开的机制（混在一起就会互相打架，都是踩过的）：

1. **面积**（`coverage`）→ 笔距。露纸是"笔没走到"，不是"走到了没沾上"
2. **浓度**（`pressure`）→ 深浅。压得轻是**变淡**，不是断线；断线要显式给 `gap`
3. **针孔**（纸纹高频）→ 只由 `g_fine` 切阈值，低频只调制 ±20% 浓度
4. **纹理**（笔尖 tip）→ 只给**单笔**用。`fill` 要 stamp 上百次，碎屑会累积成霜

### 结构线不用纹理笔

砖缝、门框这类**结构线**必须连续，`stroke(textured=False)`。
带碎屑的笔尖画缝，缝会断成一串白点，在游戏里一目了然。
