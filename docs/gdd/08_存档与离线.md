# 08 · 存档与离线

> 建 2026-11-26。这份回答**什么被存、什么时候写盘、离线期间发生什么、坏了怎么办**。
> 起因：MVP 验收里「任何时刻杀进程」「离线 2 小时被袭击」两条判据写得太粗，
> 不定义清楚就无法实现、也无法验收。

---

## 1. 存档里装什么

一个存档 = 三块。**任何一块丢了都是进度损失，所以三块同一次写盘。**

| 块 | 内容 | 变化频率 |
|---|---|---|
| **角色** | 位置（房间 id + 房内坐标）、血量、已解锁技能、弹药数、已种强化、底片点数 | 高 |
| **世界** | 已清区域列表、已开的门、每块耕地（格数/作物/种下时间戳/是否成熟）、每区驻守兵（种类/数量） | 中 |
| **元数据** | `version`（存档格式版本）、`saved_at`（写盘时刻）、`checksum`、`seed`（离线结算用） | 每次写盘 |

**不存的东西**：镜头位置、特效状态、粒子、当前播放的动画帧。这些进房间时重建。

**存储介质只有一套**（`07 §10`：Godot 为唯一开发主线）：`user://save.json` +
`save.bak.json`。原型那套 `localStorage` 只作基线对照，不实现。

## 2. 什么时候写盘（持久化时机）

**只在这些点写，不做定时轮询。** 理由：手机上每 10 秒写一次本地存储会掉帧，而且拦截不了强制杀进程。

| 时机 | 为什么在这里 |
|---|---|
| **进入暗房** | 暗房本身就是"安全点"，语义上就该存档 |
| **房间清空**（最后一只敌人死亡） | 这是"进度"的最小单位，不存就等于白打 |
| **技能获得** | 不可逆，必须立刻落盘 |
| **种下 / 收获作物** | 计时基准点，丢了就长不出来或白长 |
| **Boss 房入口** | 死了要能直接重打，不必重走 |
| **主动退出**（返回主菜单） | 正常路径，必存 |
| **页面隐藏**（`visibilitychange` / `pagehide`） | 手机切后台的唯一信号，尽力存一次 |

### 2.1「任何时刻杀进程」的真实语义

不能承诺"任何时刻退出都不丢"。**强制杀进程时，最后一次写盘之后的进度会丢**，这是物理限制。验收判据要改成可执行的形式：

> 在任意时刻杀进程 → 重进后回到**最近一次写盘点**，
> 且该点的角色/世界状态完整，**不出现半写状态导致的坏档**。

会丢的东西（明确接受）：
- 房间内捡到的材料（该房间尚未清空 → 回退到进房前）
- 房间内消耗的弹药与血量（同样回退）
- 走了一半的路程

**为什么不每 10 秒写盘**：手机浏览器写 localStorage 是同步阻塞，10 秒一次会在战斗里造成可感知的卡顿；而收益只是少丢几步路。**用"回退一个房间"换"全程不掉帧"是划算的。**

### 2.2 死亡 vs 退出 vs 杀进程

| 情形 | 回到哪 | 弹药/血 | 已清的房 | 作物计时 |
|---|---|---|---|---|
| **死亡** | 最近暗房 | 满血；弹药补到暗房补给后的值 | 保留 | 继续走 |
| **主动退出** | 最近暗房 | 同死亡 | 保留 | 继续走 |
| **杀进程** | 最近写盘点（通常是暗房或清房瞬间） | 回退到该点 | 回退到该点 | 继续走（按时间戳算） |
| **Boss 战中途退出** | Boss 房入口 | 满血 + 弹药按暗房补给 | 保留 | 继续走 |

> **Boss 战为什么特殊**：中途杀进程回退到 Boss 门口，等于给了无限重试。这不算漏洞——
> 死亡本来就回暗房，只是少走几步。**不给"中途存档"反而会让长 Boss 战在手机上一次中断就全废。**

## 3. 离线时间怎么算

**起点 = 最后一次成功写盘的 `saved_at`**，不是"最后在线时刻"。

理由：`pagehide` 不保证触发（系统回收进程时可能没有）。用写盘时间最保守——最坏情况少算"上次写盘到现在"这段，但不会多算。**多算会让玩家被不该来的袭击打一顿。**

**终点 = 本次启动读档的时刻。**

| 量 | 算法 |
|---|---|
| 离线时长 | `now − saved_at`，小于 0 时按 0 处理（防改系统时间） |
| 作物成熟数 | `floor(离线时长 / 成熟周期)`，**上限 3 茬**（`06 §6`） |
| 是否触发袭击 | 离线 ≥ 2 小时，且该区域有作物或驻守 |

---

## 4. 离线结算：确定性的，不是模拟

**规则**：离线期间**不跑任何模拟**。上线时用纯函数算一次结果。

```text
输入：离线时长、区域状态（地块/驻守/作物）、seed
输出：每个区域的袭击清单（几个敌人、分几波、强度倍率）
```

| 项 | 规则 | 为什么这样定 |
|---|---|---|
| **随机性** | 不用 `Math.random()`。用 `hash(seed, 区域id, 离线时长取整到分钟)` | 同一存档同一时刻重算必须得到同一结果，否则无法测试、无法复现 bug |
| **频次** | 每区域每次上线**最多 1 次**袭击 | 不做多次累积：手机上一次连打 3 波会疲劳，且玩家会觉得被罚 |
| **强度** | `区域基础 × min(1 + 离线小时/12, 2.0)` | 有上限（挂一周不会必死） |
| **敌人数** | `基础 30–50 × 强度`，**按同屏上限 8 分批**（`06 §5`） | — |
| **守军削减** | 每驻守 1 兵减 2 只来敌，**最多减 6 只**（3 兵满编） | 守军是"减负"不是"代打"，玩家仍必须亲自打主力 |
| **守军不代打** | 参战后按简单 AI 冲向敌人、攻击、死亡，**不减玩家操作** | 与 `03 §5` 一致：防守必须用手 |

### 4.1 一次袭击的完整流程（可验收）

1. 上线读档 → 算离线时长 → 若有区域满足条件，标记为"待袭击"
2. 玩家回到该区域 → 进房时触发，弹一行提示（不弹对话框）
3. 打。守住 → 田保住 + 掉材料；守不住 → 作物清空、**地块保留**（`03 §5`）
4. **玩家可以选择放弃**（显式按钮）→ 直接判定丢失，不进入战斗
   - 必须显式选：不能"关掉游戏当没看见"，也不能默认忽略

### 4.2 明确不做

| 不做 | 为什么 |
|---|---|
| 离线期间的实时模拟 | 手机不可能后台跑战斗；且结果不可复现，测不了 |
| 多次袭击累积 | 见 §4 频次 |
| 离线期间作物被摧毁 | 只丢一茬，不毁地。否则"关游戏"变成惩罚 |
| 离线期间自动收获 | 会让"回访"这个动作失去意义 |

## 5. 存档坏了怎么办

| 情形 | 处理 |
|---|---|
| `checksum` 不匹配 | 回退到上一份备份（保留 **2 份**轮转：`save.json` + `save.bak.json`） |
| 两份都坏 | 明确提示「存档损坏，无法读取」，给两个按钮：**新建存档** / **导出损坏文件**（供排查）。**绝不静默清空** |
| `version` 低于当前 | 走迁移函数；无迁移路径时提示「此存档来自旧版本」而不是崩 |
| 写入过程中被杀进程 | 先写临时文件再 rename（原子替换），保证 `save.json` 永远是完整的 |

> **一条铁律**：任何情况下都不能"读档失败 → 当作新游戏开始"。
> 这是最伤玩家的 bug，比崩溃更糟——玩家会以为进度被删了。

## 6. 验收（对应 `07 §4`）

| # | 项 | 判据 |
|---|---|---|
| S1 | 杀进程恢复 | 进房 → 杀进程 → 重进：回到最近写盘点，血/弹药/已清房与该点一致，无坏档 |
| S2 | 离线结算确定 | 同一存档连续读档 3 次，袭击清单（敌人种类/数量/波次）**完全一致** |
| S3 | 离线时长正确 | 改系统时间到未来 / 过去，离线时长不为负、作物茬数不超 3 |
| S4 | 坏档恢复 | 手动损坏 `save.json` 的 1 个字节 → 能从上一次备份恢复，进度不丢 |
| S5 | 双坏档 | `save.json` 与 `save.bak.json` 都损坏 → 弹提示，不进入新游戏 |
| S6 | 长时间运行 | 连续 30 分钟不退出：无持续性内存增长（场景切换 20 次后纹理数不增）、无输入失效 |
