## 1. 什么算"一个可玩的房间"

四条判据，**缺一条就不算**。这四条是拿 HK beta 的标准反推的
（见 `REF_MV_DESIGN §9`：HK beta = 2 区 + 1 能力 + 1 Boss 就能拿去开展会）：

| # | 判据 | 怎么验（不看感觉，看行为） |
|---|---|---|
| **V1** | 进去有敌人，**敌人主动朝你来并起手** | 站在门口不按键，10 秒内被至少 1 只敌人打到 |
| **V2** | **玩家可能死，死回安全屋** | 故意不还手，能死；死后回到暗房，血满、敌人已清的不复活 |
| **V3** | 清完**看得见变化** | 最后一只死掉的瞬间，全场进 ALLY 态（环境光 `night` 1.0→0.0） |
| **V4** | 出去**知道往哪走** | 不查攻略，能找到下一间的门；且门是可见的（不是藏在屏幕外） |

现在 V1、V2 **成立**，V3、V4 成立（V1/V2 于 11-27 补齐，见 §3.0 的 S0/S1 记录）。

> **V4 现在"成立"是假的**：6 间房是一条直线，门自动可走，玩家当然不会迷路。
> 真正的 V4 要有岔路。所以切片的地图不能是纯链，见 §2。

## 2. 切片范围：5 间房、2 个能力、1 个 Boss

### 2.1 地图：5 间 + 1 个岔路

```
         ┌──── [B] 高台房 ────┐        ← 折叠门（4.5–6.5 格台子）
         │  （看得见，过不去）  │
出生 [A] ─┤                    └── [E] Boss 房
         │                          ↑
         └──── [C] 安全屋（暗房）────┘
                    │
              [D] 死巷：拿折叠
```

- **[A] 出生房**：1 只纸团，教"打"。判据 V1 第一次成立。
- **[B] 高台房**：**从 A 就能看见上面有东西**，但跳不上（4.5–6.5 格）。
  第一次经过时玩家记下"这里过不去"。**这是门，不是谜题。**
- **[C] 安全屋**：暗房 + 存档 + 第一次看见耕地。判据 V2 的落点。
- **[D] 死巷**：从 C 往回折一下就到，25 秒内拿到**折叠**。
- 回到 **[B]**：折叠加二段跳 6.85 格 → 上去 → 通 **[E] Boss**。

**这一条闭环就是白哥第 2 点要的"用新能力重新发现旧区域"，而且它不违反 `04 §8`**
（详见 `REF_MV_DESIGN §10`：回头成本 = 1 房，在环上）。**B–C 之间就是那个环。**

### 2.2 现有 6 间房怎么映射

**建议直接认领**，不重命名（重命名会动 `.import` 和门引用，成本大于收益）：

| Godot 场景 | GDD 身份 | 切片角色 |
|---|---|---|
| `Room01` | **R3 根·出生点** | [A] 出生房 |
| `Room02` | **R4 根·一** | [B] 高台房（加一个折叠门） |
| `SafeHouse` | **R6 根·三（暗房）** | [C] 安全屋 |
| `Room03` | — | [D] 死巷：拿折叠（**从 Room01 分出去，不是从 SafeHouse**） |
| `Room04` | **R7 根·四** | Boss 前厅 |
| `Room05` | **R8 根·末** | [E] Boss 房 |

**缺 1 间**：GDD 的 R3b（出生点正下方的死巷，拿投掷）。切片里它的角色被
Room03 顶替，**但给的不是投掷，是折叠**（理由见 §2.3）。

### 2.3 两个能力：折叠 + 生长。投掷**不进切片**

| 能力 | 进不进 | 理由 |
|---|---|---|
| **折叠**（二段跳，+125px，总高 6.85 格） | ✅ 必进，**但活很少** | 它是整条闭环的钥匙，纯移动、不依赖任何经济。**代码已存在**（二段跳 331px 实测过），缺的只是「解锁前不许跳」那个开关 |
| **生长**（垂直攀爬） | ✅ 进，放 Boss 前 | 给 Boss 房一个"必须爬上去"的入口，和折叠形成**两种形状的门**（`04 §4.1`） |
| **投掷** | ❌ **不进** | **它会把弹药经济拖进来。** 弹药只靠种植 + 暗房补给（`06 §4`），而种植是 P2。给投掷 = 切片里必须同时有种植、种子、保底种子、空弹提示 —— 切片立刻变成整个 MVP |

> 白哥说"两三个能力"。**两个就是上限，不是下限。**
> HK 的 beta 只有**一个**（`REF_MV_DESIGN §9`）。切片的价值不在能力数量，
> 在"能不能演完一次认知改变"。

### 3.0 实施记录（11-27 完成）

代码：`world/enemies/InvaderAI.gd`（挂成 `Invader` 的子节点 `AI`）。
闸门：`tests/test_enemy_ai.gd`，六组断言 + 真实房间验收。

**为什么没有拆 S0a / S0b（改了原计划，理由留档）**：
拆分的目的本来是「先拿到一个能玩的东西」。但基线里的「接触伤害」正是 S0b 要删掉的东西——
先写它、再删它，等于给自己造一次回退。真正需要提前验证的是「AI 能不能动」，
那个用测试隔离验证比用接触伤害验证更便宜。于是直接做了终态：
**起手 → 判定 → 后摇，没有接触伤害**。

实测（`test_enemy_ai.gd` 输出）：

| 项 | 结果 |
|---|---|
| 巡逻 | 55px/s，1 秒走 55px；6 秒后仍被 96px 边界挡在范围内 |
| 察觉追击 | 240px 处 45 帧内距离 242 → 198 |
| 起手可读 | 450ms 起手里有 **12 帧**纵向压扁 >12%（要求 ≥5 帧，否则肉眼等于没有） |
| 判定结算 | 一次挥击只扣 1 次，伤害 18（120 → 102） |
| 硬直打断 | 起手期挨打 → 立刻 HURT，**这一击没有造成伤害** |
| 悬崖折返 | 400px 台面上跑 5 秒，**每帧脚下都有地**，最远 |x|=178（台面到 200） |
| **真实房间** | Room01 开局入侵，玩家站门口**不按键**：**第 5.1 秒**第一次挨打 |

**反向验证过的四条**（不验证的闸门等于没有闸门）：

| 故意改坏 | 应失败 | 实际 |
|---|---|---|
| 去掉「一次挥击只结一次」的守卫 | 判定连扣 | FAIL：8 次 |
| 起手不做形变 | 形变帧数不足 | FAIL：0 帧 |
| 取消悬崖/撞墙判定 | 走下台面 | FAIL：悬空 38 帧 |
| `_do_chase` 直接 return | 追不上人 | FAIL：9 处（含真实房间） |

**两处踩到的坑（都会让闸门静默失效）**：
1. `ws.set("invaded_rooms", ["room_01"])` 对 `Array[String]` **静默失败** →
   房间根本没入侵，测试只会报「没打到人」。必须 `(ws.get("invaded_rooms") as Array).append(...)`。
2. 敌人一开始没有重力：走下台面会**停在半空**，而「y 没变」这条断言照样绿。
   加 `GRAVITY` 后把断言改成「每帧脚下都有地」（射线），才拦得住。

### 3.0.1 S1 实施记录（11-27 完成）

代码：`entities/player/Player.gd`（`died` / `is_dead` / `_enter_death` / `revive`）、
`world/rooms/BaseRoom.gd`（安全屋复活分支 + HUD 绑定）、`core/WorldState.gd`（`purified_rooms` / `safe_room_ids`）、
`ui/HealthBar.tscn|gd`（新增）。
闸门：`tests/test_death_loop.gd`，九段断言（含 HUD 绑定与血条）+ 一段端到端。

**先纠正一个印象**：S1 不是"从零实现死亡"。`respawn_requested` → `SceneTransition.change_room`
的链路 11-27 之前就在，`test_rest_and_transition` 也早就在测它。**缺口是五处细节**，
而且五处都不会让既有测试变红：

| # | 缺口 | 后果 | 改法 |
|---|---|---|---|
| **1** | `_receive_damage` 在 emit 之前就 `hp = max_hp` | 同一帧发 `health_changed(0)` 和 `health_changed(120)`，HUD 只渲染后者 → **死亡在屏幕上不可见**，玩家只觉得画面一闪人就到了暗房 | hp 停在 0；回满血移交给 `revive()`（复活是宿主的事，不是死亡的事） |
| **2** | 死亡不停物理 | 喂一个向右的虚拟摇杆，倒下后仍会滑 **81.5px** → 看着像被打飞，不像倒下 | `_physics_process` 首行 `if is_dead: return`；`take_damage` 也早退，防止后摇里的第二击重复触发死亡流程 |
| **3** | `purify_room` 只从 `invaded_rooms` 删掉 | 没有「已清」记录 → 该房一旦种上作物，下一轮温和入侵会把它当普通候选**重新占掉**。切片里 Room01 没作物所以暂时不触发，**是巧合不是保证** | 新增 `purified_rooms`（随存档走），候选判定跳过它 |
| **4** | 正式房间从不调 `TouchHUD.bind_player` | `hud.player` 是 `null`，`_input` 第一行 `if not player: return` → **手机上所有触屏操作都不响应**。键盘走 `Input` 单例照样能玩，所以试玩和 24 套测试都没暴露 | `BaseRoom._bind_player_signals()` 统一绑 HUD |
| **5** | 全项目没有血条 | `health_changed` 只有测试里的 `TestCombat` 打印。玩家挨打唯一的反馈是 0.35s 受击动画，**血量和死亡都没有前兆** | 新增 `ui/HealthBar.tscn`（现有 `ui_heart_icon_00.png` + 两个 ColorRect，零新增美术） |

**顺带修掉一个死亡循环**：安全屋若被占（旧存档 / 规则生效前），原来的原地复活只挪位置、
不清敌人 → 「爬起来 → 敌人还在 → 继续挨打 → 再死」，退出条件是放弃游戏。
现在安全屋分支会清场 + `purify_room`，且 `WorldState.safe_room_ids` 让暗房**根本不参与**
入侵判定（`BaseRoom` 在 `is_safe_house` 时登记，默认表兜住"玩家还没进过安全屋"的情况）。

**反向验证过的四条**：

| 故意改坏 | 应失败 | 实际 |
|---|---|---|
| 把 `hp = max_hp` 挪回 `_receive_damage` | 血量停在 0 / HUD 末值是 0 | FAIL：4 处，HUD 样本变成 `[0.0, 120.0]` |
| 去掉 `_physics_process` 的 `is_dead` 早退 | 倒地期间不吃输入 | FAIL：位移 **81.5px** |
| 去掉 `purified_rooms.has(r_id)` 判断 | 已清房不被再入侵 | FAIL：12 次换房后被重新占 |
| 安全屋复活不清场 | 残留敌人归零 | FAIL：剩 3 只 |
| 删掉 `BaseRoom` 里的 HUD 绑定 | 房间 HUD 已绑 / 血条随血量变化 | FAIL：3 处（绑定本身 + 掉半血 + 血空） |
| 血条不订阅 `health_changed` | 掉半血后填充约一半 | FAIL：填充停在 260/260 |

**端到端**（这条才是 V2 的证据，前面都是直接扣血）：
Room01 开局入侵，玩家站门口**不按键**，**第 15.9 秒**倒下 → 倒地 0.7s → 转场启动。
15.9s 与理论值吻合（7 击 × 2.15s/击，18 伤打 120 血）。

**两处踩到的坑**：

1. **GDScript 的 lambda 按值捕获局部变量**。`var deaths := 0; p.connect("died", func(): deaths += 1)`
   改的是副本，外面永远读到 0 —— 测试报「不还手会被打死：FAIL」，而同一段里
   `hp == 0` / `is_dead == true` 都是绿的。用 `Dictionary` 容器绕开。
   **判据之间的矛盾就是线索**：说没死，又说血是 0。
2. **死亡演出会拖慢所有旧断言**。`test_rest_and_transition` 原本 `await _frames(2)`
   就断言"已在 SpawnFromRest"、`_frames(4)` 就断言"正在转场"。加了 0.7s 演出后这两条必红。
   改成条件轮询（`_wait_until`）—— 顺带把「等固定帧数」这个不稳定写法一起清掉。
3. **`class_name` 在 `--script` 模式下晚于脚本解析**。`TouchHUD` 里写
   `@onready var health_bar: HealthBar` 会让整个 HUD 脚本 Parse Error
   （`Could not find type "HealthBar"`），而**报错只出现在测试输出里**，血条和触屏一起静默失效。
   改成 `Control` + `has_method` 调用。这条 `test_advanced_movement` 顶部早就记着了，我又踩了一次。
4. **"几何变形 = 死亡"是错的**。`player_hurt_00_sprite.png` 本身就是坐地帧，
   压成 1.45×0.32 / 旋转 −72° 都把它毁成一条横线或一坨虫子。**已有资产画好了，别用形变去毁它。**
   这一条只有实拍才看得见 —— 断言从头到尾都是绿的。

### 3.0.2 S2 实施记录（11-27 完成）

**先纠正一个印象**：`can_double_jump` 初值 `true` **不是**锁没上的原因。
它是「本次滞空还剩不剩一次二段」，落地本来就会重置 —— 把初值改成 `false`，
第一帧落地又变回 `true`，等于什么都没做。真正的锁是**落地时按能力充能**：

```gdscript
if is_on_floor():
    can_double_jump = _fold_unlocked()   # 改之前是无条件 true
```

**上锁前先量了六间房**（`gen_room_terrain.gd --audit`，复用同一份可达性 BFS，
不另写审计脚本 —— 两份判据迟早对不上）：

| 房 | 可站格 | 单跳可达 | 孤岛 | 判定 |
|---|---|---|---|---|
| SafeHouse | 25 | 25 | — | 全通 |
| Room01 | 34 | 34 | — | 全通 |
| Room02 | 51 | 51 | — | 全通 |
| Room03 | 32 | 26 | 高台 6 格 (c12-17,r7) | **故意的**，这就是折叠点 |
| Room04 | 34 | 26 | 柱顶 4 格 + 中间台 4 格 | 柱顶 480px 二段也上不去 = 纯装饰；中间台 240px 属"折叠后奖励位" |
| Room05 | 26 | 26 | — | 全通 |

**门全部单跳可达**，所以上锁不会把玩家卡死。这条是 S2 最容易漏的一步。

**改动**：
- `WorldState`：`ABILITY_FOLD` 常量 + `unlock_ability` / `has_ability` + `ability_unlocked` 信号。
- `Player`：`can_double_jump` 落地按能力充能；每帧查真源，**不做缓存**（缓存漏刷新会让玩家「明明解锁了却跳不起来」，而这种 bug 日志里看不出来）。
- `AbilityPickup.gd|tscn`：Area2D 契约复用 `RestBench` 那条（只认有 `interact_requested` 的 body）。视觉是纯 Polygon2D 折纸（零新增美术）。
- `gen_room_terrain.gd`：蓝图字符 `A` + 头部 `ability=<id>`；新增 `--audit`（只验算不写文件）；`vista_at=<列>,<行>`。

**闸门** `tests/test_fold_lock.gd`（六段）：
无能力 → 台面/地面站定高度 → 台底起跳只升 50px（撞头）→ 未解锁补按第二下 → 拾取链路 → 解锁后真上台 → 重进房间不重复刷。

关键数据：单跳 **211.4px**、二段 **331.1px**（vy→-697）、台 **240px**、解锁后落点 **(751.3, 383.9)**。

**四条反向验证全部 FAIL 到位**：
① `can_double_jump = true` → C 段两条红，升幅 342.7px；
② `unlock_ability` 不写入 → 五条红（D 段 + E 段全线崩 + F 段纸片没隐藏）；
③ 不检查 `has_ability` → F 段红（重进房间纸片还在）；
④ 落地永远 `false` → E 段三条红（解锁了也跳不起来）。

**四个坑**（都是断言绿、玩家却玩不出来的那种）：

1. **`player.get("is_on_floor")` 拿到的是 Callable，不是布尔**。
   `is_on_floor` 是方法，`get()` 返回的是绑定方法对象；它 `== true` 不报错，只是永远 false，
   于是「落稳」判据永远不成立，位置也没测到。必须 `p.call("is_on_floor")`。
2. **`get("velocity.y")` 永远是 null**。`velocity` 是一个 `Vector2` 属性，没有 `.y` 子键。
   必须先 `get("velocity")` 拿到向量，再取 `.y`。
3. **纸片位置试了四次才定下来**，每次都只有实拍能看出来：
   - 台正下方 → 台底 528、玩家头顶 570，起跳只升 **50px 就撞头**，捡到折叠当场试跳试不出来；
   - 台左侧 c10 → 压在 VistaPoint 的「驻足·眺望风车」标签上，两行字叠一起；
   - 台右侧 c18 → 整块在触屏按钮下面（跳/攻/盾），提示被盖住；
   - **c9** → 唯一干净的位置。
   **「逻辑上能放」和「玩家能看见」是两件事，中间隔着一次截图。**
4. **拾取后纸片不能留**。第一版 `visual` 要等 2.4s 提示消失才隐藏，
   实拍就是「提示写着获得、红色折纸还杵在原地」，两句话互相打脸。改成当场消失。

**顺手做对的一件事**：把 VistaPoint 从地面挪到**台面上**（`vista_at=13,7`）。
不是为了躲标签 —— 它是这个台的回报：折叠解锁前你连标签都够不着，
解锁后站上去才看得到风车。这是切片里唯一一处「能力 → 地图回报」的闭环
（证据：`art/out/room/shot_fold_onplatform.png`，站上台后 vista 模式拉远相机）。

**生成器幂等的正确口径**：两次生成**几何与数值完全一致**，
但 `unique_id` 每次都变（Godot 自己分配的节点 ID）。所以不能拿文件 md5 判幂等，
要过滤掉 `unique_id` 再比。

**「无折叠也能走完这间房」是实测出来的，不是推的**：
把玩家放在左门、按住右，一路走到右门 `x=1063`，**全程 y=624 没掉没卡**。
台底净空 96px 刚好够一个人走过去 —— 这是 Room03 的硬约束：
折叠点不能同时是一堵墙，否则玩家被自己的目标挡在门外。

### 3.1 S0 的最小 AI 规格（唯一的阻塞项，给死数值）

**先摆一个事实**：Canvas 基线（`src/game.js` 的 `updateEnemy`）里的敌人 AI 只有三种行为，
**全部是"巡逻 + 追击 + 接触伤害"，没有起手、没有判定帧、没有后摇**：

| 基线类型 | 行为 | 数值 |
|---|---|---|
| slime | 在 `min`–`max` 之间来回走 | 55 px/s，碰到掉 10 |
| bat | 正弦上下飘；`\|dxp\| < 320` 时朝玩家靠 60 px/s | 碰到掉 12 |
| boss | 落地后每 1.6s 跳砸一次 | 碰掉 20 |

而 `06 §5` 写着「敌人起手 → 判定 **300–600 ms**（手机反应窗口）」——
**这条是建议值，从没实现过**。

原计划拆两步（S0a 转写基线 → S0b 加起手）。**实际没拆，直接做成了 S0b 的终态**，理由写在 §3.0。

一只"纸团"，状态机 7 态（巡逻 / 追击 / 起手 / 判定 / 后摇 / 硬直 / 死亡）。
下表数值**已全部落到代码里**（`world/enemies/InvaderAI.gd` 的 `@export`），
只有「血量 30」这一条还是占位待定：

| 参数 | 建议值 | 依据 |
|---|---|---|
| 血量 | **先按 30 跑通**，S0 出口再定 | 三个数打架：`Hurtbox` 默认 **30**、`06 §5` 估 **40**、基线 slime **44**。切片不改代码，先用 30；等能打死一只了，再按「打几下死」定真值 |
| 单次伤害 | **18** | `06 §5`：满血可挨 5 下（基线 slime 10 / bat 12，偏低） |
| 察觉半径 | **320px**（6.7 格） | **对齐基线实测值**，不另拍。屏宽 960 的 1/3 |
| 巡逻速度 | **55px/s** | 基线值，玩家 270 的 20%，慢到可绕 |
| 追击速度 | **60px/s** | **基线值**。玩家 44%——注意基线里这个值很低，追不上，只起"逼"的作用 |
| 攻击距离 | **60px** | 略小于玩家攻击距离，逼玩家先出手 |
| **起手（windup）** | **450ms** | 落在 `06 §5` 的 300–600ms 中间；起手必须有**可读的形变**（不能只靠颜色） |
| 后摇（recover） | **500ms** | 给玩家一个确定的还手窗口 |
| 攻击冷却 | **1200ms** | 防止贴脸连击 |
| 受击硬直 | **200ms** | 打断起手，但打断不了后摇（后摇是玩家的奖励） |

> 两个基线值要特别注明：**追击速度 60px/s 是从 web 版抄的**，它意味着敌人永远追不上玩家。
> 我们的 18 点伤害 + 起手是为了让"站着不动会挨打"，**不是为了让敌人追上你**。
> 如果实测发现玩家可以无脑跑过去，再调这个数 —— 但调它之前先问"跑过去是不是也算一种解法"。

**S0 明确不做**：多敌人协同、绕后、跳跃追击、远程弹幕。一只会走、会起手、会打的纸团就够。
**已实现范围内也没做的**：受击闪白（形变已经够读，先不加）、敌人之间互相碰撞。
