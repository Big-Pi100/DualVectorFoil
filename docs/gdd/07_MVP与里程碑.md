## 1. MVP 一句话

**一个能在手机上、用一只手、从出生点打到根系 Boss 的约 25 分钟流程；
打完能把这块地种上，退出，明天回来收一批弹药，再打一遍。**

前半句验"动作手感"，后半句验"经营纵深"。**两句都过才算 MVP 成立。**

### 1.1 时长的两个口径（别混）

| 口径 | 值 | 用途 |
|---|---|---|
| **设计目标** | **25 分钟** | 关卡按这个排：8 房、每房 40–90 秒、2 暗房、Boss |
| **验收区间** | **20–40 分钟** | 实测落在区间内即通过；低于 18 或高于 45 要查原因 |

记录方式：**首次通关**与**熟练通关**分开记，**至少 2 名非开发者**各测一次。
只测开发者自己的速度不算——开发者会背路线，时间是偏低的。

> 目标 25、区间 20–40 不矛盾：25 是"按这个排"，20–40 是"排出来多少都认"。
> 之前的写法把两个数并列，读起来像冲突。

## 2. 阶段分解

| 阶段 | 目标 | 出口标志 | 依赖 |
|---|---|---|---|
| **P0 可玩骨架** | 跑跳打、房间切换、暗房 | 见 §2.3 P0（**系统验收，不是玩家水平**） | 已有（现原型基本满足） |
| **P1 技能三件** | 投掷（消耗）+ 折叠 + 生长 | 三个技能都能用；空弹有明确反馈；折叠/生长能稳定过对应门槛 | 美术：弹药 3 + 生长 2 态 |
| **P2 经营闭环**（最小版） | 清图 → 变田 → 种 → 收 | 能种能收，退出重进进度不丢 | 美术：耕地 + 3 类作物图标 |
| **P3 防守闭环** | 袭击 + 守卫军 + 丢地 | 离线 ≥2h 后上线触发一次，守住/丢掉结果正确且**可复现**（`08 §4`） | 美术：兵种（复用敌人 + 换色） |
| **P4 Boss + 打磨** | 根系 Boss、手感调优、性能 | 25 分钟流程（区间 20–40）走通不崩 | 美术：Boss |

> **P2 是分水岭**：P2 之前这是"一个动作 demo"，P2 之后才是"这个项目"。
> 如果排期要砍，砍 P4，不砍 P2。

### 2.1 敌人数量的三个口径（之前只有一个，被误读成"同屏 30–50"）

| 口径 | 值 | 出处 |
|---|---|---|
| **单房累计** | 30–50 只 | `06 §5` |
| **同屏活跃** | **≤ 8 只**（每屏典型 3–8） | `06 §5` |
| **房间跨度** | 3–6 屏（960px 一屏，房宽 2880–5760px） | `04 §3` |

**32 只不是在 960px 里同时出现**，是沿房间长度分批生成。生成规则：

| 规则 | 值 | 备注 |
|---|---|---|
| 激活半径 | 镜头 ±1 屏 | 进入该范围才生成，避免一次性创建 32 个对象 |
| 离屏 AI 降频 | 离屏 > 2 秒 → 每 4 帧一次 | 省 CPU，玩家看不见 |
| 离屏暂停 | 离屏 > 10 秒 → 完全暂停，位置/血量保留 | 回屏恢复，**不重置起手动作** |
| 同屏硬上限 | 8 | 超出则延后生成，等前面死掉 |

> **必须在真机上测**：低端手机 8 只同屏 + 弹幕是否掉到 30fps 以下。
> PC 编辑器跑到 60fps 说明不了任何事。

### 2.2 阶段出口条件（PASS / CONDITIONAL / BLOCKED）

每个阶段收尾时填这张表，**结论不许空着，也不许"大概可以了吧"**。

| 字段 | 填什么 |
|---|---|
| 功能完成 | 该阶段的功能清单逐项打勾（不是"基本完成"） |
| 自动化测试 | `node test.js` + 相关探针全绿 |
| 人工验收 | 真机（或触屏模拟）实际操作通过 |
| 性能验收 | 目标机型达到帧率要求（当前基准：低端安卓 30fps） |
| 未解决问题 | 逐条列出，**允许带着过，但不许隐藏** |
| **阶段结论** | **PASS**（可进下一阶段）/ **CONDITIONAL**（可进，附未解决问题清单）/ **BLOCKED**（停下，先还债） |

**依赖关系**：P1 未 PASS 不得进 P2（技能三件是战斗闭环的地基）。
但**美术准备可以并行**——P2 的耕地/作物图标不依赖 P1 的代码。

### 2.3 各阶段的额外硬条件

| 阶段 | 除了通用出口表，还必须满足 |
|---|---|
| **P0** | ① **系统验收**：连续进入→退出→再进入 3 个不同房间，敌人生成、碰撞、死亡、房间状态（是否已清）全部正确；② **玩家测试**：1 名新玩家在 **≤5 次尝试**内通过前 3 房（记录实际次数，5 是参考线不是硬线）。**"连续打 3 房不死"不是程序完成标准，是玩家水平，不进 P0 出口** |
| **P1** | 空弹时必须有可见 + 可听的失败反馈；折叠 4.5–6.5 格稳定能上、7 格稳定上不去（连续 10 次） |
| **P2** | 见 §5.1 最小版本；退出重进后作物进度按真实时间推进 |
| **P3** | 同一存档连读 3 次，袭击清单完全一致（`08 §6 S2`） |
| **P4** | 30 分钟连续运行无内存增长、无输入失效（`08 §6 S6`） |

### 3.1 41 张 ≠ 41 张可用（三态）

`art/approved/` 里 41 张的实际状态：

| 类别 | 张数 | 已存在 | 可复用 | **已通过游戏内验收** |
|---|---|---|---|---|
| 角色（8 态原图 + 8 sprite） | 16 | 16 | 16 | **0** |
| 折纸鸟 `origami_bird` | 1 | 1 | 1 | **0** |
| 敌人（3 原图 + 3 sprite） | 6 | 6 | 6 | **0** |
| 道具（3 原图 + 1 sprite） | 4 | 4 | 4 | **0** |
| 特效 | 4 | 4 | 4 | **0** |
| 地形（摆件） | 7 | 7 | 7（**仅摆件**） | **0** |
| UI | 3 | 3 | 3 | **0** |
| **合计** | **41** | **41** | **41** | **0** |

定义：
- **已存在** = 文件在工程里
- **可复用** = 过了风格/尺寸/透明度检查（洋红残留 41 张全 0、尺寸已量、无空图）
- **已通过游戏内验收** = 接进真实渲染、在实际显示尺寸下确认过

**为什么"可用"是 0**：`game.js` 现在仍读旧 31 帧 `art/hero/`，敌人和道具仍是程序绘制。
**一张都没接**。所以美术缺口不是"0 张"，是**接入 41 张 + 重做若干张**两件事。

**为什么 G0–G5 全过也救不了这个 0**：那套门禁验的是"**资产本身合格**"（风格、尺寸、
抠图边缘），而且是在**来源工程**里验的。本项目 `godot/` 已于 2026-11-26 升到同一版本
（4.7.2，`§9.1`），但那套门禁**验的是图和来源工程，不是本项目**——本项目的缩放链、
节点层级、显示尺寸都还没对着真资产验过。更根本的原因是——**一张都还没接进渲染**。
门禁过关证明"图是好的"，不等于"图用上了"。

> 这张表与 `art/ART_GUIDE.md §12.3` 不重复：那边判"这张图形式上行不行"（尺寸/形态适配），
> 这边判"在 MVP 排期里算不算可用"。**一边改不需要改另一边。**

#### 3.2.1 地形瓦片的验收（5 条，缺一不算过）

| # | 判据 |
|---|---|
| 1 | 横向连续平铺 10 格以上，**接缝处无可见竖线** |

> Canvas 看一次是为了确认"基线没退化"（见 `§9 引擎口径`）。

### 3.3 纸团 / 折痕体：先当验证任务，不是"重出两张图"

复用来的 3 种敌人是 **紫色史莱姆 / 蓝色刺球 / 蝙蝠**，叙事要的是 **纸团 / 折痕体 / 纸片蝙蝠**。

| 复用资产 | 叙事原型 | 匹配度 |
|---|---|---|
| `enemy_bat` | 纸片蝙蝠 | ⚠️ 可用，但先看 `origami_bird`（更像纸） |
| `enemy_slime` | 纸团 | 🔴 像果冻，不像揉皱的纸 |
| `enemy_spike` | 折痕体 | 🔴 完全不像（是刺球，不是折叠的纸） |

**不建议"直接重出两张"**——那样只是把问题推给下一次评审。改成两个独立验证任务，
每个任务只回答一个问题：

| 任务 | 只验一件事 | 判据 |
|---|---|---|
| **T-纸团** | 能不能在 48px 主体高度下看出"揉皱" | 轮廓不规则 + 内部有皱褶线与压痕；**不能是圆形** |
| **T-折痕体** | 折线能不能表达"攻击方向 + 危险部位" | 折角朝向攻击方向；尖端=危险、钝端=安全，**不看文字也能读出来** |

两个任务都要：
1. 各出 1 张独立样本（**禁多格图**，`ART_GUIDE §10.7`）
2. 在**实际显示尺寸**（敌人 sprite 128 帧、主体 48 = 1 TILE）下与主角同框
3. 抠图后与现有 3 种敌人并排，确认**并排时不撞脸**
4. 过了才批量出；不过就换措辞重来，**一次只改一个变量**（`ART_GUIDE §5.1`）

> 占位方案（C）我仍不建议：**占位大概率变永久**。但 T-纸团/T-折痕体如果两次都不过，
> 就退回 C 并把这个决定写进 `05_叙事与主角.md`，别悬着。

### 5.1 P2 最小版本：只做"种下去、长出来、收回来"

**风险在这里**：MVP 已经含动作 + 技能 + 种植 + 交易 + 离线袭击 + 守卫军 + Boss。
东西一多，第一次实现就会写成半个模拟经营。所以 P2 第一次实现**只做三件事**：

| 做 | 不做 |
|---|---|
| 1 块地（4 格） | 多块地 / 地块升级 |
| 1 类作物（弹药） | 强化 / 成长 / 通货 / 兵营四类 |
| 种下 → 等待 → 收获 → 弹药入包 | 卖钱 / 升级树 / 仓库 |

**验收**：能种、能长、能收、退出重进不丢。就这四条。
交易、四类作物、仓库全部推到 P2.5 或 P3，**不进 P2 出口**。

## 6. 风险

| 风险 | 表现 | 对策 |
|---|---|---|
| **经营把动作挤掉** | 玩到后半段一直在点点点 | 回访 5 分钟硬指标；超了就砍功能（§5.1） |
| **范围本身过大** | 每个系统都做一半，没有一个是完整的 | P2 最小版本（§5.1）；宁可少一类作物，也要让闭环真的闭合 |
| **消耗品劝退** | 玩家不敢用弹药，退化成不打 | 弹药便宜、补给密、空弹提示明确 |
| **敌人形象与叙事错位** | "为什么史莱姆是纸做的" | §3.3 两个验证任务；两次不过则退回占位并记录 |
| **手机看不清** | 同屏 8 只时混战 | 精英标记 + 起手高亮 + 上限 8 |
| **瓦片不能铺** | 地形只能摆，房间看起来空 | P0 第一优先（§3.2） |
| **存档坏了当新游戏** | 玩家以为进度被删 | `08 §5` 铁律：绝不静默清空 |

## 9. 引擎口径：版本定版 + 哪些数字跨引擎有效

### 9.1 引擎定版（2026-11-26）

| 项 | 定值 | 怎么锁 |
|---|---|---|

| 纹理过滤 | **linear**（`1`） | 同上（蜡笔是连续色调，nearest 会出锯齿） |

**升级动作**：4.4.1 → 4.7.2（2026-11-26）。`godot/` 全量重新导入，`.import`
新增 `compress/uastc_level`、`process/channel_remap/*` 等字段——**纯新增，无行为变化**
（`compress/mode=0` 无损、`mipmaps/generate=false`、`fix_alpha_border=true` 均未变）。

#### 为什么定 4.7.2

**① 与美术规范的验证环境对齐（主要理由）。** `art/ART_GUIDE.md` 头部写明来源工程是
**4.7.2-stable**，抠图与尺寸链全部在 4.7.2 复验通过（G1–G5）。留 4.4 就是长期维护
"规范 4.7 / 工程 4.4"的双口径——每一条尺寸结论都要额外标注"在哪个版本有效"，
这个成本是持续的，收益为零。

**② 4.4 已经 EOL。** 官方支持策略只维护各分支最新 patch：**4.7.2 是当前 stable 最新版
（2026-08-18 发布，full support）**，4.4.1 停在 2025-03、已 end-of-life，4.8 还在 beta 4。
留在 4.4 意味着接下来的 bug 与平台适配修复都拿不到。

**③ 4.7 有 `VirtualJoystick`，4.4 没有——这条直接对应手机触屏优先（决定 #4）。**
本机实测（`ClassDB.class_exists`）：

| 类 | 4.4.1 | 4.7.2 |
|---|---|---|
| `VirtualJoystick` | ❌ 不存在 | ✅ 存在 |
| `TouchScreenButton` | ✅ | ✅ |
| `TileMapLayer` | ✅ | ✅ |

自己写摇杆意味着死区、多点触控、随窗口缩放、手指滑出边界这些边界条件全得手调一遍。
**第一方节点能省掉的不是代码量，是一整类"手机上才复现"的 bug。**

**④ 实测零回归**（`§9.2` 全表）。

**⑤ 导出链。** 手机是首发平台（`§10`），4.7 带稳定的 Android 导出工具链，
4.4 那套的 AGP / NDK 组合已经落后；留在 4.4 等于给打包埋一个"必须先升级"的坑。

#### 为什么不选别的

| 版本 | 不选的理由 |
|---|---|
| 4.4.1（原版本） | 已 EOL；且与美术规范的验证环境差一个 minor（见 ①②） |

| 4.7.0 / 4.7.1 | 4.7 分支只支持最新 patch，旧 patch 不修 bug；4.7.2 才是该分支的受支持版本 |
| 4.8 / dev / rc | 4.8 仍在 beta 4，**非 stable**。玩法都还没验证完，不承担引擎不稳定的风险 |

## 10. 迁移：Godot 作为唯一开发主线（2026-11-26 定）

### 10.1 决定与理由

白哥定：**后续完全在 Godot 上开发，不再用 Canvas。** 三条硬理由：

| # | 理由 | 证据 |
|---|---|---|
| 1 | **固定物理步长** | Canvas 用 `requestAnimationFrame`，物理跟帧率走：20fps 时跳高 **+8.4%**、滞空 **+11–32%**（`AUDIT_001_DVF` 发现 #1）。Godot 120Hz 物理步从根上没有这个问题 |
| 2 | **一套代码出两端** | 安卓/iOS 打包是引擎内置；Canvas 要套 WebView 或重写 |
| 3 | **写两遍比移植贵** | 从 P1 起是四技能 / 种植 / 存档——复杂度在**状态管理**，手写 Canvas 循环每加一个系统都得自己补；Godot 有节点树 + 信号 + 资源系统 |

> 当初「先验证再移植」的建议（`AUDIT_001_DVF` §0 第 3 条）前提已达成：
> 核心机制（动作手感）验完了，标定值 203.9px 在 Godot 里对得上。**该转了。**

### 10.2 代价（必须先认，不认就会中途翻车）

| 项 | 现状 | 影响 |
|---|---|---|
| **测试覆盖** | web **424 项** → godot **44 项**（env_check 8 + feel_smoke 7 + combat_smoke 23 + preset_key 6） | 迁移期"改坏了不知道"。这是最大风险 |
| **可玩性** | Godot 缺相机 / 多房间 / 攻击接线 / 敌人 | **短期内没有完整可玩的版本** |
| **截图验收** | headless 是 dummy 渲染器，**出不了图** | 视觉验收必须带窗口跑，不能全自动 |
| **美术复验** | 引擎版本已对齐（4.7.2，`§9.1`），但尺寸链**没在接真资产后复验过** | 接资产时按 `§3.2.1` 五条一起验，别跳过 |
